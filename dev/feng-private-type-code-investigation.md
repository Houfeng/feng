# 私有表示类型方案的代码调查

> 状态：调查完成，结论为 C# 方案

本文只记录当前实现、临时验证和完整交付复杂度结论。语言规则与实施 TODO 见
[公开类型的私有表示类型修复](./feng-private-representation-type-bugfix.md)。

## 1. 结论

基于完整语言行为、编译器、`.ft`、LSP 和 API 兼容性范围，C# 方案更简单。

两种方案都必须贯通私有表示依赖的声明身份、内部注册和 codegen。C# 方案在共同
底座之外增加集中的提供方可见性检查；Go 方案需要把不可命名类型的外部使用贯通
语义分析、codegen、LSP 和 API/ABI 兼容性。

当前代码存在部分按名称或声明身份推导的路径，但行为不完整，不能作为 Go 方案已经
实现的依据。

## 3. 临时验证

验证代码只创建在 `build/` 下，调查完成后已删除，未修改编译器源码。

| 场景 | 当前结果 | 说明 |
|---|---|---|
| 同次编译、跨模块执行 `let x = provider.create()`，返回类型为私有 `Hidden` | 编译并运行通过 | codegen 能访问同次编译中的完整私有声明 |
| 跨包执行相同代码 | 语义阶段通过，codegen 报 `CE0032` | `x` 只记录为 `TYPE_REF("Hidden")`，没有目标声明身份 |
| 跨包把 `x` 传给参数类型为 `Hidden` 的公开函数 | 参数匹配通过，codegen 报 `CE0032` | 名称相等可以匹配，但不能生成代码 |
| 外部显式声明 `provider.Hidden` | `AE1013` | 用户名称查询正确隐藏私有类型 |
| 外部对公开函数返回的私有类型值调用公开方法 | `AE0306` | 名称类型无法解析到私有类型成员 |
| 公开泛型类型的私有字段使用私有泛型类型 | `CE0031` | codegen 按名称和调用方可见性查找私有泛型声明 |

当前行为既不是 C#、Rust，也不是 Go，而是语义阶段按名称推导后在后续阶段不一致失败。

## 4. 两种方案的共同修复

无论选择 C# 还是 Go 方案，都需要：

1. 收集布局、泛型具化和 codegen 所需的私有表示依赖。
2. 为具名类型及其递归组成类型写入目标声明身份。
3. reader 恢复声明身份，外部模块缓存将已收录私有依赖注册到内部声明表。
4. 用户名称查询继续只返回可见声明。
5. 语义分析和 codegen 按声明身份解析内部依赖。

因此，“私有类型进入 `.ft`”包含 writer、reader、内部注册和消费链路，不能只修改
导出筛选。

## 5. 方案增量

### 5.1 C# 方案

共同修复之外，还需：

- 计算声明和组成类型的有效可见范围。
- 递归检查全部公开声明、显式类型和推导类型。
- 在提供方增加可见性不一致诊断及测试。

检查范围有限且集中在语义分析阶段。现有 ABI 签名检查可作为递归类型遍历的参考。

### 5.2 Go 方案

共同修复之外，还需：

- 将公开 API 可达的私有类型及其公开成员纳入 `.ft` 和 API/ABI 事实。
- 让不可命名类型参与推导、赋值、参数匹配、泛型推导、重载和 codegen。
- 让 LSP 对不可命名类型提供正确 hover、成员补全和诊断。
- 保持显式类型引用、导入、构造和模块补全不可见。

现有代码只覆盖部分路径；完整实现分散在语义分析、codegen、符号表和 LSP。

## 6. 复杂度判断

| 比较项 | C# 方案 | Go 方案 |
|---|---|---|
| 私有表示依赖和声明身份底座 | 必须 | 必须 |
| 新增公开签名规则 | 集中的提供方检查 | 不需要拒绝 |
| 不可命名类型外部流动 | 不需要 | 必须完整支持 |
| LSP 特殊行为 | 不需要 | 必须 |
| API/ABI 可达私有类型 | 不进入成功的公开签名 | 必须建模 |
| 完整交付复杂度 | 较低 | 较高 |

结论：若只统计当前局部代码路径，Go 方案看似可以复用部分推导逻辑；这些路径目前
产生 `AE0306`、`CE0031` 和 `CE0032`，并非可复用的完整语言能力。按完整交付范围，
C# 方案更简单，也与 Feng 现有三级可见性和公开 `.ft` 定位一致。
