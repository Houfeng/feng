# Feng ABI 互操作（待评审草案）

> 状态：讨论整理稿（供 review）
> 目标：先收敛 ABI 方向与边界，再进入实现与测试拆解。
> 说明：当前 ABI 互操作裁决以本文为准；与其他文档不一致时，后续按本文回写。

基本约定：

- `@fixed` 仅用于编译器做 ABI 兼容性检查，不引入新的运行时信息，不改变类型的运行时表示。
- 指针类型 `T*`（含函数指针 `Foo*`）在 Feng 中是不透明句柄，不能直接解引用/运算/调用。

## 1. 讨论收敛结论（当前方向）

本轮讨论的核心不在 `@fixed` 关键字本身，而在四件事：

- `string` 的 ABI 表达与 0 拷贝
- ABI 兼容数组的判定与 0 拷贝
- C API 可能逃逸指针时的生命周期责任划分
- 通过 `&` 取 `@fixed` 顶层 `fn` 获得原生函数指针用于回调

当前收敛方向：

1. `string` 与 ABI 兼容数组在 ABI 边界优先走 0 拷贝借用语义。
2. 默认只保证“调用期间有效”，不默认可逃逸。
3. 若 C API 会缓存/异步使用指针，由开发者显式保活 owner（例如放到 wrapper 成员）。
4. `&` 作为一元取地址入口，面向 C 指针传递能力，包括数据指针与函数指针。
5. `Foo*`（`@fixed spec Foo` 派生出的原生函数指针类型）作为 ABI 回调的统一载体。
6. 互操作规则不预设任何特定 C 库行为；所有生命周期、可写性、回调释放责任均由调用方显式声明与承担。

### 1.1 ABI 兼容清单（当前版）

说明：不在以下清单中的类型或函数，均视为 ABI 不兼容，编译期报错。

#### 类型清单

| 类别 | 是否 ABI 兼容 | 条件 |
| --- | --- | --- |
| 基本标量类型 | 是 | 直接按 ABI 标量规则传递 |
| 指针类型 `U*` | 是 | 仅用于 C ABI 边界传递；在 Feng 表达式中不透明、不可直接操作 |
| 函数指针类型 `Foo*`（`Foo` 为 `@fixed spec`） | 是 | 派生自标注了 `@fixed` 的 callable-form `spec`；不透明，仅在 ABI 边界传递 |
| `@fixed` 类型 | 是 | 类型本身通过 ABI 稳定校验，且直接字段类型仅允许基本标量或符合白名单的 `T*` |
| ABI 兼容数组 `T[]` | 有条件 | `T` 为基本标量 / 指针 / 已通过 ABI 校验的 `@fixed`，且元素按值连续存储 |
| `string` | 有条件 | 以字节指针和显式长度传递，默认借用语义 |

#### 函数清单

| 类别 | 是否 ABI 兼容 | 条件 |
| --- | --- | --- |
| 顶层 `fn` | 有条件 | 必须标注 `@fixed`，且全部参数与返回值 ABI 兼容 |

## 2. `@fixed` 的定位（本稿约束）

本稿用于收敛 ABI 互操作，不重开语言总模型。

`@fixed` 修饰的目标在 Feng 代码中与未标注版本没有运行时差异；`@fixed` 仅用于 ABI 兼容约束。

结合既有讨论，先采用“可实现、可诊断、可演进”的约束：

1. `@fixed` 类型必须通过编译器 ABI 稳定校验，通过后允许出现在 ABI 边界；`@fixed` 本身不改变类型的运行时表示。
2. `@fixed` 参与 ABI 边界时，传值/传指针规则由签名决定（`T` 或 `*T`）。
3. `@fixed` 相关限制继续严格执行：
    - 不允许 `@fixed` 与泛型交叉：带泛型形参的 `type` 不得标注 `@fixed`，任何泛型实例（闭合或未闭合）当前阶段均不参与 ABI 稳定校验。
    - 不允许直接依赖非 ABI 稳定类型。
    - `@fixed type` 的直接字段类型只允许以下两类：
        - 基本标量类型。
        - 指针类型 `T*`，其中 `T` 只能是 `string`、ABI 兼容数组、已通过 ABI 稳定校验的 `@fixed` 类型，或 ABI 兼容函数签名（标注 `@fixed` 的 callable-form `spec`）。
    - 因此不允许直接把 `string`、数组、`@fixed` 对象或 callable-form `spec` 本体作为 `@fixed` 成员；需要出现时必须通过对应的 `T*`。
    - 方法与成员字段是不同概念：方法定义不参与 `@fixed type` 的字段 ABI 校验，不影响字段结果。
    - 允许 `Foo*` 函数指针成员，其类型必须派生自标注 `@fixed` 的 callable-form `spec`。

示例：

```feng
@fixed
type UserType1 {
    var id: i32;
}

@fixed
type UserType2 {
    var u1: UserType1;   // 编译期报错：`@fixed type` 字段不能直接内联 `@fixed` 对象
    var u2: UserType1*;  // 合法
}
```

说明：

- ABI 语义优先放在类型与边界规则。

## 3. 一元 `&` 的拟定语义

### 3.1 允许取址的对象

仅允许对以下四类值取 C 指针：

1. `@fixed` 对象
2. `string`
3. ABI 兼容数组
4. 标注 `@fixed` 且通过 ABI 检查的顶层 `fn`（目标类型必须显式给出 `Foo*`）

其它类型一律报错，不做隐式兜底。

### 3.2 返回指针含义

1. `&fixed_value`：返回该 `@fixed` 值对应 ABI payload 的首地址指针，类型 `T*`。
2. `&str`：返回字符串 UTF-8 数据区首地址指针，类型 `byte*`。
3. `&arr`：返回 ABI 兼容数组第 0 个元素地址；空数组返回 0 指针，类型 `T*`。
4. `&fixed_fn`：在目标类型显式给出为 `Foo*` 时，返回该 `@fixed` 顶层 `fn` 的函数指针。

### 3.3 可写性

1. `&string` 结果不在语言层强制只读；是否允许写入由调用方声明的 C 契约决定。
2. `&array` 是否可写由数组可写层语义决定。
3. `&fixed_value` 是否可写由绑定可变性与成员可写规则共同决定。

### 3.4 生命周期

1. 数据指针（`T*`）默认借用，仅保证调用期间有效；C 侧若可能逃逸使用，开发者必须显式保活 owner。
2. 函数指针（`Foo*`）无生命周期问题（函数代码永不失效），但 `user_data` 等附带指针对象仍需调用方保活。
3. 对临时值取数据指针应禁止，或仅允许在直接 extern 实参位并由编译器自动延寿到调用返回。

### 3.5 与现有二元 `&`

保留二元 `&` 作为按位与；新增一元 `&` 作为取地址，按语法位置区分。

### 3.6 指针类型安全与语法示例

1. 一元 `&` 的结果类型为 `T*` 或 `Foo*`，与取址目标类型一致。
2. 指针在 Feng 中是不透明句柄：不可直接解引用、不可调用（`Foo*` 也不可直接调用）、不可指针运算、不可比较、不可进行类型转换。
3. 指针仅可用于 C ABI 互操作边界（如 `extern` 实参/返回值/`@fixed type` 成员存储），不作为通用编程能力开放。
4. 凡超出上述边界的指针操作，编译期报错。

语法示例（普通类型取址并用于 ABI 传参）：

```feng
@cdecl("c_use_i32_ptr")
extern fn c_use_i32_ptr(p: i32*): void;

let x: i32 = 42;
let p: i32* = &x;
c_use_i32_ptr(p);
```

语法示例（数组元素指针用于 ABI 传参）：

```feng
@cdecl("c_use_array_ptr")
extern fn c_use_array_ptr(p: i32*): void;

let arr: i32[] = [1, 2, 3];
let p: i32* = &arr;
c_use_array_ptr(p);
```

错误示例（禁止直接操作指针）：

```feng
let x: i32 = 42;
let p: i32* = &x;
let y: i32 = *p;      // 编译期报错：不允许解引用
let z: i32* = p + 1;  // 编译期报错：不允许指针运算
```

### 3.7 函数指针类型 `Foo*`

#### 3.7.1 定义

`@fixed spec Name(参数): 返回值;` 定义了一个 ABI 函数签名类型 `Name`；`Name*` 是对应的原生函数指针类型，兼容 C 函数指针。

规则：

1. `Name` 必须是 callable-form `spec`；标注 `@fixed` 时，编译器必须检查其全部参数与返回值均 ABI 兼容。
2. `Name` 本身仍是普通 callable-form `spec`，不引入运行时差异。
3. `Name*` 属于指针类型体系，与 `T*` 同级，遵循相同的不透明规则：不可直接调用、不可解引用、不可运算。
4. `Name*` 可来自以下位置：
    - 对满足条件的顶层 `@fixed fn` 执行 `&` 取址；
    - `extern fn` 返回值；
    - 已有 `Name*` 绑定、参数、字段或返回值的继续传递。
5. `Name*` 可直接用作 `extern fn` 参数类型、返回类型，以及 `@fixed type` 成员字段类型。
6. 除 `&fixed_fn` 场景外，编译器通常无法追溯 `Name*` 的真实来源是否匹配 `Name` 签名；这类 ABI 正确性由开发者通过 `extern fn` 声明或外部 API 契约保证。
7. 对顶层 `@fixed fn` 执行 `&` 取址时，目标类型必须显式给出 `Name*`；编译器据此检查该 `fn` 与 `Name` 的参数和返回值完全一致，缺少目标类型或签名不一致时编译期报错。

语法示例：

```feng
@fixed
spec CmpFunc(a: int, b: int): int;

@fixed
fn int_cmp(a: int, b: int): int {
    return a - b;
}

let p: CmpFunc* = &int_cmp;

@cdecl("c_get_cmp")
extern fn c_get_cmp(): CmpFunc*;

let q: CmpFunc* = c_get_cmp();
```

错误示例：

```feng
// 禁止：缺少目标 Foo* 类型，无法确定函数指针类型
let p = &int_cmp;                               // 编译期报错

// 禁止：lambda 不能取址为 Foo*
let p: CmpFunc* = &lambda(a, b) -> a - b;      // 编译期报错

// 禁止：成员方法不能取址为 Foo*
let p: CmpFunc* = &obj.method;                  // 编译期报错

// 禁止：直接调用 Foo*
let p: CmpFunc* = &int_cmp;
p(1, 2);                                        // 编译期报错
```

#### 3.7.2 在 `@fixed type` 成员中的使用

`Foo*` 可作为 `@fixed type` 的成员字段，此时其存储表示直接对应 C 函数指针，不引入额外封装。C 侧直接可见并可直接调用该字段。

```feng
@fixed
type HandlerVTable {
    let on_event: EventHandler*;
    let user_data: void*;
}
```

## 4. `string` 的 ABI 0 拷贝规则

### 4.1 基本规则

1. `string` 在 ABI 边界可按“数据指针 + 显式长度”的方式 0 拷贝传递。
2. 这是借用使用，不是所有权转移，不是普通隐式类型转换。

### 4.2 责任边界

1. 默认只保证调用期有效。
2. 若调用方声明 C 侧会在调用返回后继续使用该指针，开发者必须显式持有原始 `string` owner。

### 4.3 可写缓冲场景

如果 C API 需要可写 `char*` 缓冲，可直接使用 `string` 借用；若 C 写入破坏字符串约束（如 UTF-8/长度一致性等），行为未定义（UB，出错后不保证任何行为）。

## 5. ABI 兼容数组：判定与 0 拷贝

### 5.1 兼容判定（讨论收敛版）

数组 `T[]` 可作为 ABI 兼容数组的前提：元素类型 `T` 满足以下之一：

1. 基本标量类型
2. 指针类型 `U*`
3. 已通过 ABI 稳定校验的 `@fixed` 类型

额外硬约束：

- 元素在数组中必须按值连续存储，不能是引用槽位语义。

### 5.2 判定复杂度

使用时无需对 `T` 再做递归成员遍历，只查询 `T` 是否“已通过 ABI 稳定校验”。

说明：

1. `@fixed` 在声明时已完成完整 ABI 合法性检查。
2. 数组使用点只做 O(1) 资格查询更稳定。
3. 泛型场景在实例化闭合后再判定。

### 5.3 0 拷贝与长度

1. `&abi_array` 返回数据指针，0 拷贝。
2. 长度不跟随 `&` 一起隐式传递，长度需显式字段或参数传递。
3. 建议先只保证 rank=1 的 ABI 兼容数组；多维作为后续扩展项。

## 6. 函数指针 `Foo*` 与 C 回调

### 6.0 零假设与可判定性

1. 互操作层不得通过函数名或库习惯推断 C API 行为。
2. 回调位能力必须在 `extern fn` 签名中显式声明；参数位或返回位写成 `Foo*` 时，表示开发者声明该 ABI 位承载与 `Foo` 签名兼容的原生函数指针。
3. 编译器只检查 `Foo` 自身是否 ABI 合法、静态类型是否一致，以及 `&fixed_fn` 场景下函数签名是否与 `Foo` 完全一致；`extern fn` 实际返回或写入的函数指针是否真实匹配，由开发者负责。
4. 所有“可用/不可用”结论必须由签名规则静态判定，不能依赖运行时猜测。

示例：

```feng
@fixed
spec CmpFunc(a: int, b: int): int;

@fixed
fn int_cmp(a: int, b: int): int {
    return a - b;
}

@cdecl("c_register_cmp")
extern fn c_register_cmp(cmp: CmpFunc*): void;

let p: CmpFunc* = &int_cmp;
c_register_cmp(p);

@cdecl("c_load_cmp")
extern fn c_load_cmp(): CmpFunc*;

let q: CmpFunc* = c_load_cmp();
```

### 6.1 `@fixed spec` 与 `@fixed fn` 的检查规则

1. `@fixed spec Foo(...)` 仅允许 callable-form `spec`；编译器必须检查其全部参数与返回值 ABI 兼容。
2. `@fixed fn` 若要出现在 ABI 边界，或作为 `&` 的取址目标，必须是顶层 `fn`，且其全部参数与返回值 ABI 兼容。
3. 对顶层 `@fixed fn` 执行 `&` 时，目标类型必须显式给出为 `Foo*`；编译器据此检查该 `fn` 与 `Foo` 的参数和返回值完全一致。
4. 缺少目标类型、存在重载歧义、或 `fn` 与 `Foo` 签名不一致时，编译器必须报错。

### 6.2 `Foo*` 的来源与使用规则

1. `Foo*` 可由 `&top_level_fixed_fn` 产生。
2. `Foo*` 也可来自 `extern fn` 返回值，以及已有 `Foo*` 绑定、参数、字段或返回值的继续传递。
3. 当 `extern fn` 的参数类型或返回类型写成 `Foo*` 时，编译器只检查静态类型一致，不验证外部实现是否真的提供了与 `Foo` 签名兼容的函数指针。
4. `Foo*` 在 Feng 中始终是不透明指针，只能存储、传递和返回，不能直接调用。

### 6.3 禁止项

以下所有情况禁止作为 `Foo*` 的来源：

- 未标注 `@fixed` 的顶层函数
- 类型成员函数（成员方法）
- lambda / 闭包
- 绑定方法值
- 任何带环境捕获的 callable 值

上述禁止项仅针对 `&` 取址产生 `Foo*` 的场景；编译期报错时，诊断应明确“函数指针仅可由 `&@fixed` 顶层函数产生，或来自已声明为 `Foo*` 的 ABI 位”。

### 6.4 生命周期与释放

1. 函数指针 `Foo*` 本身无生命周期问题（函数代码永不失效）。
2. 若调用方自行通过 `user_data` 传入指针对象，其生命周期由调用方负责。
3. 若 C 侧会缓存/异步使用 `user_data` 指针，调用方必须显式保活该对象直到注销。
4. 若 `Foo*` 来自 `extern fn` 返回值或外部写入字段，是否真实满足 `Foo` 契约由开发者负责。

### 6.5 错误与约束

1. 回调跨 ABI 边界时，Feng 异常不得穿越到 C；需在边界转换为 C 可处理的错误约定。
2. 编译器必须检查被取址函数的全部参数与返回值均 ABI 兼容。
3. 凡不符合 `Foo*` 取址规则的表达式，编译器必须拒绝编译并给出固定诊断。
4. `extern fn` 返回或接收 `Foo*` 的 ABI 真实性不由编译器证明，需由开发者保证声明与外部实现一致。

## 7. 开发者责任（必须写入规范）

开发者必须根据调用方声明的 C 契约判断是否需要延长引用寿命：

1. 同步只读调用：可用默认借用（0 拷贝）。
2. 可能逃逸：必须显式保活 owner（例如 wrapper 成员持有原始 `string` / 数组 / `@fixed` 对象）。
3. 不允许把“缓存裸指针”误当作“已保活对象”。

---

## 8. 当前未决项（需要 review 后拍板）

1. 一元 `&` 对临时值的精确定义：全面禁止，还是“仅 extern 实参位可自动延寿”。
2. `string` ABI 传递是否统一要求“指针 + 长度”成对表达（建议是）。
3. ABI 兼容数组首版是否严格限制为一维。
4. `@fixed` 作为数组元素时，“按值连续存储”在实现层的落地约束点（语义层/发码层）。
5. 是否在后续版本引入成员函数回调支持（含 receiver 语义）。
6. 是否在后续版本引入闭包回调支持（trampoline + owner 句柄）。

## 9. 建议实现拆解（用于后续开发文档）

### 9.1 语义层

1. 新增一元 `&` 合法性检查与类型推导。
2. 新增 ABI 兼容数组资格谓词（基于元素类型已认证状态）。
3. 新增 ABI 边界借用生命周期诊断（至少覆盖明显逃逸误用）。
4. 新增 `@fixed spec` / `@fixed fn` 的 ABI 签名检查、`Foo*` 目标类型检查与取址合法性检查。
5. 新增 `Foo*` 来源诊断：缺少目标类型、签名不匹配、非顶层函数取址，以及 ABI 位静态类型不一致时给出固定错误码。

### 9.2 发码层

1. `&string` 生成数据指针取址路径。
2. `&abi_array` 生成元素区首地址取址路径。
3. extern 调用位自动延寿（若采用该策略）只限调用期间。
4. 首版仅生成 `&@fixed` 顶层函数对应的原生函数指针结果，并允许 `extern fn` 参数/返回位直接按 `Foo*` 传递。
5. 对成员函数、闭包、绑定方法等禁止路径不生成相关代码，编译期直接拒绝。

### 9.3 文档与测试

1. 在 ABI 规范中单列“默认借用 + 显式持有”责任模型。
2. 增加正反例：同步调用、逃逸调用、可写缓冲误用、临时值取址。
3. 增加 ABI 兼容数组资格测试：基础类型、指针类型、`@fixed` 类型、不兼容元素类型。
4. 增加函数指针测试：`&@fixed` 顶层函数通过、`extern fn` 返回 `Foo*` 通过、`Foo*` 成员字段通过、参数/返回值 ABI 检查通过。
5. 增加诊断测试：缺少目标 `Foo*` 类型报错、未标注 `@fixed` 顶层函数报错、成员函数报错、lambda 取址报错、绑定方法取址报错、ABI 检查失败报错。
