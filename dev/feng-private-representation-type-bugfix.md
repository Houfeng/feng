# 公开类型的私有表示类型修复

> 状态：待实现

## 1. 问题

公开类型可以使用私有类型作为私有成员的类型。该规则与是否泛型无关。

合法示例：

```feng
open module example;

type A<T> {
  func A() {}
}

open type B<T> {
  seal let value: A<T>;

  func B() {
    self.value = A<T>();
  }
}
```

`B<T>.value` 是私有成员，未向外暴露 `A<T>`，因此 `B<int>` 在同模块、跨模块和跨包使用时都必须正常。

当前行为：

| 场景 | 结果 |
|---|---|
| 私有非泛型类型作为公开类型的私有成员类型，同包跨模块使用 | 正常 |
| 私有非泛型类型作为公开类型的私有成员类型，跨包使用 | `CE0032` |
| 私有泛型类型作为公开泛型类型的私有成员类型，同包跨模块使用 | `CE0031` |
| 私有泛型类型作为公开泛型类型的私有成员类型，跨包使用 | `CE0031` |
| 公开成员使用私有类型 | 语义阶段通过，但跨包使用可能因私有依赖缺失而失败 |

## 2. 语言规则

- 私有成员可以使用私有类型。
- 公开成员可以使用私有类型。
- 泛型不改变该规则。
- 用户源码不能直接引用、导入或构造不可见的私有类型。
- 用户源码可以通过类型推导获得、传递该类型，并访问其公开成员。
- 类型推导、赋值、参数匹配、泛型推导、重载决议和 codegen 按声明身份使用该类型。

公开 `.ft` 中的类型声明按以下规则收录：

1. 公开顶层声明的签名及已收录类型的公开成员签名引用的所有类型均收录，不受类型可见性及是否泛型影响。
2. 已收录类型的私有成员引用的泛型类型均收录。
3. 泛型实参、泛型约束和具化依赖递归适用前两条规则。
4. 仅被私有成员引用的非泛型类型不收录。
5. 不相关的私有泛型类型不收录；私有泛型类型只有从公开声明或公开类型可达时才收录。

收录的私有类型保持私有，不进入用户名称查找、导入和补全结果。

示例：

```feng
open module example;

type A {
  seal let value: int;

  func A(value: int) {
    self.value = value;
  }

  open func getValue(): int {
    return self.value;
  }
}

open func create(): A {
  return A(42);
}

open func consume(value: A): int {
  return value.getValue();
}
```

外部代码：

```feng
let value = create();
let result = consume(value);
let current = value.getValue();
let explicit: A; // 错误：不能直接引用私有类型
```

公开 API 可达的私有类型属于公开 API/ABI 事实，不再是可任意变更的纯实现细节。

本规则统一定义在 `docs/feng-visibility.md`。其他文档只引用，不重复定义。

## 3. 根因

1. 公开 `.ft` 没有按第 2 节规则完整收录公开签名依赖和泛型具化依赖。
2. 外部模块语义视图只注册公开顶层声明，编译器内部无法解析已导入的私有依赖。
3. 具名类型和 reifiable 依赖未稳定保留目标声明身份，部分流程仍按名称和调用方源码可见性查找。

## 5. 验收矩阵

| 场景 | 预期 |
|---|---|
| 私有成员使用私有非泛型类型 | 通过 |
| 私有成员使用私有泛型类型 | 通过 |
| 仅被私有成员引用的非泛型类型声明 | 不进入公开 `.ft` |
| 公开声明或公开成员签名引用的私有类型声明 | 进入公开 `.ft`，保持私有 |
| 已收录类型的私有成员引用的泛型类型 | 进入公开 `.ft`，保持私有 |
| 不相关的私有泛型类型声明 | 不进入公开 `.ft` |
| 同包跨模块使用上述公开类型 | 通过 |
| 跨包使用上述公开类型 | 通过 |
| 公开成员直接或间接使用私有类型 | 通过 |
| 通过推导获得、传递私有类型并访问其公开成员 | 通过 |
| 外部源码直接引用私有类型 | 不可访问错误 |
| 外部源码导入或构造私有类型 | 不可访问错误 |
| 公开查询或补全查找私有类型 | 不可见 |
| 编译器内部按符号身份查找私有类型 | 可用 |
| 公开 API 可达的私有类型事实 | 纳入 API/ABI 兼容性 |

## 6. 非目标

- 不把私有表示类型改为公开类型。
- 不导出包内全部私有声明。
- 不增加公开成员与其类型的可见性一致性检查。
- 不新增 opaque type 或其他类型隐藏语法。
- 不修改 runtime ABI。
- 不修改 `Map`、迭代器或 `Option<T>`，也不针对特定类型增加特殊处理。

本修复只影响语义分析、符号元数据和编译期类型解析，不增加运行时开销。
