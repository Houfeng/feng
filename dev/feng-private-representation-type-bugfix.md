# 公开类型的私有表示类型修复

> 状态：待实现，已选择 C# 方案

## 1. 问题

公开类型的私有成员可以使用私有类型，泛型不改变该规则：

```feng
open module example;

type Entry<T> {
  func Entry() {}
}

open type Box<T> {
  seal let entry: Entry<T>;

  func Box() {
    self.entry = Entry<T>();
  }
}
```

`Box<T>.entry` 是私有成员，不向外暴露 `Entry<T>`。`Box<int>` 和
`Box<string>` 在同模块、跨模块和跨包使用时都必须正常。

公开签名使用私有类型则形成不可完整使用的 API，应在提供方报可见性不一致：

```feng
type Hidden {}

open func create() -> Hidden;          // 错误
open func consume(value: Hidden);      // 错误
open let values: List<Hidden>;         // 错误
```

当前行为：

| 场景 | 当前结果 |
|---|---|
| 私有非泛型类型作为公开类型的私有成员类型，同包跨模块使用 | 正常 |
| 私有非泛型类型作为公开类型的私有成员类型，跨包使用 | `CE0032` |
| 私有泛型类型作为公开泛型类型的私有成员类型，同包跨模块使用 | `CE0031` |
| 私有泛型类型作为公开泛型类型的私有成员类型，跨包使用 | `CE0031` |
| 公开签名使用私有类型 | 提供方语义阶段通过；消费方可能产生 `AE0306`、`CE0031` 或 `CE0032` |

## 2. 语言规则

### 2.1 可见性一致性

声明签名中每个组成类型的有效可见范围不得小于该声明的有效可见范围。
有效可见范围由 module、所属类型和成员的可见性共同决定。

规则如下：

1. 私有成员可以使用在其声明位置可访问的私有类型。
2. 公开声明不得直接或间接使用有效可见范围更小的类型。
3. 检查顶层绑定和函数，以及类型、`spec`、`fit` 的实例与静态成员。
4. 检查字段类型、参数、返回类型、构造函数参数、泛型约束、父 `spec`、
   `spec` 组成类型和 `fit` 公开签名。
5. 递归检查泛型实参、数组元素、指针目标及 callable 的参数和返回类型。
6. 泛型参数本身不参与可见性比较，其约束类型参与检查。
7. 显式类型和推导形成的公开类型都必须检查；推导类型在推导完成后检查。
8. 可见性不一致在提供方语义阶段报错，不生成公开 `.ft`。

示例：

```feng
type Hidden {}

open let value: Hidden;                 // 错误
open func create() -> Hidden;           // 错误
open func consume(value: Hidden);       // 错误
open func process<T: Hidden>(value: T); // 错误：约束类型不可见
open let values: List<Hidden>;          // 错误：递归检查泛型实参

open type Public {
  seal let hidden: Hidden;              // 合法：私有成员
  let exposed: Hidden;                  // 错误：type 成员默认公开
  static let shared: Hidden;            // 错误：静态成员默认公开
}
```

### 2.2 私有表示依赖

通过可见性检查后，公开 `.ft` 按以下规则收录声明：

1. 公开声明及其签名按现有公开导出规则收录。
2. 公开类型的字段继续携带对象布局和泛型具化所需事实，不受字段可见性影响。
3. 已收录公开类型的成员引用私有泛型类型时，收录该泛型类型的声明骨架和
   codegen 所需事实，不受成员可见性影响。
4. 私有泛型依赖递归包含其类型参数、约束、泛型实参和 reifiable 依赖。
5. 仅被私有成员引用的非泛型私有类型，不因本修复新增顶层类型声明记录。
6. 不相关的私有声明不收录。

收录的私有依赖保持私有，只进入编译器内部声明查询，不进入用户名称查找、
导入和补全。语义分析和 codegen 按声明身份使用这些依赖。

本节规则实施时统一定义在 `docs/feng-visibility.md` 和
`docs/feng-symbol-table.md`；其他正式文档只引用，不重复定义。

## 3. 根因

1. 语义分析未检查公开声明与其组成类型的有效可见范围。
2. 公开 `.ft` 未完整携带私有泛型表示类型的声明骨架和具化依赖。
3. 外部模块语义视图只注册公开顶层声明，编译器内部无法解析已收录的私有依赖。
4. 具名类型和 reifiable 依赖未稳定保留目标声明身份，部分流程仍按名称和调用方
   源码可见性查找。

## 5. 验收矩阵

| 场景 | 预期 |
|---|---|
| 私有成员使用私有非泛型类型 | 通过 |
| 私有成员使用私有泛型类型 | 通过 |
| 公开字段直接或间接使用私有类型 | 提供方可见性错误 |
| 公开函数或方法参数、返回类型使用私有类型 | 提供方可见性错误 |
| 公开静态成员或顶层绑定使用私有类型 | 提供方可见性错误 |
| 公开泛型约束使用私有类型 | 提供方可见性错误 |
| 仅被私有成员引用的非泛型私有类型声明 | 不新增到公开 `.ft` |
| 已收录公开类型的成员引用的私有泛型类型 | 进入 `.ft`，保持私有 |
| 不相关的私有声明 | 不进入公开 `.ft` |
| 同包跨模块使用合法公开类型 | 通过 |
| 跨包使用合法公开类型 | 通过 |
| 外部源码直接引用、导入或构造私有类型 | 不可访问错误 |
| 公开查询或补全查找私有类型 | 不可见 |
| 编译器内部按声明身份查找已收录私有依赖 | 可用 |

## 6. 非目标

- 不把私有表示类型改为公开类型。
- 不导出包内全部私有声明。
- 不实现 Rust 的提供方警告和消费方延迟类型隐私错误。
- 不实现 Go 的不可命名类型外部流动。
- 不新增 opaque type 或其他类型隐藏语法。
- 不修改 runtime ABI。
- 不修改 `Map`、迭代器或 `Option<T>`，也不针对特定类型增加特殊处理。

本修复只影响语义分析、符号元数据和编译期类型解析，不增加运行时开销。
