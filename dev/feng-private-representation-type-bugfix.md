# 公开类型的私有表示类型修复

> 状态：待实现

## 1. 问题

公开类型可以使用私有类型作为私有成员的类型。该规则与是否泛型无关。

合法示例：

```feng
open module example;

type A<T> {
  func A() {}
}

open type B<T> {
  seal let value: A<T>;

  func B() {
    self.value = A<T>();
  }
}
```

`B<T>.value` 是私有成员，未向外暴露 `A<T>`，因此 `B<int>` 在同模块、跨模块和跨包使用时都必须正常。

当前行为：

| 场景 | 结果 |
|---|---|
| 私有非泛型类型作为公开类型的私有成员类型，同包跨模块使用 | 正常 |
| 私有非泛型类型作为公开类型的私有成员类型，跨包使用 | `CE0032` |
| 私有泛型类型作为公开泛型类型的私有成员类型，同包跨模块使用 | `CE0031` |
| 私有泛型类型作为公开泛型类型的私有成员类型，跨包使用 | `CE0031` |
| 公开成员使用私有类型 | 语义阶段未报可见性不一致 |

## 2. 语言规则

成员签名中使用的类型，其有效可见范围必须覆盖该成员的有效可见范围。

成员的有效可见范围由 module、所属 type 和成员自身的可见性共同决定。

- 私有成员可以使用私有类型。
- 公开成员不能使用更私有的类型。
- 泛型不改变该规则。
- 泛型实参、数组元素和指针目标类型递归适用该规则。
- 字段类型、方法参数与返回类型、构造函数参数和泛型约束统一适用该规则。

非法示例：

```feng
open module example;

type A<T> {
  func A() {}
}

open type B<T> {
  open let value: A<T>;

  func B() {
    self.value = A<T>();
  }
}
```

`value` 对外可见，但 `A<T>` 不可见，必须在语义阶段报告可见性不一致。

本规则统一定义在 `docs/feng-visibility.md`。其他文档只引用，不重复定义。

## 3. 根因

1. 语义分析没有检查公开成员签名与其类型的可见性是否一致。
2. 公开包 `.ft` 包含公开类型的私有字段，但没有包含字段所依赖的私有类型声明，跨包 codegen 无法解析其布局。
3. codegen 使用调用方的源码可见性查找私有表示依赖，导致同包跨模块的私有泛型实例注册失败。

## 4. 修复方案

### 4.1 语义检查

新增统一的类型可见性检查：

1. 计算成员的有效可见范围。
2. 递归检查成员签名中的类型引用。
3. 类型的可见范围不能小于成员的有效可见范围。
4. 在声明分析阶段报告错误，不允许进入 codegen。

私有成员不对外暴露类型，不触发本项可见性错误；其类型仍须能在声明上下文正常解析。

### 4.2 符号表

为每个公开类型计算私有表示依赖闭包：

```text
公开类型
  -> 全部实例字段
  -> 字段引用的私有类型
  -> 私有类型的布局字段
  -> 递归依赖的其他私有类型
```

公开包 `.ft` 必须包含该闭包中 codegen 所需的声明级和布局信息：

- 类型种类和可见性；
- 泛型形参及约束；
- 实例字段及其类型；
- 值布局和生命周期描述所需信息；
- 泛型 reifiable 依赖。

这些类型在 `.ft` 中仍标记为私有。普通名称查询、补全和外部源码访问不得返回它们。

只导出公开类型可达的私有表示依赖，不导出无关私有声明，也不导出函数体。

### 4.3 导入

导入包符号时区分两种用途：

- 源码查询：只提供公开声明。
- 编译器内部表示查询：允许按符号身份读取私有表示依赖。

私有表示类型进入编译器内部类型注册表，但不进入用户可见符号集合。

### 4.4 Codegen

拆分两种类型查找：

- 用户源码中的类型引用按当前模块可见性查找。
- 私有表示依赖按声明身份或符号 ID 查找，不使用调用方可见性过滤。

本地语义依赖保存目标声明身份；跨包符号依赖保存目标符号 ID。泛型替换后继续保留该身份，避免重新按名称和调用方上下文查找。

## 5. 测试

### 5.1 语义测试

- 私有成员使用私有非泛型类型：通过。
- 私有成员使用私有泛型类型：通过。
- 公开成员使用私有非泛型类型：可见性错误。
- 公开成员使用私有泛型类型：可见性错误。
- 公开成员通过泛型实参、数组或指针间接暴露私有类型：可见性错误。

### 5.2 符号表测试

- `.ft` 包含公开类型可达的私有表示类型。
- 私有表示类型保留私有标记。
- 公开查询无法获取私有表示类型。
- 编译器内部查询可以按符号身份获取私有表示类型。
- 无关私有类型不进入公开包 `.ft`。

### 5.3 兼容性测试

非泛型和泛型分别覆盖：

- 同模块使用；
- 同包跨模块使用；
- 跨包使用；
- 外部直接引用私有表示类型仍报不可访问。

完成后运行全量回归测试 `make test`。

## 6. 非目标

- 不把私有表示类型改为公开类型。
- 不导出包内全部私有声明。
- 不修改 runtime ABI。
- 不在本修复中修改 `Map`、迭代器或 `Option<T>`。

本修复只影响语义检查、符号元数据和编译期类型解析，不增加运行时开销。
