# Feng 官方网站规范

> 本文档定义 Feng 官方网站在仓库内的目标、信息架构与内容来源约束。语言规则、CLI 规则与包格式规则仍分别以对应规范文档为准；官网只做面向访客的介绍性表达，不承载仓库导览职责。

## 1 目标与边界

- 官网实现位置固定为 `website/` 目录。
- 官网面向首次了解 Feng 的开发者，核心任务是介绍语言定位、语言特性与典型工作流。
- 官网默认采用静态站点实现，要求无需额外构建步骤即可直接本地预览。
- 官网首页不得承担仓库结构说明、目录导览、编辑器实现说明等仓库级内容。
- `website/` 作为网站根目录，页面内不得直接链接到 `website/` 之外的父级或同级其他目录；若后续需要扩展内容，应将页面或资源落到 `website/` 内部。

## 2 内容权威来源

- 语言定位、特性总览、关键词与文件扩展名说明以 `docs/feng-language.md` 为准。
- CLI 命令与项目工作流以 `docs/feng-cli.md` 为准。
- 编译器与构建工具职责分离以 `docs/feng-build.md` 为准。
- 包格式、`feng.fm` 与 `.fb` 分发语义以 `docs/feng-package.md` 为准。
- 官网中使用的示例代码、命令与清单片段必须能在现有规范或示例文件中找到依据。

官网可以对上述内容做压缩表达，但不得重新定义规则，也不得把“去仓库哪里看”作为首页主叙事。

## 3 首页信息架构

首页至少包含以下区块：

1. Hero：一句话介绍 Feng 的设计定位，并将访客导向“特性”和“工作流”。
2. Language Features：突出强类型、`spec` / `fit`、函数与闭包、异常、C 互操作、包分发等语言能力。
3. Code Sample：展示一段 Feng 语法片段与一段最小项目清单，帮助理解表层语法与项目形态。
4. Workflow：说明从 `feng init`、`feng check`、`feng build` 到 `feng run` / `feng pack` 的典型路径。
5. Language Surface：概括模块、类型系统、流程控制、异常、内存管理与互操作等主题分布。

## 4 实现约束

- 页面需兼顾桌面与移动端阅读。
- 页面视觉上应形成明确品牌感，不使用默认浏览器风格。
- 页面文案必须以“语言介绍”为中心，不出现仓库目录导览、仓库模块清单或实现组件罗列。
- 页面文案必须面向最终用户，优先回答“用 Feng 能做什么、为什么值得用、如何开始”，避免“网站该回答什么”“先看实现再看语言面”这类自指或面向实现者的表达。
- 网站内导航与资源引用必须留在 `website/` 根目录范围内。
- 官网静态资源命名应清晰稳定，便于后续继续扩展多页结构。

## 5 验证要求

- 至少验证首页 HTML 能正确引用自身 CSS / JS / 资源文件。
- 至少验证首页关键区块存在：Hero、Language Features、Code Sample、Workflow、Language Surface。
- 至少验证首页不存在跳出 `website/` 根目录的本地链接。
