# Feng 官方网站规范

> 本文档定义 Feng 官方网站在仓库内的目标、信息架构、视觉方向与内容来源约束。语言规则、CLI 规则与包格式规则仍分别以对应规范文档为准；官网只做面向访客的介绍性表达，不承载仓库导览职责。

## 1 目标与边界

- 官网实现位置固定为 `website/` 目录。
- 官网面向首次了解 Feng 的开发者，核心任务是让访客认识 Feng、看到语言形态、完成安装，并进入文档或 GitHub。
- 官网默认采用静态站点实现，要求无需额外构建步骤即可直接本地预览。
- 官网首版使用简体中文；其他语言版本在中文内容与视觉定稿后基于同一信息架构制作，首版不设置语言切换入口。
- 官网首页不得承担仓库结构说明、目录导览、编辑器实现说明等仓库级内容。
- 官网首页保持极简，只呈现完成上述核心任务所必需的内容；非必要的功能清单、数据指标、工作流展开与装饰性区块不得进入首版。
- `website/` 作为网站根目录，页面内不得直接链接到 `website/` 之外的父级或同级其他目录；若后续需要扩展内容，应将页面或资源落到 `website/` 内部。

## 2 内容权威来源

- 语言定位、特性总览、关键词与文件扩展名说明以 `docs/feng-language.md` 为准。
- CLI 命令与项目工作流以 `docs/feng-cli.md` 为准。
- 编译器与构建工具职责分离以 `docs/feng-build.md` 为准。
- 包格式、`feng.fm` 与 `.fb` 分发语义以 `docs/feng-package.md` 为准。
- 在线安装脚本的入口、唯一源文件与发布规则以
  `dev/feng-release-and-install.md` §7.2 为准。
- 官网中使用的示例代码、命令与清单片段必须能在现有规范或示例文件中找到依据。

官网可以对上述内容做压缩表达，但不得重新定义规则，也不得把“去仓库哪里看”作为首页主叙事。

## 3 首页信息架构

首页采用单页结构，按以下顺序组织：

1. 顶部导航：包含 Feng 品牌入口、`安装`、`文档` 与 `GitHub`。`安装` 指向首屏安装入口；文档正式上线前，`文档` 明确标记为尚未开放，不得链接到空页面；`GitHub` 指向 Feng 官方仓库。
2. Hero：展示 Feng 品牌名、一句简洁的语言定位、唯一一处在线安装命令、手动下载入口与 GitHub 入口。安装命令必须在首屏内完整可见，并提供复制操作；当前支持的 host 平台及 macOS Command Line Tools 前置要求以简短辅助文字呈现。首页不得在后续区块重复安装命令或另设安装区。
3. 代码示例：展示一段简短、可读且具有 Feng 语法辨识度的代码，使访客无需阅读文档即可了解语言表层形态。首页只保留一个示例，不增加标签切换、项目清单或多示例浏览。
4. 文档与 GitHub：文档上线前只显示简洁的准备中说明；GitHub 提供官方仓库入口，并可直接提供 Releases 与 Issues 入口。
5. 页脚：仅保留项目名称、必要的版权信息及 GitHub 入口，不扩展仓库导览或重复页面主体内容。

首页不得设置关键词数量、保留字数量、注解数量等数据指标，不使用多卡片特性宫格、完整 CLI 工作流、语言主题目录或 Manifest 示例填充页面。语言能力如需在首页辅助表达，只允许使用少量短语，不展开为完整功能说明；详细内容由后续文档承载。

## 4 视觉规范

官网采用克制、现代的宋式美学。宋式特征通过留白、比例、排版与材质感表达，不通过堆叠传统装饰符号表达。

- 页面以暖白纸色为背景、墨色为主要文字颜色，以少量朱砂红作为唯一强调色；辅助色不得形成多彩产品卡片效果。
- 中文标题与正文以清晰、克制的宋体为主，操作文字可使用现代无衬线字体，代码使用等宽字体。字体必须具备稳定的系统回退方案；中文排版不得直接沿用英文斜体与负字距规则。
- 页面以单栏纸本排版为主，版心保持适度收窄；段落行长、字号、行距与区块间距优先保证阅读节奏，并通过大面积留白形成层次。
- 分隔优先使用细线、字重与间距，不依赖大面积阴影、渐变、毛玻璃、胶囊形容器或密集圆角卡片。
- 相邻区块共享边界时只保留一条分隔线；分隔线应紧邻其归属内容，避免被区块级留白推离内容。
- 安装命令与代码示例沿用纸色背景和细线分隔，不使用大面积深色容器、区块编号或装饰性面板制造层级。
- 不使用竹、祥云、山水、印章等装饰元素直接模拟传统风格；品牌确需使用印记式元素时，必须保持抽象、少量且不影响阅读。
- 动效不是必要内容。若保留动效，只允许用于操作反馈或轻微状态过渡，并遵守用户的减少动态效果偏好；不得以滚动动画作为内容可见的前提。
- 桌面与移动端保持相同的信息顺序和视觉气质，不通过移动端隐藏核心安装、文档或 GitHub 入口。

## 5 实现约束

- 页面需兼顾桌面与移动端阅读。
- 页面视觉上应形成明确品牌感，不使用默认浏览器风格，也不得以增加模块数量代替视觉完成度。
- 页面文案必须以“语言介绍”为中心，不出现仓库目录导览、仓库模块清单或实现组件罗列。
- 页面文案必须面向最终用户，优先回答“用 Feng 能做什么、为什么值得用、如何开始”，避免“网站该回答什么”“先看实现再看语言面”这类自指或面向实现者的表达。
- 对外网站首版文案使用简体中文，包括导航、标题、按钮、说明文本与交互反馈；Feng、GitHub、macOS、Linux、Xcode、Command Line Tools 与代码等品牌名或技术名词保留原文。
- 网站内导航与资源引用必须留在 `website/` 根目录范围内。
- 在线安装命令必须使用 `https://feng-lang.com/install.sh`；页面不得维护安装脚本副本，也不得重新定义脚本行为。
- GitHub、GitHub Releases 与 GitHub Issues 使用官方仓库的外部链接；除这些明确的外部入口外，首页不增加社交媒体、社区或第三方平台链接。
- 复制安装命令是首版唯一必需的脚本交互。导航、代码示例与安装说明在 JavaScript 不可用时仍须完整可读、可访问。
- 页面必须使用语义化 HTML，具备清晰的标题层级、键盘可操作的交互、可见焦点状态和满足可读性的颜色对比度。
- `website/` 不维护专用自动校验脚本，页面内容、视觉效果、响应式布局与交互质量由人工 Review 验收。
- 官网静态资源命名应清晰稳定，便于后续继续扩展多页结构。
- GitHub Pages 部署物必须通过临时 staging 生成，不得把部署生成文件写回
  `website/`。除 `website/` 静态内容外，staging 仅按
  `dev/feng-release-and-install.md` §7.2 注入在线安装脚本。
- 自定义域名由仓库 GitHub Pages 设置管理，Actions 部署物不维护 `CNAME` 文件。

## 6 人工 Review 要求

官网变更由人工 Review 验收，不要求通过 `website/` 专用脚本执行自动验证。Review 至少覆盖以下内容：

- 首页 HTML 正确引用自身 CSS、JavaScript 与资源文件，页面内不存在失效引用。
- 首页包含 Hero、单一代码示例、文档状态、GitHub 入口和页脚。
- 在线安装命令只出现一次，使用 `https://feng-lang.com/install.sh`，在首屏内完整可见且不产生横向滚动；手动安装入口指向官方 GitHub Releases。
- 首页不包含关键词、保留字、注解等数据指标，不包含多示例切换或完整 CLI 工作流区块。
- 首页与前端交互脚本的对外文案使用简体中文；除品牌名、技术名词与代码外，不残留英文版界面文案。
- 首页不存在跳出 `website/` 根目录的本地链接。
- 关闭 JavaScript 后，导航、代码示例、安装说明、文档状态与 GitHub 入口仍然可读。
- 键盘操作、可见焦点、移动端布局与减少动态效果偏好符合本规范。
