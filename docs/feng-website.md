# Feng 官方网站规范

> 本文档定义 Feng 官方网站在仓库内的目标、信息架构与内容来源约束。语言规则、CLI 规则与包格式规则仍分别以对应规范文档为准；官网只做摘要、导览与示例展示，不重复定义语言标准。

## 1 目标与边界

- 官网实现位置固定为 `website/` 目录。
- 官网面向首次了解 Feng 的开发者，提供一句话定位、核心能力概览、快速上手、文档导览与示例代码入口。
- 官网默认采用静态站点实现，要求无需额外构建步骤即可直接本地预览。
- 官网不承载语言规范全文，不新增独立语义承诺，不替代 `docs/` 下的正式规范文档。

## 2 内容权威来源

- 语言定位、特性总览、关键词与文件扩展名说明以 `docs/feng-language.md` 为准。
- CLI 命令与项目工作流以 `docs/feng-cli.md` 为准。
- 编译器与构建工具职责分离以 `docs/feng-build.md` 为准。
- 包格式、`feng.fm` 与 `.fb` 分发语义以 `docs/feng-package.md` 为准。
- 首页示例代码优先复用 `examples/` 下的真实示例文件。

官网引用上述内容时应使用“摘要 + 链接继续阅读”的方式，不得在官网中重新定义细节规则。

## 3 首页信息架构

首页至少包含以下区块：

1. Hero：一句话介绍 Feng 的设计定位，并给出快速阅读入口。
2. Core Pillars：用简短卡片概括强类型、`spec` / `fit`、C 互操作、包分发等能力。
3. Code Sample：展示一段来自仓库真实示例的 Feng 代码，帮助用户快速理解语法风格。
4. Workflow：说明从项目初始化、检查、构建到运行的基本路径。
5. Docs Map：按主题列出规范入口，帮助用户继续深入阅读。
6. Status / Roadmap：说明项目当前仍处于演进中，但目标是生产级语言实现。

## 4 实现约束

- 页面需兼顾桌面与移动端阅读。
- 页面视觉上应形成明确品牌感，不使用默认浏览器风格。
- 若官网展示命令、示例代码或规则摘要，内容必须能在仓库现有文件中找到依据。
- 官网静态资源命名应清晰稳定，便于后续继续扩展多页结构。

## 5 验证要求

- 至少验证首页 HTML 能正确引用自身 CSS / JS / 资源文件。
- 至少验证首页关键区块存在：Hero、Core Pillars、Code Sample、Workflow、Docs Map。
- 至少验证首页指向的仓库文档链接目标在仓库内存在。
