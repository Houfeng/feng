# Feng 官方网站规范

> **禁止在此文档中描述站点外观，这个文档是用来说明官网包含的内容和逻辑的。**

> 本文档定义 Feng 官方网站的目标、内容范围、信息架构、用户路径与交互逻辑。语言规则、CLI 规则与包格式规则仍分别以对应规范文档为准；官网只做面向访客的介绍性表达，不承载仓库导览职责。

## 1 目标与边界

- 官网实现位置固定为 `website/` 目录。
- 官网面向首次了解 Feng 的开发者，核心任务是让访客认识 Feng、看到语言形态、完成安装，并进入文档或 GitHub。
- 官网默认采用静态站点实现，要求无需额外构建步骤即可直接本地预览。
- 官网首版使用简体中文；其他语言版本在中文内容与信息架构定稿后制作，首版不设置语言切换入口。
- 官网首页不得承担仓库结构说明、目录导览、编辑器实现说明等仓库级内容。
- 官网首页只包含完成上述核心任务所必需的内容；非必要的功能清单、数据指标与工作流展开不得进入首版。
- `website/` 作为网站根目录，页面内不得直接链接到 `website/` 之外的父级或同级其他目录；若后续需要扩展内容，应将页面或资源落到 `website/` 内部。

## 2 内容权威来源

- 语言定位、特性总览、关键词与文件扩展名说明以 `docs/feng-language.md` 为准。
- CLI 命令与项目工作流以 `docs/feng-cli.md` 为准。
- 编译器与构建工具职责分离以 `docs/feng-build.md` 为准。
- 包格式、`feng.fm` 与 `.fb` 分发语义以 `docs/feng-package.md` 为准。
- 在线安装脚本的入口、唯一源文件与发布规则以
  `dev/feng-release-and-install.md` §7.2 为准。
- 官网中使用的示例代码、命令与清单片段必须能在现有规范或示例文件中找到依据。

官网可以对上述内容做压缩表达，但不得重新定义规则，也不得把“去仓库哪里看”作为首页主叙事。

## 3 首页信息架构

首页采用单页结构，按以下顺序组织：

1. 顶部导航：包含 Feng 品牌入口、`安装`、`文档` 与 `GitHub`。`安装` 指向首页唯一的安装内容；文档正式上线前，`文档` 明确标记为尚未开放，不得链接到空页面；`GitHub` 指向 Feng 官方仓库。小窗环境允许收起导航入口，展开后必须提供同一组菜单项。
2. Hero：传达 Feng 的核心定位，包含主标题以及 `AI 友好`、`显式契约`、`静态类型`、`自动内存管理`、`C 亲和`、`容易上手`这一组定位关键词。Hero 同时承担开始使用 Feng 的入口，只出现一处在线安装命令，并提供复制命令、支持平台说明与手动下载入口。GitHub 入口由顶部导航提供，不在安装内容中重复；首页不得在后续区块重复安装命令或另设安装区。
3. 代码示例：展示一段简短、可读且具有 Feng 语法辨识度的代码，使访客无需阅读文档即可了解语言表层形态。首页只保留一个示例，不增加标签切换、项目清单或多示例浏览。
4. 页脚：仅保留项目名称、必要的版权信息及 GitHub 入口，不扩展仓库导览或重复页面主体内容。首页不另设文档与 GitHub 介绍区块，避免与顶部导航、Hero 和页脚重复。

首页不得包含关键词数量、保留字数量、注解数量等数据指标，不得包含扩展特性清单、完整 CLI 工作流、语言主题目录或 Manifest 示例。语言能力如需在首页辅助表达，只允许使用少量短语，不展开为完整功能说明；详细内容由后续文档承载。

## 4 用户路径与交互逻辑

- 首次访问者应能依次完成三个认知步骤：理解 Feng 的定位、看到语言代码形态、选择安装或继续进入文档与 GitHub。
- 顶部“安装”入口定位到首页唯一的安装内容；GitHub 进入官方仓库；文档未上线时只说明状态，不链接到不存在的页面。
- 小窗导航默认收起，用户可以通过“菜单”操作展开或再次收起；选择菜单项后允许自动收起。导航展开能力不得依赖 JavaScript。
- 复制安装命令是首页唯一必需的脚本交互。成功或失败都应给出简体中文反馈，反馈结束后恢复原操作文本。
- 复制操作优先使用浏览器 Clipboard API，在不可用或被拒绝时使用兼容性回退；回退失败时不得伪造成功状态。
- 手动下载入口始终指向官方 GitHub Releases，不在官网复制或维护发布文件。
- JavaScript 不可用时，语言定位、安装命令、支持平台、代码示例、文档状态和所有链接仍应完整可读。
- 桌面端与移动端提供相同的内容、操作和访问顺序，不因设备类型隐藏核心信息。

## 5 实现约束

- 页面需兼顾桌面与移动端访问，所有核心内容和操作在两类设备上保持一致。
- 页面文案必须以“语言介绍”为中心，不出现仓库目录导览、仓库模块清单或实现组件罗列。
- 页面文案必须面向最终用户，优先回答“用 Feng 能做什么、为什么值得用、如何开始”，避免“网站该回答什么”“先看实现再看语言面”这类自指或面向实现者的表达。
- 对外网站首版文案使用简体中文，包括导航、标题、按钮、说明文本与交互反馈；Feng、GitHub、macOS、Linux、Xcode、Command Line Tools 与代码等品牌名或技术名词保留原文。
- 网站内导航与资源引用必须留在 `website/` 根目录范围内。
- 在线安装命令必须使用 `https://feng-lang.com/install.sh`；页面不得维护安装脚本副本，也不得重新定义脚本行为。
- GitHub、GitHub Releases 与 GitHub Issues 使用官方仓库的外部链接；除这些明确的外部入口外，首页不增加社交媒体、社区或第三方平台链接。
- 复制安装命令是首版唯一必需的脚本交互。导航、代码示例与安装说明在 JavaScript 不可用时仍须完整可读、可访问。
- 页面必须使用语义化 HTML，具备清晰的标题层级，支持键盘操作并满足无障碍要求。
- `website/` 不维护专用自动校验脚本，页面内容、链接、跨设备可用性与交互质量由人工 Review 验收。
- 官网静态资源命名应清晰稳定，便于后续继续扩展多页结构。
- GitHub Pages 部署物必须通过临时 staging 生成，不得把部署生成文件写回
  `website/`。除 `website/` 静态内容外，staging 仅按
  `dev/feng-release-and-install.md` §7.2 注入在线安装脚本。
- 自定义域名由仓库 GitHub Pages 设置管理，Actions 部署物不维护 `CNAME` 文件。

## 6 人工 Review 要求

官网变更由人工 Review 验收，不要求通过 `website/` 专用脚本执行自动验证。Review 至少覆盖以下内容：

- 首页 HTML 正确引用自身 CSS、JavaScript 与资源文件，页面内不存在失效引用。
- 首页包含顶部导航、Hero、单一代码示例和页脚；文档状态与 GitHub 入口由顶部导航提供，不另设重复介绍区块。
- 在线安装命令只出现一次并使用 `https://feng-lang.com/install.sh`；手动安装入口指向官方 GitHub Releases。
- 首页不包含关键词、保留字、注解等数据指标，不包含多示例切换或完整 CLI 工作流区块。
- 首页与前端交互脚本的对外文案使用简体中文；除品牌名、技术名词与代码外，不残留英文版界面文案。
- 首页不存在跳出 `website/` 根目录的本地链接。
- 关闭 JavaScript 后，导航、代码示例、安装说明、文档状态与 GitHub 入口仍然可读。
- 键盘操作、交互反馈与跨设备内容一致性符合本规范。
