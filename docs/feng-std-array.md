# Feng 数组与标准库数组规范

本文档统一定义 Feng 内建数组 `T[]` / `T[!]` 的语言语义，以及标准库 `std` / `std.collections` 提供的数组与切片 API。数组虽然是语言直接提供的内建托管引用类型，但其 `length()`、`clone()`、`slice()`、`Span<T>` 与 `toArray()` 等能力都与数组本体语义紧密耦合，因此统一在本文档收敛。

## 1 职责

- 定义数组类型语法、默认零值、逐层可写性、类型兼容、显式转换与 ABI 边界约束。
- 定义标准库 `std` 提供的数组实体复制能力，以及 `std.collections` 提供的只读视图与视图实体化能力。
- 定义数组相关的编译期与运行时约束，作为其他文档引用数组语义时的唯一权威入口。

## 2 语义

`T[]` 与 `T[!]` 是 Feng 的内建数组类型。Feng 不额外提供独立的“动态数组”类型；数组实例在初始化完成后长度固定不变。二者都采用引用语义：赋值、传参与返回复制的是数组引用，而不是数组元素本体。

补充定义:

- 数组使用 `T[]` 语法；其默认零值是 `[]`（长度为 `0` 的有效数组引用，不是 `null`）。`T[!]` 的默认零值是“长度为 `0` 的可写数组实例”（字面量写作仍为 `[]`，由目标类型决定可写层）。数组由自动内存管理机制托管。
- `T[]` 表示元素类型为 `T` 的只读数组类型；`T[!]` 表示该数组层的元素可写。多维数组沿 `[]` 递进书写，`!` 只约束其紧邻的 `[]` 这一层，因此可逐层组合写成 `T[][]`、`T[][!]`、`T[!][]`、`T[!][!]` 等形式。
- 对多维数组而言，每一层 `[]` 的可写性独立判断。`T[][!]` 表示最外层数组元素可写、其元素类型仍是只读 `T[]`；`T[!][]` 表示最外层数组元素不可写，但其元素类型是可写数组 `T[!]`；`T[!][!]` 表示两层都可写。
- 数组类型表达式中不包含长度；数组长度是运行时属性，而不是静态类型的一部分。元素类型、数组层数以及每一层 `[]` 对应的可写标记一致的数组才视为同一数组类型，不因实例长度不同而区分为不同类型。
- 数组实例在创建完成后长度固定；当前版本不提供修改数组长度的语言机制。`[]` 表示长度为 `0` 的空数组字面量；其具体可写层由目标类型决定（可贴合 `T[]` 或 `T[!]`）。
- `T[]` 的当前层元素默认不可变；当前版本不提供通过该层下标位置原地改写其元素的语言机制。对多维数组同理，是否可在某一层通过下标写入，取决于该层 `[]` 是否标记 `!`。
- `T[!]` 的当前层元素可通过该层下标位置原地改写。对多维数组同理，`!` 只赋予其紧邻 `[]` 这一层的写入能力，不会自动传播到其他层级。数组的可写性只影响对应层的元素写入能力，不改变数组长度固定与引用语义。
- 数组长度访问通过标准库模块 `std` 在数组目标上的 `fit` 方法 `length()` 提供，返回类型为 `long`（`i64`），表示当前数组层元素个数。
- 标准库数组 `length()` 的实现必须直接读取运行时数组长度元数据，时间复杂度为 `O(1)`；不得通过遍历数组计数获得长度。
- 标准库模块 `std` 在数组目标上提供 `clone()` 与 `clone(start, length)`。`clone()` 返回复制当前数组全部元素得到的新数组；`clone(start, length)` 返回复制区间 `[start, start + length)` 得到的新数组，不与源数组共享底层元素存储。
- 标准库模块 `std.collections` 在数组目标上提供 `slice(start, length)`，返回只读切片视图 `Span<T>`。`Span<T>` 是 `std.collections` 中定义的共享底层数组的普通对象，不是新的内建数组类型，也不改变数组实例长度固定的语义；当前阶段应通过数组 `slice` 获得该视图。
- `Span<T>` 采用右开区间 `[start, end)` 表示视图范围；`length()` 返回 `end - start`，`get(index)` 以视图左端为基准访问元素。
- `Span<T>` 在自身上继续提供 `slice(start, length)`，表示以当前视图左端为基准再取得一个只读子视图；该操作继续共享同一底层数组，不隐式复制元素。
- `Span<T>` 提供 `toArray()`，返回复制当前视图全部元素得到的新数组；该数组不与源数组或源视图共享底层元素存储。
- 当前版本不支持 `.length` / `.len` 属性语法；必须使用方法调用形式 `value.length()`。
- 数组类型之间默认不隐式兼容。显式转换只允许在保持元素类型与数组层数不变的前提下移除某一层或多层已有的 `!` 标记，不允许增加 `!` 标记。例如允许从 `T[!]` 显式转换到 `T[]`、从 `T[][!]` 显式转换到 `T[][]`、从 `T[!][]` 显式转换到 `T[][]`，不允许反向转换。
- 指定长度数组创建表达式统一使用 [Feng 语言表达式与运算规范](./feng-expression.md) 中的 `Type[:n]` / `Type<Args>[:n]`；`value[n]` 始终是索引访问，不参与数组创建解析。
- 即使数组元素类型之间存在 `type` / `spec` 满足关系、父子 `spec` 关系或其他可见契约关系，也不因此支持数组层面的 variance 或隐式/显式自动转换。例如 `T2` 可按 `T1` 视角使用，不代表 `T2[]` 可自动转换为 `T1[]`；需要时开发者必须手动编程完成遍历并重建目标数组。
- 数组在语言实现层是受托管的引用类型；多个变量可引用同一数组实例。
- 数组变量绑定的可变性（`let` / `var`）控制的是绑定能否重新指向另一个数组，而不是数组长度或元素可写性。
- 数组在 C ABI 边界上的兼容资格、桥接与限制统一见 [Feng 语言 C 互操作规范](./feng-interop.md)。

```feng
let empty: int[] = [];
let nums = [1, 2, 3];
let writable_empty: int[!] = [];
let writable_nums = [1, 2, 3];
let outer_writable_matrix: int[][!] = [[1, 2], [3, 4]];
let inner_writable_matrix: int[!][] = [[1, 2], [3, 4]];
let fully_writable_matrix: int[!][!] = [[1, 2], [3, 4]];
let alias = nums;
var current = nums;
current = [4, 5, 6];
writable_nums[0] = 10;
outer_writable_matrix[0] = [9, 10];
inner_writable_matrix[0][0] = 9;
fully_writable_matrix[0] = [5, 6];
fully_writable_matrix[0][0] = 7;

let readonly_nums = (int[])writable_nums;
let readonly_outer_matrix = (int[][])outer_writable_matrix;
let readonly_inner_matrix = (int[][])inner_writable_matrix;

let cloned = nums.clone();
let cloned_range = nums.clone(1, 2);
let middle = nums.slice(1, 2);
let dense = middle.toArray();

spec Animal {}
spec Dog: Animal {}

let dogs: Dog[] = [];
// let animals: Animal[] = dogs; // 非法: Feng 不支持数组 variance，需手动编程转换

// nums[0] = 10; // 非法: 基础数组元素默认不可变
// outer_writable_matrix[0][0] = 9; // 非法: 内层 `T[]` 未标记 `!`
// inner_writable_matrix[0] = [9, 10]; // 非法: 最外层 `[]` 未标记 `!`
// let writable_again = (int[!])nums; // 非法: 不允许从只读数组显式转换到可写数组
```

## 3 规则

分为「必须」。

- [必须] 数组类型表达式中不包含长度；判断数组类型兼容性时，长度不是静态类型的一部分。
- [必须] 可写数组层通过在对应的 `[]` 后追加 `!` 表示，例如 `T[][!]`、`T[!][]`、`T[!][!]`。
- [必须] `!` 只约束其紧邻的 `[]` 这一层；未标记 `!` 的数组层，其元素不可通过该层下标位置直接赋值修改。
- [必须] 元素类型、数组层数和各对应数组层的可写标记一致的数组才视为同一数组类型，不因实例长度不同而区分为不同类型。
- [必须] 基础数组实例一旦创建完成，其长度保持不变。
- [必须] 数组长度访问仅通过 `std` 提供的 `length()` 方法提供，返回类型为 `long`（`i64`）；当前版本不得提供 `.length` / `.len` 属性语法。
- [必须] 标准库数组 `length()` 的实现必须直接读取运行时数组长度元数据，时间复杂度必须为 `O(1)`；不得通过遍历数组计数获得长度。
- [必须] `std` 提供的数组 `clone()` 必须返回复制当前数组全部元素得到的新数组，不得返回共享底层存储的别名视图。
- [必须] `std` 提供的数组 `clone(start, length)` 必须校验 `start >= 0`、`length >= 0` 且 `start + length <= array.length()`；不满足时必须以 Feng 异常失败，而不是静默截断。
- [必须] `std` 提供的数组 `clone(start, length)` 返回的新数组必须与源数组解耦；后续对源数组元素的写入不得改变已返回的新数组内容。
- [必须] `std.collections` 提供的数组 `slice(start, length)` 返回共享底层数组的只读视图 `Span<T>`；该操作不得隐式复制底层数组元素。
- [必须] `slice(start, length)` 必须校验 `start >= 0`、`length >= 0` 且 `start + length <= array.length()`；不满足时必须以 Feng 异常失败，而不是静默截断。
- [必须] `std.collections.Span<T>.slice(start, length)` 必须以当前视图左端为基准校验 `start >= 0`、`length >= 0` 且 `start + length <= span.length()`；不满足时必须以 Feng 异常失败。
- [必须] `std.collections.Span<T>.get(index)` 必须按视图边界校验 `index`，不得把越界访问透传为对底层数组其他区间的合法访问。
- [必须] `std.collections.Span<T>.toArray()` 必须返回复制当前视图元素得到的新数组，不得返回共享底层存储的别名视图。
- [必须] `T[]` 的当前层元素默认不可变；当前版本不得通过该层下标位置直接赋值修改元素。
- [必须] `T[!]` 的当前层元素可通过该层下标位置直接赋值修改。
- [必须] 数组类型之间默认不隐式兼容；显式转换只允许移除某一层或多层已有的 `!` 标记，不允许增加 `!` 标记。
- [必须] 数组兼容性比较时，元素类型必须保持完全一致；若元素类型不同，则不支持数组层面的 variance 或隐式/显式自动转换；需要时只能由开发者手动编程完成转换。
- [必须] 数组绑定的 `let` / `var` 仅控制绑定能否重新指向另一数组，不改变数组长度固定以及由类型决定的元素可写性语义。
- [必须] 数组在 C ABI 边界上的兼容资格、桥接与限制统一遵循 [Feng 语言 C 互操作规范](./feng-interop.md)。

## 4 编译期

- 编译器必须将数组视为内建托管引用类型；语言层数组值的实现表示是对运行时数组对象的引用，而不是内联元素序列。
- 编译器必须将数组长度视为运行时属性而非静态类型的一部分；判断数组类型兼容性时，必须比较元素类型、数组层数以及各对应数组层的可写标记。
- 编译器必须把每个 `[!]` 解释为其紧邻数组层的可写标记；未标记 `!` 的数组层默认不可写。
- 编译器必须允许在多维数组类型的任意数组层使用 `[!]` 标记，并拒绝任何未紧跟在 `[]` 之后的孤立 `!` 用法。
- 编译器必须拒绝任何对 `T[]` 下标位置的直接赋值。
- 编译器必须允许对 `T[!]` 下标位置的直接赋值，并检查被写入值的元素类型兼容性。
- 编译器必须拒绝任何会增加数组层 `!` 标记的显式转换；必须允许在保持元素类型与数组层数不变的前提下移除一个或多个已有 `!` 标记的显式转换。
- 编译器必须在数组类型兼容性检查中要求元素类型完全一致；若仅元素类型之间存在 `type` / `spec` 满足关系、父子 `spec` 关系或其他可见契约关系，而数组层数与 `!` 标记相同，也必须拒绝任何数组层面的 variance 或隐式/显式自动转换；需要时只能由开发者手动编程完成转换。
- 编译器必须按 [Feng 语言 C 互操作规范](./feng-interop.md) 校验数组在 C ABI 边界上的兼容资格与桥接限制。

## 5 运行时

- 数组在运行时以受托管堆对象表示；赋值、传参与返回默认复制数组引用而非元素内容。数组对象一旦创建完成，其长度保持不变；各数组层的元素是否可原地改写，按该层 `[]` 是否标记 `!` 独立判断。当前对象布局与释放规则见 [Feng 语言对象生命周期规范](./feng-lifetime.md)。
- `std.clone()` 与 `Span.toArray()` 必须产生新的数组对象；`std.collections.slice()` 与 `Span.slice()` 只返回共享底层数组的只读视图。
- 数组传递到 C ABI 边界时，其桥接与必要的生命周期协调统一遵循 [Feng 语言 C 互操作规范](./feng-interop.md)。
