# Feng 语言泛型规范

> **状态**: 草案。
> 本文档当前只收敛已经确认的泛型语法与编译期约束：泛型声明入口、显式泛型调用的 `:<...>` 语法，以及“泛型 `type` 内的方法泛型参数不得与外层类型泛型参数重名”的规则。
> 类型参数约束、类型推导细则、实例化策略与代码生成策略暂不在本文定义。

## 1 职责

- 为 Feng 增加类型参数机制，允许在 `type`、`fn`、`spec` 和成员方法上声明泛型参数。
- 在不让 Parser 反向依赖 Semantic 的前提下，为显式泛型调用提供无歧义语法。
- 收敛已经确认的命名约束：泛型 `type` 内的方法泛型参数不得与所在类型的泛型参数重名。

## 2 术语

- 类型泛型参数：声明在 `type Name<T>` 或 `spec Name<T>` 上的类型参数。
- 函数泛型参数：声明在顶层 `fn Name<T>` 上的类型参数。
- 方法泛型参数：声明在 `type` 成员方法 `fn Name<T>` 上的类型参数。
- 显式泛型调用：在调用点显式写出类型实参的函数或方法调用，统一使用 `callee:<...>(...)` 语法。
- 类型位置：变量类型标注、字段类型、参数类型、返回类型以及类型构造等只允许出现类型的语法位置。

## 3 语法

正确语法一，泛型声明：

```feng
type List<T> { ... }

fn map<T, U>(left: T, right: U): T { ... }

spec Comparable<T> {
  fn compare(other: T): int;
}

spec Mapper<T, U>(value: T): U;
```

正确语法二，泛型类型中的泛型方法：

```feng
type Box<T> {
  fn get(): T { ... }

  fn map<U>(value: U): T { ... }
}
```

正确语法三，类型位置中的泛型实例化：

```feng
type Holder<T> {
  let value: T;
}

let a: List<int> = ...;

fn wrap(value: Holder<string>): List<string> { ... }

let b = List<int>();
```

正确语法四，显式泛型调用：

```feng
let a = map(data, option);
let b = map:<int, string>(data, option);
let c = pkg.map:<int>(data);
let d = obj.map:<int>(data);
```

错语法一，把 `<...>` 直接写在调用目标后面：

```feng
let a = map<int, string>(data, option);
let b = pkg.map<int>(data);
let c = obj.map<int>(data);
```

错语法二，方法泛型参数与所在类型泛型参数重名：

```feng
type Box<T> {
  fn bad<T>(value: T): T { ... }
}
```

## 4 语义

- Feng 允许在 `type`、顶层 `fn`、object-form `spec`、callable-form `spec` 和成员方法上声明泛型参数。
- 泛型声明头继续使用普通角括号语法，即 `Name<T>`、`Name<T, U>`。
- 类型位置中的泛型实例化继续直接使用 `<...>` 语法；`List<int>`、`Map<string, int>` 这类写法不引入歧义，因此不使用 `:<...>`。
- 显式泛型调用只在函数或方法调用处引入歧义消解语法。凡是在调用点显式写出类型实参，无论目标是顶层函数、模块函数还是成员方法，都统一使用 `:<...>`。
- 因此，`foo<T>(...)`、`pkg.foo<T>(...)`、`obj.foo<T>(...)` 都不作为显式泛型调用语法。
- 当调用点不显式写出类型实参时，调用表面语法仍与普通调用完全一致，例如 `map(data, option)`；是否允许省略、以及省略时如何推导，由后续泛型推导规则定义。
- 泛型 `type` 内的方法可以同时使用所在类型的泛型参数与方法自己的泛型参数；为避免重名遮蔽，方法泛型参数名不得与外层类型泛型参数名重名。
- `:<...>` 的引入仅用于语法消歧，使 Parser 仅根据词法序列就能识别“这里是显式泛型调用”，而不需要反向依赖 Semantic。

## 5 规则

分为「必须、禁止、建议」。

- [必须] 泛型声明在声明名后使用 `<...>` 书写类型参数列表。
- [必须] 类型位置中的泛型实例化继续直接使用 `<...>` 语法，不得改写为 `:<...>`。
- [必须] 显式泛型调用统一使用 `callee:<...>(...)` 语法；该规则同时适用于顶层函数、模块函数和成员方法调用。
- [必须] 在泛型 `type` 内声明泛型方法时，方法泛型参数名不得与所在类型的泛型参数名重名。
- [禁止] 把 `foo<T>(...)`、`pkg.foo<T>(...)` 或 `obj.foo<T>(...)` 当作显式泛型调用语法。
- [禁止] 在泛型 `type` 内声明与外层类型泛型参数同名的方法泛型参数。
- [建议] 当调用点不需要显式指定类型实参时，优先使用普通调用语法，避免无必要的 `:<...>`。

## 6 编译期

- 编译器必须识别 `type`、顶层 `fn`、`spec` 和成员方法上的泛型声明头。
- 编译器必须把 `:<...>` 识别为显式泛型调用语法的一部分，并据此解析后续的实参调用。
- 编译器不得把 `foo<T>(...)`、`pkg.foo<T>(...)` 或 `obj.foo<T>(...)` 解释为显式泛型调用；这些写法若不能按普通表达式语法成立，则必须报错。
- 编译器必须检查泛型 `type` 内的方法泛型参数名是否与外层类型泛型参数名重名；若重名，必须在编译期报错并阻止通过。

## 7 运行时

- 本文档当前不引入新的运行时可见语义承诺。
- `:<...>` 仅用于语法消歧，本身不规定泛型实例化、代码生成或运行时表示方式。
- 泛型的实例化策略、运行时布局与代码生成规则待后续规范补充。
