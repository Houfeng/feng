# Feng 语言设计原则

本文档用于沉淀 Feng 语言层面的设计原则,说明为什么语言规则被设计成当前形式,并为具体规范文档提供统一的判断依据。若具体规则文档与本文档表达的原则出现冲突,应优先修正规则文档,而不是在规则层继续堆积例外。

## 1 分层原则

- 关键字决定语法类别。凡属于语法结构的问题,都应能在 parse 阶段被检查并报错。
- 注解只影响语义分析与代码生成,不改变语法产生式,也不决定某条语句在 parse 阶段是否合法。
- `extern func` 保留为关键字语法,因为它表达的是“外部函数声明、没有 Feng 实现、不能有函数体”这一语法类别; `extern` 不形成独立可复用修饰符,只能与顶层 `func` 组合使用。
- `@abi` 保留为内建注解,因为它表达的是“声明希望接受 ABI 兼容性检查”这一语义资格,而不是新的语法类别。
- 未来若引入自定义注解,也应遵循同一分层原则: 自定义注解可以增加语义和代码生成约束,但不应改写核心语法。

## 2 C互操作原则

- `extern func` 用于声明无函数体的外部函数; `extern` 只能用于顶层 `func`,不得用于 `type`、`enum`、`spec`、`fit`、模块级 `let` / `var` 或其他声明。当前公共规范明确定义的目标路径是 C ABI 导入。
- `@abi` 仅用于标记对象形式的 `type`、callable-form 的 `spec` 与顶层 `func` 需要接受 ABI 兼容性检查; `@abi` 不改变运行时表示。
- 对象形式的 `@abi type` 用于声明可导出 ABI payload 的对象类型。
- callable-form 的 `@abi spec` 用于声明 ABI 函数签名; 对应的原生函数指针类型写作 `Foo*`。
- 带参数的 `@cdecl`、`@stdcall` 和 `@fastcall` 定义 `extern func` 的 C ABI 导入路径; 无参数形式只用于描述顶层 `@abi func` 进入 ABI 边界时的调用方式,不改变其“由 Feng 提供实现”的语义身份。
- 哪些声明与类型能够进入 C ABI 边界,以及对应的兼容资格、借用规则与函数指针规则,统一见 [Feng 语言 ABI 互操作规范](./feng-interop.md)。

## 3 ABI资格原则

- `@abi` 的合法性属于语义资格检查。某个声明是否能标记为 `@abi`,由其直接依赖的类型语义决定,而不是由 `@abi` 改写后的特殊语法决定。
- `@abi` 声明的直接字段类型与可调用 ABI 边界上的参数/返回值兼容资格,统一见 [Feng 语言 ABI 互操作规范](./feng-interop.md)。
- `@abi` 不改变对象类型、函数值或 callable-form `spec` 在 Feng 中的运行时形态; 它只约束 ABI 边界上的可用资格与发码方式。
- `@abi type` 的直接字段不能直接内联 `string`、数组、`@abi` 对象值或 callable-form `spec` 值; 需要表达这些能力时必须改用 `T*` 或 `Foo*`。
- `Foo*` 的类型资格由 callable-form 的 `@abi spec` 定义; `Foo*` 在 Feng 中始终是不透明原生函数指针。

## 4 布局与代码生成原则

- `@abi type` 描述的是对象的 ABI payload 视图,不是另一类 Feng 对象模型。
- `@abi type` 的 payload 仅由字段声明决定; 方法、构造函数、访问控制和注解本身都不参与 payload 计算。
- callable-form 的 `@abi spec` 只定义 ABI 函数签名; `Foo*` 直接对应原生函数指针,不再额外引入可调用对象包装层语义。
- `@abi` 相关代码生成必须优先采用可预测、可直接由静态签名判定的策略,不得依赖具体库名、函数名或运行时猜测来补足 ABI 规则。
- 公开 `@abi` 接口是头文件、导出清单与 ABI 元信息生成的依据。

## 5 生命周期原则

- 普通 `type` 是托管对象,标注 `@abi` 不改变其对象生命周期、构造流程或比较语义; `@abi` 与终结器互斥,标注 `@abi` 的类型不得声明终结器。
- `@abi` 只额外约束进入 ABI 边界时的资格、借用与 payload 传递方式,不单独引入另一套 Feng 侧生命周期模型。
- 原始指针 `T*`、函数指针 `Foo*` 与 C 侧资源本体不受自动内存管理机制接管。
- 若通过 `&` 把对象 payload、字符串数据或数组元素区借给 C 侧,默认只保证调用期间有效; 一旦可能逃逸,由开发者显式保活 owner。

## 6 诊断原则

- `extern func` 的错误属于语法错误,应描述为“`extern func` 不能有函数体”之类的结构性问题。
- `@abi` 的错误属于语义资格错误,应描述为“该声明不能标记为 `@abi`”,而不是“`@abi` 改变了这种语法可写的成员种类”。
- 诊断信息应尽量指出不满足资格的具体原因,例如字段、参数或返回类型中存在非 ABI 兼容类型,或函数指针缺少显式 `Foo*` 目标类型。

推荐诊断风格示例:

- `type PointList` 含有不能直接内联到 `@abi type` 的成员 `items`,因此不能标记为 `@abi`。
- `func point_sum` 的参数 `user` 类型不是 ABI 兼容类型,因此该函数不能标记为 `@abi`。
- `let cb = &int_cmp` 缺少显式目标 `Foo*` 类型,因此不能确定函数指针类型。
