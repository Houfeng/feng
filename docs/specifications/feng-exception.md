# Feng 语言异常模型规范

本文档用于补充 [feng-language.md](./feng-language.md) 中的异常处理概要说明,聚焦 Feng 语言中的 `throw`、异常传播、`try/catch` 表达式与 C ABI 边界规则。

> **设计原则基础**: `extern func` 自身的无函数体约束属于语法层; `@abi` 边界上的异常限制属于语义与代码生成层。详见 [Feng 语言设计原则](./feng-principles.md)。

## 1 异常模型概览

- Feng 支持结构化异常处理,使用 `throw` 触发异常,使用 `try/catch` 处理异常。
- `try` 后只能是表达式,不能是语句块。
- 异常沿调用栈向外传播,直到被最近的 `catch` 捕获。
- 每个 `try` 至少包含一个 `catch` 子句；普通调用产生但未被当前函数捕获的异常自动继续向上传播。
- 异常不能跨越 C ABI 边界传播。

## 2 `throw` 语句

`throw 表达式;` 用于显式抛出新的异常值。

规则说明:

- `throw` 后必须跟一个非 `void` 表达式。
- `throw` 语句通常以分号结束；当它是 `if`、`match` 或 `try` 表达式的分支块中最后一条语句时，末尾分号可加可不加。
- `throw` 与带具体类型的 `catch ex: Type` 共用 §3.3 定义的有限异常载荷类型集合；同一静态类型不得在
  两处得到不同的许可结果。
- `throw ex` 中的 `ex` 若是当前 `catch ex: unknown` 的绑定，表示原样重抛当前异常，不创建
  `unknown` 类型的新异常载荷。
- `throw` 会终止当前执行路径,其后的同级语句不可达。

```feng
func ensure_positive(x: int) {
    if x < 0 {
        throw "x must be positive";
    }
}
```

## 3 `try/catch`

### 3.1 `try/catch` 用法

作为普通语句使用

```feng

// 常规语句
try foo() catch ex: string {
  puts(ex);
} catch ex: unknown { // 兜底 catch 子句
  puts("unknown error");
  return; // 作为语句时，使用 return 结束函数
}

// 匿名 catch，不建立异常值绑定
try foo() catch {
  // 这里不能访问 ex，因为 ex 没有绑定，也就不存在 ex
  puts("unknown error");
}

```

作为表达式使用

```feng

// 常规表达式
let x = try foo() catch ex: string {
  puts(ex);
  // 作为表达式时，最后一个表达式作为 catch 块的求值结果（可带可不带分号，与 if 表达式一致）
  // 不可使用 return 语句（与 if 表达式一致）
  // 必须有返回值，结果类型按流程控制规范的统一分支规则确定
  123; 
};

// 匿名 catch，不建立异常值绑定
let x = try foo() catch {
  // 这里不能访问 ex，因为 ex 没有绑定，也就不存在 ex
  puts("unknown error");
  // 作为表达式时，最后一个表达式作为 catch 块的求值结果（可带可不带分号，与 if 表达式一致）
  // 不可使用 return 语句（与 if 表达式一致）
  // 必须有返回值，结果类型按流程控制规范的统一分支规则确定
  123;  
};

```

### 3.2 `try`

- `try` 用于求值一个可能抛出异常的表达式。
- 语法形态: `try <expr> (catch [ex: Type] { ... })+`，后必须附加至少一个 `catch` 子句；各子句可为绑定形式 `catch ex: Type { ... }` 或匿名形式 `catch { ... }`。
- `try` 后只能是单个表达式,不允许 `try { ... }` 语句块形态。

### 3.3 `catch`

- `catch` 捕获从对应 `try` 表达式或其内部调用链抛出的异常。
- `catch` 有两种形式：
  - **绑定形式** `catch ex: Type { ... }`：将捕获的异常值以不可变绑定方式绑定到 `ex`，类型注解必须显式给出，不可省略。
  - **匿名形式** `catch { ... }`：不绑定异常值，无需类型注解；body 内不可访问被捕获的异常值，但可 `throw` 任意合法值作为新异常。
- 支持多个 `catch` 子句，按书写顺序逐一尝试匹配，第一个匹配成功的子句生效，后续子句不再执行。
- 带具体类型注解的 `catch ex: Type` 仅在抛出值的精确具体类型身份与 `Type` 一致时匹配；不按字段布局、
  底层标量、父类型或其他结构兼容关系匹配。
- 兜底子句写作 `catch ex: unknown`，匹配任意类型的抛出值，应置于所有具体类型子句之后；`unknown` 类型的 `ex` 不可调用任何方法或访问字段，仅允许 `throw ex`（重新上抛）。
- 匿名 `catch { ... }` 同样匹配任意类型的抛出值，应置于所有具体类型子句之后。
- 每个 `catch` 子句独立匹配一个类型，不支持在单个子句内列举多个类型。
- 每个绑定形式 `catch` 都有独立的子句头部作用域,异常名称声明在该作用域中; 紧随的花括号 body
  是其子级块,可以按变量绑定规范合法屏蔽异常名称。不同 `catch` 子句的头部作用域彼此独立,
  可以复用同一异常名称。
- `catch` 块中可执行常规语句；若需继续上抛，应使用 `throw <expr>;` 显式抛出。
- `throw` 与具体类型 `catch` 允许以下静态类型：
  - `bool`；
  - 数值标量 `i8`、`i16`、`i32`、`i64`、`u8`、`u16`、`u32`、`u64`、`f32`、`f64`；
  - `string`；
  - 具名 `enum`；
  - 普通实体 `type` 与具名 tuple；
  - `@value type`；
  - 上述用户类型的闭合泛型实例，即完成类型实参替换后不再包含开放类型参数的具体类型；
  - 普通 `@abi type` 与 `@value @abi type`。`@abi` 只增加 C ABI 投影，不抹除 Feng 类型身份，且不
    改变 §5 的异常边界规则。
- `throw` 与具体类型 `catch` 一律拒绝以下静态类型：
  - array；当前数组实例共享对象类型身份，不能仅按精确具体数组类型进行无额外运行时工作的匹配；
  - object-form、intersection-form、union-form 与 callable-form 在内的所有 `spec`；
  - 直接泛型类型参数，以及完成当前可用替换后仍包含开放类型参数的类型；
  - pointer 与 `void`；
  - 函数值、函数类型、lambda 与成员方法等 callable 值。
- array 或 `spec` 即使在运行时携带元素信息、subject 或 witness，也不得在异常匹配阶段读取这些实例数据
  以推断类型。若需抛出实现某个 `spec` 的对象或联合成员，应在具体静态类型可见时抛出该具体值。
- 具名类型采用名义精确匹配：不同具名 enum 即使底层值相同也不匹配，enum 与其底层整数不匹配；不同
  具名 tuple 或 `@value type` 即使布局相同也不匹配；闭合泛型实例按完整类型实参区分。
- **`unknown` 仅限 `catch` 子句**：`unknown` 出现在 `let`、函数参数、返回类型、字段类型等位置时，语法合法但语义非法，语义分析阶段报错拒绝。

### 3.4 语句用法与表达式用法

`try/catch` 可作为独立**语句**或赋值右侧**表达式**使用，两种用法下 `catch` 块的求值与控制流规则不同，参照 `if` 语句与 `if` 表达式的区别。

**作为语句使用时：**

- `try/catch` 语句以最后一个 `catch` 块的 `}` 结束，末尾不得添加分号，与 `if`、`match`、`while` 和 `for` 等花括号控制流语句保持一致。
- `catch` 块可执行任意语句，无需以结果表达式结束。
- 可使用 `return <value>;` 提前退出当前函数。
- 可使用 `throw <expr>;` 终止当前路径并继续上抛。

**作为表达式使用时（出现在赋值右值或需要求值的位置）：**

- 每个可正常完成的 `catch` 块必须以结果表达式结束（块中最后一个表达式作为求值结果，可带可不带分号，与 `if` 表达式一致）。
- 结果分支中的 `return` 控制转移边界统一遵循
  [Feng 语言流程控制规范 §4.1](./feng-flow.md#41-if--match--try-%E8%A1%A8%E8%BE%BE%E5%BC%8F%E7%BB%93%E6%9E%9C%E7%B1%BB%E5%9E%8B)，
  不在异常规范中另行定义一套规则。
- `try` 主表达式与各 `catch` 块的结果类型按 [Feng 语言流程控制规范 §4.1](./feng-flow.md#41-if--match--try-%E8%A1%A8%E8%BE%BE%E5%BC%8F%E7%BB%93%E6%9E%9C%E7%B1%BB%E5%9E%8B)统一选择目标类型并贴合。
- 若路径以 `throw <expr>;` 终止，则该路径无需提供结果表达式。
- 当 `try` 主表达式结果类型为 `void` 时，`catch` 块可以只执行语句并正常结束，不需要结果表达式。
- 若表达式上下文提供目标类型，则 `try` 主表达式结果与各 `catch` 块结果都必须分别符合该目标类型。

### 3.5 `if`/`match` 表达式分支中的 `throw`

`if` 表达式和 `match` 表达式的各分支块允许以 `throw` 结尾，与 `try/catch` 表达式的 `catch` 子句规则一致。

- 以 `throw` 结尾的分支不产生结果值，不参与结果类型推导和一致性比较。
- 如果一个分支 `throw`、另一个分支有 yield 表达式，则结果类型取有 yield 的分支类型。
- 如果所有分支都以 `throw` 结尾，则表达式结果类型为 unknown，不可用于需要明确类型的上下文。

```feng
let x = if cond {
  throw "error";
} else {
  42;
};

let label = if value {
  0 { "zero"; }
  1 { throw "unexpected one"; }
  else { "other"; }
};
```

## 4 异常传播规则

- 未被当前函数处理的异常会继续向调用方传播。
- 若异常传播到程序入口 `main` 仍未被捕获,程序立即以异常失败状态结束。
- 对于 `try/catch` 表达式,`catch` 完成结果返回后,控制流从该表达式之后继续执行。
- 当前 `try/catch` 没有匹配当前异常的子句时，异常继续向外传播。

### 4.1 异常路径上的资源清理

- 异常沿调用栈传播时,栈上所有已经初始化、当前作用域可见的托管局部(由编译器与运行时共同管理引用计数的对象,例如字符串、数组、对象实例)必须被释放,等价于这些局部正常走完作用域。
- 释放顺序与正常退出相同:按声明的逆序逐个释放,且每个槽位释放后被置空,任何后续路径都不会重复释放。
- 抛出表达式自身的值在传递到 `catch` 之前持有 +1 引用;`catch` 块结束后由运行时释放该引用。`catch` 中再次执行 `throw <expr>;` 时,按新抛出值独立适用相同生命周期规则。
- 任何被 `@abi` ABI 边界拦截或在程序入口外仍未被捕获的异常,在终止进程前同样要释放沿途所有可见的托管局部,以保证调试信息一致、不掩盖真实泄漏。

## 5 与 C ABI 的边界约束

- 异常不得穿过 `@abi` ABI 边界传播到 C 调用方。
- 用于 ABI 边界的顶层 `@abi func`（含回调函数来源,以及未来的公开导出 surface）均须确保内部异常在函数体内被捕获处理，不得向 C 调用方传播。
- 编译器在语义阶段对 `@abi` ABI 边界做静态异常传播分析：若用于 ABI 边界的顶层 `@abi func` 内存在可能未被捕获而到达函数出口的异常路径，编译期报错，而非依赖运行时检测。
- 若未捕获异常到达 `@abi` 的 ABI 边界,运行时直接终止当前进程,不得向 C 侧继续返回未定义状态。
- C ABI 路径下的 `extern func` 导入声明本身不向 Feng 异常系统抛出可捕获异常; 来自 C 的错误应通过返回值、错误码或显式回调约定传递。
