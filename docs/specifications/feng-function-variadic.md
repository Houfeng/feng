# Feng 语言变长参数规范

本文档说明 Feng 中变长参数（variadic parameter）的职责、语法、语义与编译期约束。变长参数是函数系统的组成部分；函数系统概要见 [feng-function.md](./feng-function.md)，可调用形状（`spec`）的变参声明规则见本文 § 4.4。

## 1 职责

- 变长参数允许函数或可调用形状在最后一个参数位置接受任意数量的同类型实参。
- 变长参数在函数体内以只读数组形式呈现，调用侧传入的多个实参由编译器自动打包；函数内部对 `args` 的使用与普通只读数组完全一致。
- 变长参数不引入新的运行时机制，完全复用现有数组类型与托管对象基础设施。

## 2 术语

- 变长参数（variadic parameter）：使用 `T...` 标记的最后一个参数；在函数体内类型为 `T[]`。
- 变参元素类型：`T...` 中的 `T`，即每个实参的期望类型。
- 变参打包（variadic packing）：调用侧编译器将变参位的零个或多个实参自动构造为 `T[]` 并传递的行为。
- 预打包变参数组转发（prepacked variadic forwarding）：调用侧使用 `...expr`，将一个已经构造完成的只读数组直接作为目标函数的整个变参数组数组传递，不再执行变参打包。
- 固定参数：变参参数之前的所有普通参数，遵循既有参数规则。

## 3 语法

正确语法一，仅含变长参数的函数：

```feng
func print_all(args: string...): void {
    // args 的类型为 string[]，可使用全部数组操作
}
```

正确语法二，固定参数 + 变长参数：

```feng
func log(level: int, args: string...): void {
    // level 是普通 int 参数，args 类型为 string[]
}
```

正确语法三，变长参数的调用（含零实参）：

```feng
print_all("foo", "bar", "baz")   // 三个实参打包为 string[]
print_all("only")                 // 一个实参打包为含单个元素的 string[]
print_all()                       // 零实参打包为 string[]（空数组）

log(1, "a", "b")                 // level=1，args=["a","b"]
log(0)                            // level=0，args=[]（空数组）
```

正确语法四，`spec` 可调用形状中的变长参数：

```feng
spec Printer(args: string...): void;

func make_printer(): Printer {
    return (args: string...) {
        // args 类型为 string[]
    };
}
```

正确语法五，直接转发已经打包的变参数组：

```feng
func forward(level: int, args: string...): void {
    log(level, ...args);
}

let values: string[] = ["a", "b"];
log(1, ...values);
```

错误语法一，变长参数不在最后一个位置：

```feng
// 错误：args 不是最后一个参数
func bad(args: string..., level: int): void { }
```

错误语法二，参数列表中出现多个变长参数：

```feng
// 错误：一个函数只能有一个变长参数
func bad(names: string..., counts: int...): void { }
```

错误语法三，将已有数组直接传入变参位：

```feng
let arr: string[] = ["a", "b"];
print_all(arr)   // 错误：普通变参位不接受已有数组；直接转发整个数组应写为 print_all(...arr)
```

错误语法四，`extern func` 声明变长参数：

```feng
// 错误：extern func 不支持变长参数
extern func printf(fmt: string...): int;
```

错误语法五，`...expr` 后仍有其他实参：

```feng
// 错误：预打包变参数组必须是最后一个实参
log(1, ...values, "tail")
```

## 4 语义

### 4.1 参数类型规范化

- `T...` 仅作为参数声明位的语法形式，不引入新的类型；在编译器内部，该参数的类型被规范化为 `T[]`（只读数组）并附带变参标记。
- 变长参数在函数体内的类型为 `T[]`，与显式声明 `T[]` 参数的使用方式完全相同，包括 `args.length`、下标访问等所有数组操作。
- 变长参数始终为只读数组（`T[]`，非 `T[!]`）；调用侧打包生成的临时数组不向函数内部暴露写权限。

### 4.2 调用侧打包规则

- 调用变长函数时，编译器将变参位的所有实参（零个或多个）自动打包为 `T[]` 并传入函数；调用侧代码不需要手动构造数组。
- 零实参合法：`f(fixed...)` 对变参位不提供实参时，编译器传入空数组 `[]`。
- 每个变参实参的类型必须匹配变参元素类型 `T`；类型不匹配时编译期报错，报告具体的位置与期望类型。
- 不允许将已有 `T[]` 作为一个普通变参实参直接传入变参位：`f(existingArr)` 中若 `existingArr` 的类型是 `T[]`，编译器报错并给出提示；如需把该数组作为完整变参数组传递，应显式写为 `f(...existingArr)`。
- 打包生成的临时数组由运行时托管，ARC 负责其生命周期；函数返回后该临时数组自动释放，不需要调用侧手动管理。

### 4.3 预打包变参数组转发

- `...expr` 只允许出现在调用实参列表中，表示将 `expr` 的结果直接作为目标函数的整个变参数组数组传递；它不是通用的数组元素展开运算。
- `...expr` 必须是调用实参列表中的最后一项，并且必须恰好位于目标函数的第一个变参实参位置；它之前只能出现目标函数声明的固定参数，不能先传入普通变参元素再转发预打包数组。
- 被调用目标必须声明变长参数。若目标声明为 `func f(fixed..., values: T...)`，则 `...expr` 的静态类型必须匹配归一化后的只读数组类型 `T[]`；非数组、可写数组 `T[!]` 或元素类型不匹配均不合法。
- `expr` 按普通表达式规则求值且只求值一次。调用仍先求值被调用目标，再从左到右求值固定实参，最后求值 `expr`。
- `...expr` 不执行变参打包：编译器必须把 `expr` 求值得到的同一个数组直接传入目标函数归一化后的数组参数，不得创建新数组、复制或遍历数组元素，也不得重新打包。
- `...` 只消除调用机制原本产生的变参打包；`expr` 自身固有的构造、分配和副作用不受影响。
- 数组引用的传递和生命周期完全沿用普通函数调用与现有 ARC 规则；`...` 不改变所有权、可变性或数组对象身份。
- 重载解析以预打包转发形状参与候选匹配：仅变参候选可匹配，固定参数数量必须等于 `...expr` 之前的实参数量，数组类型必须匹配该候选归一化后的变参数组类型。

### 4.4 `spec` 中的变长参数

- callable-form `spec` 可以在最后一个参数位声明变长参数，语法与 `func` 声明相同：`spec Name(args: T...): R;`。
- 未绑定的函数或 lambda 进入变参 callable-form `spec` 位置时，结构匹配要求：参数个数、参数类型、变参标志与返回类型完全一致；具体实参为 `T...` 的参数必须对应 `spec` 的 `T...` 参数，不允许以 `T[]` 参数匹配变参位。
- 通过变参 callable-form `spec` 值发起调用时，编译器按 spec 的变参声明执行相同的调用侧打包，不需要调用者感知底层实现是否使用 `...`。
- 通过变参 callable-form `spec` 值发起调用时，也可以使用 § 4.3 的 `...expr` 直接转发预打包变参数组。

### 4.5 重载冲突检测与消歧

**冲突判定算法**

对同名的两个重载 F 和 G（至少一个含变参），令 `nf`、`ng` 分别为各自的固定参数数量：

1. **若含变参的一方固定参数较少**（`nf < ng`，且 F 为变参）：将 F 的固定参数列表用其变参元素类型 `T` 向后填充至与 G 等长，再逐位比较；若完全一致则冲突。
2. **若含变参的一方固定参数较多**（`nf > ng`，且 F 为变参）：丢弃 F 的变参标记，仅保留固定参数列表；两者长度不同，必然不冲突。
3. **固定参数数量相等**（`nf == ng`）：直接逐位比较固定参数列表；若完全一致则冲突（两个非变参相同、或两个变参固定前缀相同均适用此情形）。

示例（冲突）：`func f(x: int, y: string)` 与 `func f(x: int, args: string...)` — 后者固定数 1 < 前者 2，填充后得 `(int, string)`，与 `(int, string)` 一致 → 冲突。

示例（不冲突）：`func f(x: int, y: float)` 与 `func f(x: int, args: string...)` — 填充后得 `(int, string)`，与 `(int, float)` 不一致 → 不冲突。

示例（冲突）：`func f()` 与 `func f(args: string...)` — 固定数均为 0，直接比较 `()` 与 `()` 一致 → 冲突（`f()` 两者均匹配）。

示例（冲突）：`func f(x: int, args: string...)` 与 `func f(x: int, args: float...)` — 固定数均为 1，`(int)` 与 `(int)` 一致 → 冲突（`f(0)` 两者均匹配，变参均为空）。

示例（不冲突）：`func f(x: int)` 与 `func f(x: int, y: string, args: float...)` — 后者固定数 2 > 前者 1，丢弃变参后长度 2 ≠ 1 → 不冲突。

**调用侧消歧**

经过声明侧严格冲突检测后，存活的重载候选在同一调用位置上不存在类型重叠，调用侧仅按类型精确匹配唯一确定候选。若经以上步骤仍存在多个候选，编译期报歧义调用错误。

### 4.6 `extern func` 限制

- `extern func` 不支持 `T...` 变长参数语法；`extern func` 与 C 可变参数（`printf` 风格）的 ABI 互操作通过单独的 C ABI 扩展机制处理，不属于本规范范围。

## 5 规则

分为「必须、禁止、建议」。

- [必须] 变长参数必须是参数列表中的最后一个参数；若出现在非末尾位置，编译期报错。
- [必须] 一个函数或 callable-form `spec` 最多只能声明一个变长参数。
- [必须] 变长参数的语法标记为 `T...`，其中 `T` 为具体的已声明类型；函数体内该参数类型为 `T[]`（只读数组）。
- [必须] 变长参数始终为只读数组，不支持 `T[!]...` 形式。
- [必须] 调用侧变参位的每个实参类型必须与变参元素类型 `T` 精确匹配；字面量数值可按目标元素类型贴合，已具有静态类型的值须完全匹配。
- [必须] 零变参调用合法：编译器为变参位生成空数组并传入。
- [禁止] 将已有 `T[]` 作为一个普通变参实参直接传入变参参数位；直接转发整个数组必须使用 `...expr`。
- [必须] 直接转发已有 `T[]` 作为整个变参数组时，必须显式写为 `...expr`。
- [必须] `...expr` 只能用于调用实参，必须是最后一个实参，并且必须恰好位于目标函数的第一个变参实参位置。
- [必须] `...expr` 的目标必须声明变长参数，`expr` 的类型必须匹配目标归一化后的只读变参数组类型 `T[]`。
- [禁止] 在 `...expr` 之前同时传入同一目标的普通变参元素。
- [禁止] `extern func` 使用 `T...` 变长参数语法。
- [禁止] `spec` 参数位使用 `let` 或 `var` 修饰（继承自 `spec` 通用规则；变参位同样禁止）。
- [必须] 未绑定函数或 lambda 进入变参 callable-form `spec` 位置时，变参标志必须与 spec 声明一致；以 `T[]` 参数匹配变参 `spec` 位不合法。
- [必须] 非变参重载与变参重载同名共存时，若存在某个实参序列能同时匹配两者，编译期在声明处报冲突错误；不依赖调用侧优先级规则消歧。
- [建议] 若接口需要接受任意数量的同类型实参，优先使用变长参数而不是显式传入数组，以保持调用侧的简洁性。

## 6 编译期

- 编译器必须检查变长参数是否位于参数列表末尾；否则报错并阻止通过。
- 编译器必须检查一个函数或 callable-form `spec` 中至多只有一个变长参数；否则报错并阻止通过。
- 编译器必须在调用侧检查变参位每个实参是否与变参元素类型 `T` 兼容，不兼容时报具体位置与期望类型。
- 编译器必须在调用侧检查是否将已有 `T[]` 直接传入变参位；若是则报错并给出提示（"变参位不接受已有数组"）。
- 编译器必须在 AST 中保留调用实参 `...expr` 的预打包转发标记，不得在解析阶段将其退化为普通数组实参。
- 编译器必须检查 `...expr` 仅出现在调用实参列表末尾；非法位置使用 `SE1003`。
- 编译器必须在重载解析中检查 `...expr` 对应变参目标、首个变参实参位置和只读数组类型；目标非变参、位置不匹配、表达式非只读数组或元素类型不匹配均使用 `AE0524`。
- 编译器必须在调用侧按变参元素类型将零个或多个实参打包为 `T[]`，生成对应的数组构造代码，并将其作为最后一个参数传递。
- 对合法的 `...expr`，编译器必须直接传递表达式求值得到的数组，禁止生成变参数组数组构造、元素复制、遍历或二次打包代码。
- 编译器必须在结构匹配阶段检查函数或 lambda 的变参标志是否与目标 callable-form `spec` 一致；`T[]` 参数不匹配变参 `spec` 位。
- 编译器必须检查非变参重载与变参重载是否存在参数类型重叠（即非变参的参数序列落在变参的等效展开范围内），若存在则在声明处报冲突错误。
- 编译器必须拒绝 `extern func` 使用 `T...` 语法。

## 7 运行时

- 变参打包由编译器在调用侧生成数组构造代码实现，运行时本身不感知"变参"概念；运行时看到的只是一个普通的 `T[]` 参数。
- 预打包变参数组转发同样不引入运行时机制；运行时接收的仍是普通 `T[]`，且必须是 `expr` 求值得到的同一个数组对象。
- 打包生成的临时数组纳入 ARC 托管；调用返回后若无其他引用，自动释放。
- 函数体内 `args` 的所有操作（`args.length`、`args[i]` 等）与普通只读数组完全相同，无额外运行时开销。
