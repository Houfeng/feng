# Feng 语言流程控制规范

本文档用于补充 [feng-language.md](./feng-language.md) 中的流程控制概要说明,聚焦 Feng 语言的条件判断、`if` 表达式、循环与控制转移规则。

## 1 流程控制概览

- Feng 提供条件分支、`if` 表达式、循环和结构化异常处理。
- 条件判断支持 `if / else if / else` 形式。
- `if` 支持作为表达式使用,用于条件分支求值。
- 循环支持 `while`、`for`（三段式）、`for/in`（迭代）、`break` 和 `continue`。
- `try / catch` 与控制流的详细异常语义见 [Feng 语言异常模型规范](./feng-exception.md)。

## 2 普通条件判断

规则说明:

- `if` 和 `else if` 的条件表达式必须是 `bool`。
- 条件分支按从上到下顺序依次判断,命中第一个为 `true` 的分支后即停止后续判断。
- `else` 分支可省略，省略时表示条件全部不满足则直接离开整个分支结构。

```feng
if a > b {
  // 逻辑代码
} else if a == b {
  // 逻辑代码
} else {
  // 逻辑代码
}
```

## 3 模式匹配形式

Feng 额外支持以 `match 目标值 { ... }` 形式书写的模式匹配表达式。

该语法按目标值静态类型分为两类：

- 常量相等性匹配：目标值静态类型为 `所有整型`、`string`、`bool`、`enum`。
- union member 匹配：目标值静态类型为 union-form `spec`，分支标签写该 union-form 的归一化 member。

union-form 的成员归一化、active member 判别、收窄与显式转换边界由 [feng-union-type.md](./feng-union-type.md) 定义；本节只说明它与 `match 目标值 { ... }` 这层流程控制语法外壳的关系。

### 3.1 常量相等性匹配

规则说明:

- 匹配目标表达式先求值一次。
- 匹配目标类型仅支持 `所有整型`、`string`、`bool`、`enum`。
- 每个分支的标签部分支持以下三种形式，可在同一分支中混合使用，以逗号分隔：
  - **单值**：字面量，或初始化器为字面量的 `let` 绑定；不允许运行时表达式、含运算符的常量折叠表达式或跨绑定传播。当目标类型为 `enum` 时，单值必须写为 `EnumName.ItemName` 形式的 enum item 引用；同一 match 体中的所有 enum 标签必须引用与目标类型相同的 `enum`，不得跨 `enum`，也不得与字面量、值列表或整数区间标签混用。
  - **值列表**：多个单值以逗号分隔，如 `10, 19, 29`；支持所有条件匹配允许的类型。`enum` 目标类型下的值列表元素必须是同一 `enum` 的 enum item 引用，如 `HttpStatus.Ok, HttpStatus.NotFound`。
  - **整数闭区间**：`m...n` 表示 `[m, n]`（两端均包含），仅支持整型；`m`、`n` 须为单值形式的编译期常量，且 `m <= n`，否则编译期报错。`enum` 目标类型不支持区间标签。
  - 同一分支内可混合以上形式，如 `0, 10...18, 100`；`enum` 目标类型分支只能由 enum item 引用单值与值列表组成，不得与区间标签或字面量混用。
- 分支按书写顺序匹配，命中第一个覆盖目标值的分支后返回对应结果。
- 编译器对所有分支标签进行交叉检测：单值重复、值列表元素与其他分支重叠、区间与单值重叠、区间与区间重叠，均视为不可达死代码，编译期报错。对 `enum` 目标类型，同一 enum item 在多个分支重复出现视为不可达死代码；不同 `enum` 的同底层 `int` 值不视为重叠。
- `else` 分支可省略，省略时表示条件全部不满足则直接离开整个分支结构。
- 本节的三种标签形式（单值、值列表、整数闭区间）同时作为 §3.3 infix match 运算的 pattern 使用；块形式的多 label 用 `,` 分隔，infix 形式的多 label 用 `|` 分隔（区别见 §3.3）。

```feng
match age {
  0 { 
    // 逻辑代码
  }
  1...17 { 
    // 逻辑代码
  }
  18, 20, 22 { 
    // 逻辑代码
  }
  19, 23...59 { 
    // 逻辑代码
  }
  else { 
    // 逻辑代码
  }
}
```

### 3.2 union-form member 匹配

当匹配目标表达式的静态类型是 union-form `spec` 时，`match 目标值 { ... }` 进入 union member 匹配模式。

规则说明:

- 是否进入 union member 匹配，由目标表达式的静态类型决定；一旦进入该模式，分支标签必须写该 union-form 的归一化 member，不得与字面量、值列表或整数区间标签混用。
- 每个非 `else` 分支支持两种形式：
  - **有绑定分支** `[let|var] name: Type { ... }`：匹配的同时把收窄后的值绑定到新的局部变量 `name`；`name` 在分支内以获得的具体 member 类型操作。绑定变量默认为 `let`（不可变），可显式使用 `let` 或 `var`。
  - **无绑定分支** `Type { ... }`：仅做匹配判别，目标值在分支内保持原始 union 类型，不做自动收窄。
- 单个 member 的有绑定分支把绑定变量收窄到该确定 member 类型；多个 member 的有绑定分支把绑定变量收窄到对应 member 子集的 union 类型；`else` 分支收窄为剩余 member 集合，不支持绑定。
- 匹配只按当前 active member 判别；不会在匹配阶段把当前 member 自动向上转换到别的 `spec` 后再尝试命中分支。
- 无绑定分支内，目标值保持原始 union 类型，不可直接做成员访问或比较；有绑定分支内，若绑定变量收窄后仍包含多个 member，则仍是 union 视角，若要访问、调用或比较，必须继续收窄到单一 member。
- 允许同一匹配体中混合使用绑定分支和无绑定分支。
- 该模式的完整语义，包括 active member 的进入站点选择、object-form `spec` member 的视角取得与显式转换限制，见 [feng-union-type.md](./feng-union-type.md)。
- union member type 标签同时作为 §3.3 infix match 运算的 pattern 使用；infix 形式的 union member pattern 支持可选绑定 `[let|var] name: Type`，绑定作用域与 `if` / `while` 体绑定一致（详见 §3.3）。

```feng
match v {
  u: UserType {
    // 有绑定分支，u 的类型为 UserType
  }
  UserType {
    // 无绑定分支，仅做匹配判别，v 保持 union 类型
  }
  sub: Named, string {
    // 有绑定分支，sub 的类型为子集 union Named | string
    // 若要访问或比较，仍需继续收窄到单一 member
  }
  else {
    // 无绑定，收窄为剩余 member 集合
  }
}
```

### 3.3 infix match 运算

除了块形式的 `match 目标值 { ... }`，Feng 还支持 infix 形式的 `expr match pattern`，返回 `bool`，表示 `expr` 是否匹配 `pattern`。infix 形式把单分支 match 表达为可嵌入条件、可参与逻辑组合的 bool 表达式。

规则说明:

- 语法形式：`expr match pattern`，其中 `pattern` 复用 §3.1 / §3.2 既有标签形式（单值、整数闭区间、union member type、enum item 引用），多 label 用 `|` 分隔（区别于块形式的 `,`）。
- 运算结果为 `bool`：命中 pattern 返回 `true`，未命中返回 `false`。
- target 类型仍按 §3.1 / §3.2 的允许集合校验：常量相等性匹配支持 `所有整型`、`string`、`bool`、`enum`；union member 匹配支持 union-form `spec`。
- 可选绑定：`expr match [let|var] name: Type` 仅对 union member type pattern 有效，把收窄后的值绑定到 `name`；默认 `let`，可显式 `let` 或 `var`；多 member 子集绑定时 `name` 收窄为对应 member 子集的 union 类型。
- binding 仅在全部 label 为 type pattern 时有效；与非 type label 混用报 AE1009。
- pattern 形式与 target 类型兼容性如下：

| pattern 形式 | 适用 target 类型 | 是否支持绑定 |
| ----------- | --------------- | ----------- |
| 单值字面量 `0` / `"abc"` / `true` / `EnumName.Item` | 整型 / string / bool / enum | 否 |
| 整数闭区间 `m...n` | 整型 | 否 |
| union member type `Type` | union-form spec | 是 |
| 多 label `label1 \| label2 \| ...` | 各 label 须与 target 类型兼容 | 仅当全部为 type 时支持绑定 |

- `|` 在 pattern 位置作为 label 分隔符，**不是按位或运算符**；parser 在 pattern 解析循环内消费 `|`，退出循环后剩余 `|` 才按按位或处理。`bool | int` 本身非法（AE0030），故 `(x match 0) | 1` 这种解读天然无意义。
- 不用 `,` 作为 infix 多 label 分隔符：`,` 在函数参数、元组、数组等容器上下文已是分隔符，混用会歧义；块形式在 `{ ... }` 内无此歧义，继续用 `,`。
- 运算优先级与关系运算 `<` / `<=` / `>` / `>=` 同级、高于相等运算（`==` / `!=`）、低于算术与移位、高于逻辑 `&&` / `||`、高于赋值 `=`；同级左结合。链式 `x match a match b` 按左结合解析为 `(x match a) match b`，语义合法性由类型检查器捕获。

**绑定作用域**（可见性分析的 AST 级静态推导）：

- 从条件根递归向下收集可见的 match 绑定变量：`&&` 合并两侧；`||` / `!` 子树内全部丢弃；分组 `(A)` 透明穿透；`match v: T` 收集 v；其他运算符（`==` / `!=` / `^` / `?:` / 位运算 / 函数调用 / 类型转换等）不传播，返回空。
- `if` / `while` 条件中，body 内可见的 match 绑定变量 = `collect_visible_match_bindings(条件根)` 的结果集合，登记到体作用域。
- `A && B` 中 B 求值时可见 A 的 match 变量（`&&` 短路保证 A 为 true）。
- `||` 或 `!` 只在其子树内丢弃 match 变量；作为 match 的侄子（位于兄弟子树内）不影响 match 自身的可见性。
- `else` body 内所有 match 绑定变量一律不可见（不做 when-false 反向推导）。
- 语句后不可见：`let r = x match v: T;` 后即使写 `if r { use(v); }` 也不允许；编译器不跟踪 `r` 真值与 `v` 绑定状态的关联。
- 函数边界外不可见：`f(x match v: T)` 中 `v` 仅在 match 表达式内可见，不跨函数体传播。
- `while` 每轮迭代重新求值条件并重新绑定；上一轮的 `v` 与本轮无关。
- `!` 不做递归等价变换：`!!(x match v: T)` 中 v 不可见（外层 `!` 子树返回空）；用户应把 `!!cond` 改写为正向形式 `cond`。
- 不可见位置使用 binding 变量复用 AE0001（undefined identifier），不引入新错误码。
- 本设计是 C# `is` 模式匹配的保守简化版：不做 `!!` 等价变换、不做 else body 反向推导、不识别 `==` / `!=` 等运算符的语义等价。用户应把 match 表达式直接写在条件正向位置。

```feng
// 无绑定：返回 bool
let r = x match 0                // 值匹配
let r = x match 1...10           // 整数闭区间匹配
let r = x match UserType         // union member 匹配
let r = x match 0 | 1 | 2        // 值列表匹配（| 分隔）
let r = x match 0 | 1...10 | 100 // 值与区间混合
let r = x match Type1 | Type2    // 多 member type 匹配

// 有绑定（仅 union member 模式）
let r = x match v: UserType       // 默认 let 绑定
let r = x match let v: UserType   // 显式 let 绑定
let r = x match var v: UserType   // 显式 var 绑定
let r = x match v: Type1 | Type2 // 多 member 绑定，v 收窄为 Type1 | Type2 子集

// 用于 if 条件
if x match 0 { ... }
if x match 1...10 { ... }
if x match v: UserType { ... }       // v 在 if 体内可见
if x match var v: UserType { ... }   // v 在 if 体内可见且可变
if x match 0 | 1 | 2 { ... }         // 值列表作为 if 条件

// 用于 while 条件（每轮迭代重新求值并重新绑定）
while x match v: UserType { ... }

// 与逻辑运算符组合
if x match UserType && y match OtherType { ... }
if x match v: UserType && v.age > 10 { ... }   // v 在 v.age > 10 与 if 体内可见
```

### 3.4 块形式 `match` 的表达式结果

块形式的 `match` 作为表达式时，每个正常完成的分支均以块内最后一个表达式作为结果；以 `throw` 结尾的分支不产生结果值，也不参与结果类型检查。表达式形式必须包含 `else` 分支。

结果分支的目标类型选择与贴合统一遵循 §4.1；分支顺序为各普通分支的书写顺序，`else` 视为最后一个分支。

## 4 分支表达式

### 4.1 `if` / `match` / `try` 表达式结果类型

`if`、块形式 `match` 与带 `catch` 的 `try` 作为表达式时，所有正常完成的结果分支使用同一套目标类型选择与贴合规则：

1. 当前表达式上下文提供目标类型时，每个结果分支分别直接向该完整目标类型贴合并接受类型检查；分支之间不要求先推导为同一静态类型，也不得先按分支结果选择或改写目标类型。所有分支均贴合成功后，整个表达式的结果类型为该目标类型。
2. 无目标类型时，按书写顺序查找第一个并非可贴合数值字面量、且具有确定类型的结果分支，以其类型作为目标类型，其他结果分支分别向该类型贴合。
3. 无目标类型且所有结果分支均为可贴合数值字面量时，各分支分别按默认类型推导，随后要求结果类型一致；不得以分支顺序决定字面量之间的贴合方向。

`if` 的分支顺序为 `then`、`else`；`match` 的分支顺序见 §3.4；`try` 的分支顺序为主表达式、各 `catch` 块。以 `throw` 终止的路径不产生结果值，也不参与目标选择或贴合；若所有路径均以 `throw` 终止，结果类型为 `unknown`。

这里的“可贴合数值字面量”包括纯数值字面量及纯字面量数值常量表达式，具体定义与贴合能力以数值类型规范为准。上下文目标类型包括显式类型绑定、函数或方法参数、函数返回值、成员或局部赋值目标，以及其他能够为当前表达式提供确定目标类型的上下文。目标类型自身的接受规则仍由对应类型规范定义；例如目标为 union-form 时，分支结果能否进入该完整目标由 [Feng 联合类型规范](./feng-union-type.md) 的 member 选择规则判定，而不是由分支表达式另行选择类型。上述规则不引入额外的隐式类型转换；任一正常分支无法贴合时，表达式类型检查失败。

### 4.2 `if` 表达式

`if` 可作为表达式参与赋值、返回值计算或参数传递。表达式形式的 `if` 会返回被选中分支的值。

规则说明:

- `if` 表达式，支持上述 2 种 `if` 形式。
- `if` 表达式必须有返回值，各分支结果按 §4.1 选择目标类型并贴合，且不可省略 `else` 分支。
- 各分支块中，最后一条语句行（非自然行）必须是一个表达式；编译器始终取该表达式的值作为该分支的结果。末尾分号可加可不加，不影响块值提取。
- 各分支块的最后一条语句如果是 `if/else`、`match` 或 `try/catch`，编译器自动将其视为表达式参与块值提取。如果最后一条语句不是表达式且不属于上述可转换形式，则报 AE1101 错误。
- 各分支块的最后一条语句也允许是 `throw`，此时该分支不产生结果值，不参与结果类型推导和一致性比较。如果所有分支都以 `throw` 结尾，则表达式结果类型为 unknown，不可用于需要明确类型的上下文。

```feng
let label = if age >= 18 {
  "adult";
} else {
  "minor";
}
```

```feng
let label = match age {
  0 { "婴儿"; }
  18 { "成年"; }
  60 { "老年"; }
  else { "青年"; }
}
```

## 5 `while` 循环

- `while` 条件表达式必须为 `bool`。
- 循环体必须使用花括号块；循环体可以为空，仅包含注释的循环体也按空块处理。
- 每次进入循环体前都会重新计算条件。
- 条件为 `false` 时立即退出循环。

```feng
var i = 0;
while i < 3 {
  print(i);
  i = i + 1;
}
```

## 6 `for` 循环

`for` 支持两种形式：三段式循环与 `for/in` 迭代循环。

两种形式的循环体都必须使用花括号块；循环体可以为空，仅包含注释的循环体也按空块处理。

### 6.1 三段式 `for`

```feng
for 初始化; 条件; 更新 {
  // 循环体
}
```

规则说明：

- 初始化子句可为空，也可使用局部绑定或赋值语句。
- 非空初始化子句在进入当前 `for` 时执行且只执行一次，先于第一次条件求值。
- 条件子句可为空；为空时表示恒为 `true`。
- 更新子句可为空，通常写赋值、复合赋值或函数调用。
- 条件为 `true` 时执行循环体。循环体正常结束，或执行作用于当前 `for` 的 `continue` 时，均先将
  更新子句执行一次，再重新求值条件；更新子句为空时直接重新求值条件。同一轮只会沿一条控制路径
  到达更新子句，因此即使循环体中有多个 `continue` 分支，实际命中的路径也只执行一次更新子句。
- 执行作用于当前 `for` 的 `break` 时立即退出，不执行当前轮尚未执行的更新子句。
- 初始化子句中声明的绑定仅在当前 `for` 循环内部可见。
- 初始化子句中的绑定必须显式写 `let` 或 `var`，不可省略。
- 若更新子句对该绑定赋值，则必须声明为 `var`，否则编译期报错。
- 初始化子句声明的绑定在执行初始化子句时只产生一个绑定实例；条件、更新和每轮循环体均引用该
  实例。条件、更新或循环体引用已经在 `for` 外声明的绑定时，也始终引用原有绑定，不因进入新一轮
  而产生副本。
- 每次进入循环体都会进入该块的一次新动态执行；在循环体内执行到的局部绑定声明每次产生新的绑定
  实例。因此 Lambda 捕获外部绑定或初始化子句绑定时，各轮形成的 Lambda 引用同一绑定；捕获循环
  体内声明的局部绑定时，各轮形成的 Lambda 引用各轮各自的绑定。捕获方式统一遵循
  [Feng 语言函数规范](./feng-function.md)的引用捕获规则。

```feng
for var i = 0; i < 10; i = i + 1 {
  print(i);
}
```

### 6.2 `for/in` 循环

```feng
for let it in items {
  // 循环体
}

for var it in items {
  // 本轮可修改 it
}

for let (key, value) in entries {
  // 按位置解构本轮 tuple 元素
}
```

规则说明：

- `in` 前的循环绑定可以是单个标识符，也可以是一级 tuple 解构模式；绑定关键字必须显式写为
  `let` 或 `var`，不可省略。
- 单标识符绑定的类型由序列元素类型推断：序列类型为 `T[]` 或 `T[!]` 时，绑定类型均为 `T`。
- tuple 解构要求序列元素为具名 tuple，模式位置数必须与 tuple 元素数一致。模式只允许一级标识符
  或空位，不允许嵌套解构、单位置模式或类型标注；具体位置规则由
  [Feng 语言 tuple 规范](./feng-tuple.md)第 8 节定义。
- tuple 解构按位置为每个非空位置创建独立绑定；空位不创建绑定。模式前的 `let` / `var` 同时作用
  于所有非空位置。
- `let` 绑定在循环体内不可重新赋值，`var` 绑定可在循环体内修改，但不影响序列本身及下一轮的
  绑定值。对 tuple 解构中的 `var` 分量赋值同样不修改源 tuple。
- 循环绑定仅在循环体内可见；其绑定实例化模型等同于在每轮进入循环体前执行一次相应的单变量或
  解构局部绑定声明：每轮的每个非空位置均产生独立的新绑定，并以本轮元素或对应分量初始化。
- Lambda 捕获循环绑定时只捕获当前轮对应位置的绑定；同轮多个 Lambda 共享同一位置的该轮绑定，
  不同轮的绑定互不共享。先形成 Lambda、再修改同轮 `var` 绑定时，该 Lambda 读取修改后的值；
  `let` 绑定仍不可重新赋值。捕获方式统一遵循
  [Feng 语言函数规范](./feng-function.md)的引用捕获规则。
- 循环序列支持数组 `T[]`、`T[!]`，以及满足
  [Feng 语言迭代器规范](./feng-iterator.md)的 `@iterable` / `@iterator` 类型。
- 未加括号的迭代表达式之后，首个 `{` 作为循环体的开始，不作为对象字面量后缀。若迭代表达式本身是对象字面量，必须使用括号包裹，例如 `for let it in (Items {}) {}`。

### 6.3 绑定模型与实现开销

- 上述“整个循环共享”与“每轮独立”描述的是程序可观察的绑定身份，不要求未捕获绑定使用堆对象或
  每轮使用不同物理地址；在不改变可观察行为时，编译器可以复用栈存储。
- 编译器必须在编译期确定循环绑定是否被 Lambda 捕获。未被捕获的三段式 `for` 与 `for/in` 绑定不
  得仅为表达绑定身份而增加堆分配、capture cell、运行时捕获判断或额外 ARC；元素类型本身按
  [Feng 语言生命周期规范](./feng-lifetime.md)要求执行的生命周期管理不属于额外捕获开销。
- 只有实际被捕获且需要越过当前块存活的绑定，才按普通闭包规则持久化；该开销不得扩散到未捕获
  路径。
- 未捕获的 tuple 解构必须直接从本轮元素的对应位置建立绑定，不得为解构本身物化或复制完整 tuple、
  增加运行时模式判断或堆分配；空位不得产生绑定专属的复制、retain 或 release。被使用分量按其自身
  类型执行的必要生命周期管理不属于额外解构开销。

## 7 `break` 与 `continue`

- `break` 仅可用于 `while` 或 `for` 循环内部，用于立即退出当前最近的一层循环。退出三段式 `for`
  时不执行当前轮尚未执行的更新子句；退出 `for/in` 时不再获取下一元素。
- `continue` 仅可用于循环内部，用于跳过当前轮剩余语句，并按最近一层循环的形式继续：
  - `while`：重新求值循环条件；
  - 三段式 `for`：按第 6.1 节执行一次更新子句，再重新求值条件；
  - `for/in`：结束当前轮并获取下一元素；当前轮绑定继续遵循第 6.2～6.3 节的作用域与捕获规则。
- `break` 和 `continue` 都不携带返回值、标签或层数参数。
- Feng 不支持循环标签；循环可以嵌套，但 `break` 和 `continue` 每次始终只作用于最近一层循环，
  不支持跨层跳转。
