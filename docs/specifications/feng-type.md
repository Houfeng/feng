# Feng 语言类型规范

本文档补充 [feng-language.md](./feng-language.md) 中的类型系统概要,聚焦具体类型定义、对象行为模型、初始化与契约协作约束。

## 1 职责

`type` 是 Feng 语言中用于声明具体类型实现的机制,承担以下职责:

- 定义具体数据结构与行为实现,声明成员字段与构造函数,确立实例化与初始化语义。
- 定义类型成员绑定点,通过成员上的 `let`/`var` 决定成员可变性与初始化约束。
- 通过成员展开声明复用其他具体类型的公开实例字段，并把生成字段纳入目标自身的普通
  成员与对象布局。
- 通过 `@abi` 标注,声明可参与 ABI 兼容性校验的对象类型。
- 作为契约实现者,与 `spec`/`fit` 协作建立“具体类型满足契约”的关系。

## 2 术语

- 具名类型: 通过 `type` 声明的类型。
- 对象类型: 以对象语法声明的具名类型(如 `type User { ... }`); 是否标注 `@abi` 不改变其类型命名,只影响 ABI 边界约束。
- 对象字面量: 以 `Type() { ... }`、`Type() {}`、`Type(args) { ... }`、`Type(args) {}`、`Type { ... }` 或 `Type {}` 形式进行的对象初始化表达式; 其中 `Type { ... }` 是 `Type() { ... }` 的简写,`Type {}` 是 `Type() {}` 的简写; 泛型对象类型使用 `Type<Args>() { ... }`、`Type<Args>() {}`、`Type<Args> { ... }` 或 `Type<Args> {}` 形式显式给出类型实参。
- 数组类型: 使用数组类型语法声明的类型; 其具体定义、层级可写性、类型兼容与显式转换规则统一见 [feng-builtin-type.md](./feng-builtin-type.md)。
- C 指针类型: 使用 `T*` 语法声明、仅用于 C 互操作的指针类型。
- ABI 约束: 类型标注 `@abi` 后,在 C ABI 边界需要满足的兼容性与使用约束。
- 成员绑定: `type` 成员上的 `let`/`var` 绑定声明,用于定义成员可变性与赋值约束。
- 静态成员: `type` 中使用 `static` 声明的类型级成员,包括 `static let`、`static var` 与 `static func`; 静态成员通过类型名访问,不绑定具体对象实例。`fit` 只允许通过 `static func` 补充静态方法,不得补充静态绑定或实例字段。
- 默认零值: 无初始值绑定在编译期按类型规则得到的默认值。
- 方法值: 以 `obj.method` 形式获取的、已绑定到特定对象实例的可调用值; 调用时 `self` 始终指向该实例,不会因传递或别名而改变。
- 成员展开声明: 仅出现在 `type` 成员位置、以 `...` 开头的声明；它在编译期为目标
  生成普通实例字段，并按 [Feng 语言函数规范](./feng-function.md) 处理来源成员面中的
  `@mixable` 静态方法。
- 展开来源类型: 成员展开声明显式指定或由来源构造表达式直接确定的具体对象 `type`。

## 3 语法

正确语法一,基础与对象类型:

```feng
type User {
  let id: int;
  var name: string;

  func User(id: int, name: string) {
    self.id = id;
    self.name = name;
  }
}
```

正确语法二,带 `@abi` 的对象类型:

```feng
@abi
type Point {
  var x: int;
  var y: int;
}
```

正确语法三,显式无参构造与对象字面量简写:

```feng
type Counter {
  let value: int;

  func Counter() {
    self.value = 1;
  }
}

let a = Counter();
let b = Counter() {};
let c = Counter {};
let d = User(1, "feng") {};
let e = User(2, "feng") { name: "Feng" };
```

错语法一,在类型内嵌套声明类型:

```feng
type A {
  type B {
    var x: int;
  }
}
```

错语法二,成员类型位置内联匿名类型:

```feng
type A {
  var c: {
    var c1: string;
    var c2: string;
  };
}
```

错语法三,无参构造不可见时使用对象字面量简写:

```feng
type Hidden {
  seal func Hidden() {}
}

let x = Hidden {};
```

正确语法四,成员方法与 `self`:

```feng
type Counter {
  var value: int;

  func inc() {
    self.value = self.value + 1;
  }
}
```

正确语法五,方法值与重载决议:

```feng
type User {
  func say() {}
  func say(msg: string) {}
}

spec M0(): void;

func test(m: M0) {
  m();
}

let u = User {};
test(u.say);
let s_ok: M0 = u.say;
let s = u.say; // 错误: say 存在多个重载,当前上下文无法推导 s 的函数类型
```

`u.say` 在作为参数传给 `test` 时,传递的是一个已绑定到 `u` 所引用实例的方法值; 由于目标类型 `M0` 能唯一确定无参重载,`test` 内部执行 `m()` 时,`say` 中的 `self` 仍然指向该 `User` 实例。`let s_ok: M0 = u.say;` 同样合法,因为显式声明的目标函数类型足以唯一选定无参重载。`let s = u.say;` 则因缺少足以唯一选定重载的目标函数类型,编译期报错。

正确语法六,静态成员:

```feng
type Counter {
  open static let zero: int = 0;
  open static var count: int = 0;

  open static func create(): Counter {
    return Counter { value: 0 };
  }

  open static func wrap<T>(value: T): Box<T> {
    return Box<T> { value: value };
  }

  let value: int;
}

let c = Counter.create();
Counter.count = Counter.count + 1;
```

静态成员可带 `open`/`seal` 可见性修饰。若存在可见性修饰符,`static` 必须紧跟在 `open` 或 `seal` 之后,并始终位于 `let`/`var`/`func` 之前,即 `[open | seal] static (let | var | func) ...`。`static open let ...`、`static seal func ...` 这类顺序均为语法错误。

错语法六,通过实例访问静态成员或把构造器/终结器声明为静态:

```feng
type Bad {
  static func Bad() {}   // 错误: 构造器不能加 static
  static func ~Bad() {}  // 错误: 终结器不能加 static
}

let b = Bad {};
b.Bad();                // 错误: 静态成员不能通过实例访问
```

正确语法七,引用别名:

```feng
type User {
  var name: string;
}

let a = User { name: "guest" };
let b = a;
b.name = "admin";  // a.name 同时变为 "admin"
```

正确语法八,`let`/`var` 两层语义:

```feng
type User {
  var name: string;
  let created_at: int;
}

let user = User { name: "guest", created_at: 1 };
user.name = "admin";    // 合法: name 是 var 成员
// user.created_at = 2; // 非法: let 成员初始化后不可再赋值
// user = User {};      // 非法: user 绑定为 let,不可重新指向另一个对象
```

正确语法九，终结器:

```feng
type Resource {
  var fd: int;

  func Resource(fd: int) {
    self.fd = fd;
  }

  func ~Resource() {
    // 在对象被释放前由运行时自动调用
    // 可通过 self 访问所有成员
  }
}
```

正确语法十，显式 `: void` 与空 `return`:

```feng
type Counter {
  func Counter(): void {
    return;
  }
}

type Resource {
  func ~Resource(): void {
    return;
  }
}
```

错语法四，构造函数或终结器声明非 `void` 返回类型，或终结器带参数:

```feng
type A {
  func A(): int {}     // 错误: 构造函数不能声明非 void 返回类型
}

type B {
  func ~B(x: int) {}   // 错误: 终结器不能有参数
}

type C {
  func ~C(): int {}    // 错误: 终结器不能声明非 void 返回类型
}
```

错语法五，构造函数或终结器中的带值 `return`:

```feng
type User {
  func User() {
    return 1;        // 错误: 构造函数中的 return 只能是空 return
  }
}

type Resource {
  func ~Resource(): void {
    return 1;        // 错误: 终结器中的 return 只能是空 return
  }
}
```

正确语法十一，三种成员展开声明:

```feng
type Button: Widget {
  // 显式来源类型；生成字段各自取默认零值。
  ...: View;
}

type BoundButton: Widget {
  // 显式来源类型；构造来源一次后绑定生成字段。
  ...: View = View();
}

type GenericButton<T>: Widget {
  // 由构造表达式直接推导来源类型。
  ... = View<T>();
}
```

错语法七，在 `type` 成员以外使用成员展开声明，或使用非构造表达式作为来源:

```feng
...: View;                   // 错误: 不在 type 成员位置

type Bad {
  ...: View = makeView();    // 错误: 普通函数调用结果不是对象构造表达式
}
```

## 4 语义

### 4.1 对象类型通用语义

- Feng 采用强类型、静态类型系统,无 `any` 类型,变量、参数与返回值在编译期完成类型检查。
- 统一使用 `type` 定义具名具体类型; `spec` 负责定义 object-form 契约形状、callable-form 可调用形状与 union-form 候选成员集合。
- `@abi` 只引入 ABI 边界约束,不改变类型本身的命名、语义分类、`type` 语法形式、构造流程、默认零值或自动内存管理规则; 合法性由语义分析按 ABI 规则检查。`@abi` 与终结器互斥: 标注 `@abi` 的类型不得声明终结器,违反时编译期报错(见 §5/§6)。`@abi type` 在 Feng 内部仍采用普通对象的引用语义; 进入 C ABI 边界时,传递方式由 `extern func` 或 `@abi func` 的参数类型直接决定（参数类型为 `T` 则按 ABI payload 值语义传递,参数类型为 `T*` 则传递 payload 地址）,编译器不做额外隐式转换。
- 目前成员顺序的调整,不是兼容变更。未来增加基于编译期计算出稳定的成员 KEY 进行编译期成员重排的方式优化此问题。
- 具名类型声明必须位于模块级顶层,不支持嵌套声明、匿名类型定义或在类型位置直接内联声明类型。
- 同一模块内的具名具体类型允许前向引用与互引用。
- 对象类型支持 `Type()`、`Type(args)`、`Type() { ... }`、`Type() {}`、`Type(args) { ... }` 与 `Type(args) {}` 等对象构造写法; `Type { ... }` 与 `Type {}` 分别是 `Type() { ... }` 与 `Type() {}` 的简写; 泛型对象类型通过 `Type<Args>()`、`Type<Args> { ... }` 与对应对象字面量后缀形式显式实例化。
- 构造函数与终结器都是特殊成员函数; 构造函数必须直接写成 `func TypeName(...) { ... }`,终结器必须直接写成 `func ~TypeName() { ... }`; 两者都不得声明非 `void` 返回类型,省略返回类型或显式写 `: void` 都表示“无返回值”。
- 构造函数与终结器的函数体中若出现 `return`,只能写成空 `return;`; 不得返回任何表达式值。
- 构造对象实例的所有写法都遵循"成员声明及绑定初值 -> 构造函数 -> 对象字面量初始化"的统一流程; 某些写法只是省略了空的对象字面量阶段或把无参对象字面量写成简写形式。
- 上述构造流程在同包源码消费和外部二进制包消费时必须一致。外部包不向 consumer
  暴露字段初始化器 AST 时，由来源包的普通对象构造实现负责完成“成员声明及绑定初值”
  阶段；consumer 不得退化为仅分配默认零值对象后调用显式构造函数。
- 在成员声明及绑定初值阶段,有初始值绑定的成员直接完成显式绑定,不得先生成类型默认零值再以显式值覆盖; 无初始值的成员底层存储取类型默认零值,但这不视为该成员已完成显式绑定,后续仍可在构造函数或对象字面量阶段完成首次显式绑定。
- `var` 成员在三个构造阶段内及创建完成后均可多次赋值,不受单次最终绑定限制。
- 构造函数中的 `self` 指向当前正在初始化的对象实例; 成员方法中的 `self` 指向当前调用该方法的对象实例; 两种情况下 `self` 的绑定规则相同,均由编译器隐式提供。
- `type` 及 `fit` 块的成员 `func` 与构造函数中可使用 `self` 引用当前实例; `self` 由编译器隐式提供,无需在参数列表中显式声明; 该绑定始终稳定,不会因别名赋值、参数传递或作为方法值使用而改变; 普通 `func` 或 `Lambda` 中直接使用 `self` 编译期报错。
- `let`/`var` 在对象场景中分为两层语义: 绑定层——变量名是否允许重新绑定到另一个对象; 成员层——对象的具体成员是否允许被改写; `let user = ...;` 表示 `user` 本身不可重新绑定,但不自动冻结对象内部的 `var` 成员。
- 成员字段初始化与赋值中的数值类型匹配遵循 [Feng 内建类型规范](./feng-builtin-type.md): 数值字面量与纯字面量数值常量表达式可按已确定目标数值类型贴合; 已具备静态类型的绑定值在不同数值类型间赋值必须显式转换。
- 成员方法通过 `obj.method(args)` 调用; 以 `obj.method` 形式获取方法值时,该值已绑定到 `obj` 引用的实例,`self` 不会因传递或别名改变; 同名方法有多个重载时,赋值目标须提供足以唯一选定重载的函数类型,否则编译期报错。
- 静态成员通过类型名访问,如 `Type.member` 或 `Type.method(args)`; 不允许通过对象实例访问静态成员。静态方法不接收隐式 `self`,其调用开销必须与同等签名的模块顶层函数一致。静态绑定采用与模块顶层绑定一致的延迟初始化语义,访问开销不得高于同等类型的模块顶层绑定。
- 静态方法支持泛型,其类型参数、约束、推断、实例化与重载判定规则与实例方法一致。
- `open` 静态成员可跨 fb 包使用,包符号表必须记录其名称、所属类型、静态性、可见性、成员种类与完整类型信息; `seal` 静态成员仅在声明包内可见。
- 对象类型只有在其自身标注 `@abi` 且通过 ABI 校验后,才可直接出现在 `@abi func` 的参数或返回值位置; 未标注或未通过 ABI 校验的对象类型不应成为 `@abi type` 的直接内联成员; `@abi type` 的方法不改变其 ABI payload,且方法本身不是当前 `@abi` 目标。即使未来优化 `@abi type` 也还是声明顺序不会重排。
- 终结器以 `~TypeName` 命名（`~` 加类型同名），无参数，且不得返回值；省略返回类型或显式声明为 `: void` 都表示“无返回值”。每个 `type` 至多定义一个终结器；终结器由运行时在对象释放前自动调用，程序员不得直接调用；终结器内若出现 `return`，只能写空 `return;`；终结器内异常必须由程序员自行捕获，若异常未捕获而传播到终结器边界，运行时直接 crash；调用时机与循环组内多终结器的执行规则见 [Feng 语言对象生命周期规范](./feng-lifetime.md)。
- 标注 `@abi` 的类型不得声明终结器; `@abi` 与终结器互斥,违反时编译期报错。未标注 `@abi` 的类型若定义终结器,其声明与执行规则统一遵循 [Feng 语言对象生命周期规范](./feng-lifetime.md)。

### 4.2 成员展开

#### 4.2.1 语法与来源类型

成员展开声明只允许直接出现在具体 `type` 的成员列表中，支持三种形式:

```feng
...: Source;
...: Source = SourceConstruction;
... = SourceConstruction;
```

- `...: Source;` 显式指定来源类型，不创建来源实例。
- `...: Source = SourceConstruction;` 显式指定来源类型，并使用右侧对象构造表达式
  创建一次来源实例。
- `... = SourceConstruction;` 由右侧对象构造表达式直接确定来源类型，并创建一次
  来源实例。

`SourceConstruction` 只允许使用本规范已经定义的对象构造表达式，包括带或不带对象
字面量阶段的 `Type()`、`Type(args)`、`Type { ... }` 和 `Type(args) { ... }` 等形式；
不允许变量引用、成员访问、普通函数调用结果、条件表达式或其他任意表达式。显式来源
类型形式中的构造结果按普通绑定规则绑定到 `Source`；类型不匹配时使用现有表达式类型
诊断。

来源必须解析到确定的具体对象 `type` 声明。允许已经确定来源声明的泛型实例，例如
`View<T>`；不允许裸类型参数、任一 form 的 `spec`、`enum`、内建类型、数组或其他
非具体对象类型。来源类型和构造表达式位于目标类型成员作用域，可以引用目标类型的
泛型参数；泛型实参替换、约束检查和构造匹配使用现有规则。

成员展开不会建立来源类型与目标类型之间的继承、子类型、类型转换或运行时类型链；
来源类型声明的 `spec` 关系也不会自动复制给目标，目标仍须按现有规则显式声明需要
满足的 object-form `spec`。

#### 4.2.2 来源成员面

一个展开来源的成员面只包含以下在目标位置可见的公开声明:

1. 来源具体类型最终成员面中的实例字段；
2. 来源具体类型最终成员面中标注 `@mixable` 的静态方法；
3. 可通过普通 `Source.method(...)` 成员查找和调用的公开 `fit Source` 静态扩展方法，
   且该方法标注 `@mixable`。

来源实例方法、静态字段、未标注 `@mixable` 的静态方法、`fit Source` 实例方法、私有
声明和目标位置不可见的声明均不参与展开。`@mixable` 方法的声明、生成和传播语义由
[Feng 语言函数规范](./feng-function.md) 唯一定义。

生成字段是目标自身的普通实例字段，保留来源字段的名称、实例字段类型、`let` / `var`
可变性和公开可见性。来源字段的初始化器、其他注解和声明身份不复制到目标；生成字段
不是来源字段的别名，也不通过来源对象间接访问。目标以后作为其他类型的来源时，其
公开生成字段与手写公开字段一样继续参与成员展开。

#### 4.2.3 默认零值形式

对于 `...: Source;`，每个生成字段直接按照自身类型执行普通默认零值初始化。编译器
不得创建完整 `Source` 默认零值临时实例，不得执行来源字段初始化器、来源构造函数、
来源对象字面量阶段或来源终结逻辑，也不得增加来源对象分配、释放或引用计数。

生成的 `let` 字段保持未显式绑定状态，之后仍可在目标构造函数或目标对象字面量阶段
完成首次最终显式绑定；生成的 `var` 字段取得其字段类型的默认零值。字段类型本身不能
作为默认零值目标时，继续使用现有默认零值合法性诊断。

#### 4.2.4 显式来源构造形式

对于带 `SourceConstruction` 的形式，每次构造目标实例时，该构造表达式在现有“成员
声明及绑定初值”阶段只求值一次；同一声明产生的全部字段共用这一个来源值。字段处理
完成后，临时来源值按现有生命周期规则释放，且不保存为目标的隐藏字段。

`SourceConstruction` 必须完全复用 Feng 的普通对象构造语义，先按“成员声明及绑定
初值 -> 构造函数 -> 对象字面量初始化”的既有流程产生一个完整来源实例，再由成员展开
读取其公开字段。来源声明位于同包还是外部包不改变该流程；成员展开不得新增专用的
跨包初始化规则、构造 ABI 或字段初始化器恢复路径。如果等价的普通
`let source = SourceConstruction;` 构造不能得到完整实例，应修复普通对象构造机制，
不得在成员展开中补偿。

来源 `var` 字段始终把来源构造全部阶段完成后的最终值绑定到目标生成字段。来源 `let`
字段是否已经显式绑定，由下列已有编译期声明事实合并决定:

1. 来源字段在成员声明及绑定初值阶段已经绑定；
2. 当前构造表达式选中的构造函数绑定了该字段；
3. 当前构造表达式的对象字面量阶段绑定了该字段。

来源 `let` 已显式绑定时，读取 `source.field` 绑定目标字段，并把目标 `let` 标记为已在
目标成员声明及绑定初值阶段完成最终显式绑定；来源 `let` 未显式绑定时，不生成显式
赋值，目标字段保持默认零值和未绑定状态。绑定状态是编译期声明事实，不从来源实例
读取运行时标志。

字段值继续使用普通绑定语义：值类型按值复制，引用类型按引用绑定，callable 按现有
callable 值语义绑定。字段槽位之间不建立后续同步关系；若复制出的引用或 callable
自行保留来源实例，其生命周期只由现有引用与 RC 规则决定。

#### 4.2.5 展开顺序、冲突与循环

成员展开在普通成员合法性、`spec` 满足和代码生成检查之前完成。生成字段立即进入目标
的普通成员集合、对象布局和“成员声明及绑定初值”阶段，继续使用等价手写字段适用的
构造顺序、重复绑定、可见性、泛型、生命周期、冲突和代码生成规则。

如果目标显式成员按现有成员冲突规则与待生成字段冲突，则不生成该字段。不同成员展开
声明产生的字段之间不设来源优先级；若等价手写声明会冲突，继续使用现有冲突诊断。
生成成员引发后续诊断时，诊断必须保留目标成员展开声明和来源成员声明的位置映射。

如果一个成员展开声明的来源成员面直接或间接依赖当前目标的成员展开结果，则构成展开
依赖循环，编译器必须报错且不得进行部分展开，也不得按声明顺序截取已经可见的成员。
字段类型、方法签名或其他普通声明中的类型引用循环不属于展开依赖循环；生成普通成员
后仍由现有类型循环规则处理。

#### 4.2.6 跨包声明事实

同包声明与 `.ft` 恢复声明必须为来源查询提供一致的公开字段、字段类型、可变性、
可见性和 `let` 绑定事实。显式来源构造完全复用普通对象构造路径创建完整来源实例，
不要求 `.ft` 为成员展开额外携带来源字段初始化器 AST，也不引入成员展开专用构造
入口。

目标导出前完成成员展开，并把生成后的公开普通字段及其最终绑定事实作为目标自身声明
写入 `.ft`。下游消费已经编译的目标时使用这些普通成员，不重新执行目标原始来源声明
的展开。

## 5 规则

分为「必须、禁止、建议」。

- [必须] 有初始值绑定可省略类型并由编译器推导; 无初始值绑定必须显式标注类型并使用默认零值初始化。
- [必须] 对象类型成员必须使用 `let` 或 `var` 修饰。
- [必须] 成员展开声明只能直接出现在具体 `type` 的成员列表中，并且只能使用
  `...: Source;`、`...: Source = SourceConstruction;` 或
  `... = SourceConstruction;` 三种形式。
- [必须] 成员展开来源必须是确定的具体对象 `type`；带来源表达式的形式只能使用对象
  构造表达式，且每次目标实例构造只求值一次。
- [必须] 成员展开只生成公开实例字段以及 [Feng 语言函数规范](./feng-function.md) 定义
  的 `@mixable` wrapper；不得展开实例方法、静态字段或未标注的静态方法。
- [必须] `...: Source;` 必须直接默认初始化每个生成字段，不得创建完整来源实例。
- [必须] 展开生成字段使用等价手写字段适用的普通成员、构造、绑定、冲突、可见性、
  泛型、生命周期和代码生成规则。
- [禁止] 对展开依赖循环进行部分展开或按声明顺序选择已经可见的来源成员。
- [必须] 类型成员默认公开; 需要收窄访问范围时,必须显式使用 `seal`。
- [必须] `type` 内静态成员必须写作 `[open | seal] static let`、`[open | seal] static var` 或 `[open | seal] static func`; 若存在 `open`/`seal`,则 `static` 必须紧跟其后。
- [必须] 成员 `let`/`var` 绑定语义与赋值规则遵循 `feng-binding.md` 的统一绑定规范。
- [必须] 成员字段初始化与赋值时，数值字面量或纯字面量数值常量表达式可按目标数值类型贴合；包含已具备静态类型绑定值的跨类型赋值必须显式转换（详见 [Feng 内建类型规范](./feng-builtin-type.md)）。
- [必须] 对象类型成员类型必须引用已声明具名类型。
- [必须] 构造函数与类型同名,按“名称 + 参数个数 + 参数类型”参与重载决议,且不得声明非 `void` 返回类型; 省略返回类型或显式写 `: void` 都合法。
- [必须] 同一 `type` 内的成员方法按“名称 + 参数个数 + 参数类型”参与重载决议; 同名同参（参数个数与每个位置参数类型完全一致）的多个方法构成重复签名,编译期报错; 仅返回类型不同、参数列表完全相同的两个重载亦非法,编译期报错。
- [必须] 同一 `type` 内静态方法与实例方法形成独立重载集合; 静态方法之间仍按“名称 + 泛型参数数量 + 参数个数 + 参数类型”参与重载决议。
- [必须] 同一冲突面内字段与无泛型方法不得同名; 实例字段与实例方法属于同一冲突面,静态字段与静态方法属于同一冲突面; 静态成员与实例成员因访问路径不同(`TypeName.member` 与 `self.member`)不构成冲突面; 违反时编译期报错。
- [必须] 静态成员只能通过类型名访问,不得通过对象实例访问。
- [必须] 静态绑定的访问与初始化必须复用模块顶层绑定的延迟初始化规则。
- [禁止] 构造函数或终结器声明为 `static`。
- [必须] 构造函数函数体中若出现 `return`,只能使用空 `return` 语句。
- [必须] 对象类型支持 `Type()`、`Type(args)`、`Type() { ... }`、`Type() {}`、`Type(args) { ... }` 与 `Type(args) {}`; 其中 `Type { ... }` 与 `Type {}` 分别是 `Type() { ... }` 与 `Type() {}` 的简写。
- [必须] 构造对象实例的所有写法都必须遵循“成员声明及绑定初值 -> 构造函数 -> 对象字面量初始化”的统一流程; 其中某些写法只是该流程的简写形式。
- [必须] 若对象类型未显式声明任何构造函数,则视为存在默认的公开无参构造函数。
- [必须] `Type()`、`Type() { ... }`、`Type {}` 与 `Type { ... }` 都依赖当前作用域可见的无参构造; 若显式把无参构造声明为 `seal`,则在不可见作用域中不得使用这些写法。
- [必须] `Type(args)`、`Type(args) {}` 与 `Type(args) { ... }` 都依赖当前作用域可见且能匹配实参的构造函数。
- [必须] `let` 成员在成员声明及绑定初值、构造函数和对象字面量三个构造阶段内至多完成一次最终显式绑定。
- [必须] 若某个 `let` 成员在三个构造阶段都未完成显式绑定,则实例创建结束后保留其底层默认值。
- [必须] 三个构造阶段结束后,`let` 成员无论最终取显式绑定值还是默认值,都不得再绑定或赋值。
- [必须] 对象类型的默认零值采用递归零值实例语义,不执行构造函数; 自引用或互引用的对象类型不可作为默认零值目标,无初始值绑定该类型时编译期报错。
- [必须] 具体 `type` 进入 object-form `spec` 位置前必须通过定义头或可见 `fit` 显式建立契约关系。
- [必须] 具体 `type` 只能通过定义头或可见 `fit` 显式满足 object-form `spec`; callable-form 与 union-form `spec` 不能作为 `type` 声明头或 `fit` 的满足目标。
- [必须] union-form `spec` 是具名类型位置中的值视角,具体值只能在赋值、初始化、传参、返回等值流站点进入 union-form,并按 [Feng 语言 `spec` 规范](./feng-spec.md) 与 [Feng 联合类型规范](./feng-union-type.md) 确定 active member。
- [必须] `fit A { ... }` 形式的自扩展只为 `A` 补充方法,不单独建立新的 `spec` 契约关系；`fit` 块中不得声明 `let`/`var` 字段。
- [必须] 若同一重载集合中的两个候选在当前可见的显式契约关系下可能同时匹配同一实参类型,则该重载集合非法,编译期报错。
- [必须] 对象字面量中每个成员按书写顺序逐个初始化; 同一字面量中同名成员最多只能出现一次,若重复出现则编译期报错。
- [必须] 对象字面量只能初始化当前作用域可访问的成员; 来自其他模块的 `seal` 成员不可在对象字面量中直接赋值。
- [必须] 泛型对象实例的对象字面量初始化,必须先按显式类型实参替换成员类型中的泛型形参,再检查字段初始化表达式类型。
- [必须] 构造函数中对 `self.<let成员>` 的直接赋值视为该成员在构造阶段完成最终显式绑定。
- [必须] 只有标注 `@abi` 且通过 ABI 校验的对象类型,才可直接出现在 `@abi func` 的参数或返回值位置; 未标注或未通过 ABI 校验的对象类型不应成为 `@abi type` 的直接内联成员。
- [必须] 终结器必须以 `~TypeName` 命名（`~` 加类型名称），无参数，且不得声明非 `void` 返回类型; 省略返回类型或显式写 `: void` 都合法。
- [必须] 终结器函数体中若出现 `return`,只能使用空 `return` 语句。
- [必须] 每个 `type` 至多定义一个终结器。
- [禁止] 标注 `@abi` 的类型声明终结器; `@abi` 与终结器互斥。
- [禁止] 直接调用终结器。
- [禁止] 终结器内让异常传播至终结器外部；终结器内的可能抛出操作须自行 `try`/`catch` 处理；若异常未捕获达到终结器边界，运行时直接 crash。
- [禁止] `void` 作为变量、成员、数组元素或普通值类型使用。
- [禁止] 在 `type` 内嵌套声明新类型。
- [禁止] 在成员类型位置内联声明匿名类型或新的具名类型。
- [建议] 对第三方或无法改动源码的类型,优先通过 `fit` 建立契约关系。

## 6 编译期

- 编译器必须检查 `type` 成员与实例创建路径的类型合法性与初始化路径。
- 编译器必须解析并保存三种成员展开声明的来源类型、可选构造表达式、自动推导形式，
  以及目标展开声明到来源成员声明的诊断位置映射。
- 编译器必须检查展开来源为确定的具体对象 `type`，并检查右侧只使用对象构造表达式。
- 编译器必须检测直接或间接的展开依赖循环并报错，不得在该检查中扩大普通类型引用
  循环的既有处理范围。
- 编译器必须在普通成员检查前生成公开实例字段；默认零值形式不得构造来源实例，显式
  来源构造形式必须只求值一次并按来源最终绑定事实生成目标字段绑定。
- 编译器必须让同包声明和 `.ft` 恢复声明提供一致的来源成员面，并把目标生成字段及其
  最终绑定事实按普通目标成员导出。
- 编译器必须检查 `type` 声明位置是否满足模块级顶层约束。
- 编译器必须检查成员类型引用是否为已声明具名类型。
- 编译器必须检查构造函数是否与所属 `type` 同名,且不得声明非 `void` 返回类型; 省略返回类型或显式 `: void` 都视为“无返回值”。
- 编译器必须检查构造函数函数体中若出现 `return`,是否始终为不带表达式的空 `return` 语句。
- 编译器必须检查成员 `let`/`var` 绑定是否合法,并按绑定规则验证赋值路径。
- 编译器必须在解析阶段检查 `static` 的关键字顺序,并拒绝静态构造器、静态终结器以及实例侧访问静态成员的非法写法。
- 编译器必须在语义阶段解析类型名上的静态成员访问与调用,并按可见性、重载、泛型实例化和跨包符号表信息完成校验。
- 编译器必须为成员声明及绑定初值阶段生成对应初始化逻辑; 带初始值且省略类型的成员字段必须以初始化器推导结果作为静态成员类型。
- 编译器必须按“成员声明及绑定初值 -> 构造函数 -> 对象字面量初始化”的顺序检查对象创建路径,并把所有对象构造写法归一到这一流程上,据此处理构造函数匹配、默认无参构造函数、构造可见性与对象字面量初始化。
- 编译器必须保证外部二进制包的普通对象构造完整执行同一流程；该能力属于普通对象
  构造实现，不得由成员展开或其他消费方语法分别补偿。
- 编译器必须检查 `Type { ... }` 与 `Type {}` 是否正确解析为对应的无参构造加对象字面量初始化,并检查 `Type(args) { ... }` 与 `Type(args) {}` 是否正确解析为匹配构造加对象字面量初始化。
- 编译器必须检查对象创建阶段中 `let` 成员是否发生重复显式绑定。
- 编译器必须检查 `let` 成员在三个构造阶段结束后是否仍出现非法绑定或赋值。
- 编译器必须检查 `type` 与 `spec` 职责边界: 契约形状由 `spec` 定义,`type` 仅声明具体实现类型。
- 编译器必须拒绝 callable-form 或 union-form `spec` 出现在 `type` 声明头与 `fit` 满足目标中。
- 编译器必须检查标注 `@abi` 的类型是否满足 ABI 约束。
- 编译器必须检查对象字面量中是否出现同名成员重复初始化,并在编译期报错。
- 编译器必须在语义阶段检查同一 `type` 内同一冲突面中字段与无泛型方法是否同名,并在编译期报错; 静态成员与实例成员因访问路径不同不构成冲突面,不在此检查范围内。
- 编译器必须检查对象字面量中每个被初始化的成员在当前作用域是否可访问(`seal` 成员不可从外部字面量赋值)。
- 编译器必须在泛型对象字面量中使用实例化后的成员类型进行字段初始化类型检查。
- 编译器必须检查类型重载与契约关系是否存在歧义或冲突,并在语义阶段报错阻止通过。
- 编译器必须检查终结器是否符合 `~TypeName` 命名规则，且无参数，且不得声明非 `void` 返回类型；省略返回类型或显式 `: void` 都视为“无返回值”。
- 编译器必须检查终结器函数体中若出现 `return`,是否始终为不带表达式的空 `return` 语句。
- 编译器必须检查每个 `type` 是否至多定义一个终结器。
- 编译器必须拒绝标注 `@abi` 的类型声明终结器(`@abi` 与终结器互斥)。
- 编译器必须拒绝任何直接调用终结器的代码。
- 编译器必须检查无初始值绑定的目标类型是否可作为默认零值目标; 当目标类型是对象类型且存在自引用或互引用时,必须报错并要求显式初始化器。

## 7 运行时

- 无初始值绑定按类型规则得到默认零值。
- `...: Source;` 在运行时只保留目标自身的生成字段，不创建或保存来源对象；字段访问
  与等价手写目标字段相同，不经过运行时间接转发。
- 带来源构造表达式的成员展开在每次目标实例构造时创建一次临时来源值，完成普通字段
  绑定后按现有生命周期释放；目标中不保存隐藏来源对象或隐藏 base 字段。
- 对象类型的默认零值是“递归零值实例”: 由运行时分配一个该类型的新实例,内存先按字节零初始化,随后按字段类型递归赋予对应默认零值(数值/布尔字段保持位零,`string` 字段取 `""`,数组字段取 `[]` / `[!]`,嵌套对象字段递归取其类型默认零值);该过程不执行用户构造函数,也不进入对象字面量初始化阶段。若类型存在终结器,则该实例在被自动内存管理机制释放前仍正常触发终结器。
- 若某个对象类型自身或其传递包含的某个字段类型构成对象引用环路(自引用或互引用),则该类型不可作为默认零值的目标:`let x: T;` 或 `var x: T;` 这类无初始值绑定在编译期报错,要求显式提供初始化器以打破环路。
- 对象类型采用托管引用语义; 赋值、传参与返回默认复制引用而非复制对象本体; 多个变量可同时引用同一对象实例,对任一引用的修改均可通过其他引用观察到。
- `string`、数组、对象类型与闭包环境由自动内存管理机制托管。
- 对象字面量阶段在构造函数执行完成后运行; `Type { ... }` 与 `Type {}` 分别等价于 `Type() { ... }` 与 `Type() {}`; `Type(args) { ... }` 与 `Type(args) {}` 则表示在匹配构造函数执行后再进入对象字面量初始化阶段。
- 因此对象创建的最终成员值取决于“成员声明及绑定初值 -> 构造函数 -> 对象字面量初始化”三阶段的有序合成结果。
- 标注 `@abi` 的类型在 Feng 语言内部继续采用普通对象的引用语义：赋值、传参与返回默认复制引用而非复制对象本体；其对象生命周期与构造器规则与未标注 `type` 一致; 但 `@abi` 类型不得声明终结器(见 §5)。进入 C ABI 边界时，传递方式完全由 `extern func` 或 `@abi func` 参数类型决定；按值位置传递 ABI payload，按指针位置传递 payload 地址，编译器不做额外隐式转换。
- `T*` 指针与 C 侧分配内存同样不受自动内存管理。
- 对象类型上的 `==` / `!=` 默认比较引用身份; 两个不同实例即使成员值完全相同,仍不相等; 若需要值语义比较,应显式编写比较函数或成员方法。
- 定义了终结器的对象在被自动内存管理机制确认释放前，运行时自动调用其终结器；调用时机与释放流程见 [Feng 语言对象生命周期规范](./feng-lifetime.md)。
