# 内存访问摘要

> **状态：已终止 · 已归档。日期：2026-09-29。**
>

> 推导及相应 FT 元数据已退出本轮实现；下述语法、诊断码和编码要求均不生效。
> 现行互操作、符号表及诊断规范已撤回对本方案的增补。
> 终止范围与验证历史见[归档开发方案](../engineering/feng-memory-access-inference-dev.md)。

## 1. 范围

内存访问摘要是编译期事实，描述一次调用可能产生的内存访问上界。它不改变参数绑定、
值复制、共享引用、异常或求值顺序。普通 Feng 函数由编译器推导；外部函数可以提供
显式契约。摘要随 Symbol 和 FT 保存，不要求依赖包分发源码。

## 2. 访问与未知

访问权限是两个独立的位：读和写，组合为 `none`、`read`、`write`、`readwrite`。
`unknown` 是独立的知识状态，不是第五种权限。某个区域未知时，该区域不能获得限制性
优化承诺；已经观察到的读写仍保留。合并分支、循环和调用时取可能行为的并集。

区域区分参数可达内存、全局及其他外部状态。内部表示可以进一步记录参数来源，但
不由此承诺不同参数互不别名。不能定位的访问影响全部外部区域。

参数槽位和未逃逸局部槽位属于本次调用。读取参数、给 `var` 参数重新绑定，以及读写
未逃逸的值副本，不等于访问调用者的绑定。通过对象、数组或值副本中的共享引用访问
外部存储，仍分别计入读、写或读写。无法证明来源或逃逸性质时保守扩大范围。

摘要分别保存显式操作与隐式操作的结果。ARC、对象构造和清理、运行时辅助调用、
全局惰性初始化、异常载荷和捕获状态均属于实际调用行为。不能证明其访问行为时，
隐式部分为未知。可供原生后端使用的结果必须合并这两部分。
其中浮点余数运算的 libm 调用及 defer 的清理登记／执行均须计入；源码中的局部
算术或局部清理不能代替对这些调用的证明。
隐式转换按目标类型计算，包括标量进入 union／spec 的装箱、参数桥接和隐藏返回
存储；不能仅由右值或返回表达式的标量类型判为无隐式访问。

## 3. 自动推导

推导消费语义分析已经解析的声明和调用身份。直接调用、不可变 callable 来源和已知
回调实参传播摘要；共享可变 callable、开放分发或其他无法证明的目标保持未知。
未知不能被当作空摘要。函数的返回值来源与调用本身的访问分别记录。

递归和相互递归使用单调不动点：仅在全部依赖稳定后发布结果。分析中间态不是对外的
`none` 证明。泛型和 spec 的开放部分保守处理；已解析的具体实现沿用相同调用规则，
不依据函数名、库名或基准程序形态识别行为。

捕获异常不撤销此前已经发生的内存访问；catch 和 defer 的行为同样并入摘要。
异常传播摘要的定义见[异常规范](feng-exception.md#6-编译期异常摘要)。

## 4. 外部契约

仅顶层 `extern func` 可以写 `@memory`，且只能出现一次，参数必须为一个字符串
字面量，值为 `none`、`read`、`write` 或 `readwrite`。分别承诺整个外部调用没有
外部读写、只可能读、只可能写或可能读写。未标注的外部函数保持未知。
字面量按既有字符串语法解码，包括原始字符串与转义；不接受绑定或常量表达式。

契约约束整个调用，包括被调用函数、回调、线程同步和可观察状态。绑定作者负责契约
真实性；错误契约可能使优化后行为错误。`errno` 等状态不能忽略。此注解不承诺
无异常、必定返回、不捕获参数、不别名或可提前执行；也不表示数学意义的纯函数。

适用位置错误使用 `AE1339`，参数错误使用 `AE1340`，重复声明使用 `AE1341`。
诊断指向对应注解；重复声明指向第二个注解。不存在手写分区域或按参数的注解语法。

## 5. 持久化与消费

FT 必须保存结构化内存摘要及其必要调用依赖。未知是合法摘要；缺少必要摘要、损坏
的引用或非法编码是无效产物，不得用未知掩盖。现有模块须重新编译；缓存按原有失效
路径重建，包错误提示重新构建生产端。消费和实例化不得修改共享声明摘要。

原生函数属性必须依据最终 ABI 和隐式操作验证。内存信息只授权对应 `memory(...)`
限制；异常信息只授权已证明的 `nounwind`。不得附带 `willreturn`、`noalias` 等
未经独立证明的属性，不能把外围 catch 后的空异常结果贴到内部被调用者。

后端优化保持默认优化等级和既有浮点行为，不要求 LTO 或全局关闭向量化。未证明的
性质不添加属性；LLVM 对可见函数体自行完成的分析不受此规则限制。
