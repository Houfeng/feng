## ISSUE-G12-001：用户不可达的 SE 发码点不应驱动 G12 用例或错误码重构

### 归属

- 发现组：G12；
- 关联组：无；
- 发现用例：Parser 稳定诊断实施前的源码、规范与现有测试反向审计。

### 现象与结论

- 最小复现：沿 `feng_parse_source`、`parse_program` 和各静态 Parser helper 的唯一调用链，核对每个
  `SE` 发码点的调用前置条件；
- 实际结果：当前实现存在 15 个用户输入不可达的 `SE` 发码点，涉及 13 个不同错误码。其中 10 个
  由调用方 token、循环退出条件或数量上限保证，是纯内部不变量防御；1 个 lambda arrow 诊断被
  候选识别条件遮蔽；4 个 `extern` 相关下层诊断被顶层“`extern` 只能跟 `func`”分派提前截获；
- 规范与实现另有 `SE0311`、`SE1107`、`SE1404` 三个当前没有实现发码点的条目；连同仅存在于不可达
  分支的 `SE0306`、`SE0401`、`SE0513`、`SE0516`、`SE0801`，共 8 个现行条目没有用户可达路径；
- 结论：这些位置不能作为“缺少反向用例”的依据。为它们制造源码用例不可行；把内部防御批量改为
  `IE`、改变 lambda 识别或重排 `extern` 诊断会把 G12 扩大为错误码和 Parser 分派重构，不符合本组
  以正向/反向语法覆盖为主的目标。

### 决策与实施

- 状态：已关闭；
- 分类：既有测试问题；
- 建议方案：G12 只覆盖当前用户输入可达的语法分支；不可达发码点保留审计记录，不计入覆盖率，
  不在本组修改。后续如需收敛 `SE` / `IE` 分类、失效错误码或改善 lambda/`extern` 专项诊断，应另立
  独立任务并由人工决定用户可见诊断兼容策略；
- 是否涉及既有测试修改：否；G12 只新增独立测试；
- 是否涉及运行时性能：否；本问题不修改产品实现；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 人工决策与批准范围：已确认 G12 的关键目标是更全面覆盖正向和反向用例，使核心编译器及后续变更
  更有保障；错误码具体取值和不可达防御重构不是本组重点；
- 实际变更：仅在 G12 实施文档和本问题文件中固定覆盖边界，未修改 Parser 或错误码主规范。

### 验收与关闭

- 本组专项复验结果：`make build/bin/test_parser && build/bin/test_parser` 通过；不可达分支未进入新增
  反向用例，所有新增失败源码均为直接调用 `feng_parse_source` 可达的 Parser 路径；
- 本组沙箱外 `make test` 结果：通过，退出码 0；UBSan 与 normal 两个干净阶段均完成；
- 关闭依据：人工已确认上述范围；本问题的处理目标是阻止不可达分支驱动伪用例或大范围错误码改动，
  该范围已写入实施文档。若未来启动诊断分类收敛，应使用新的独立问题和交付范围。

## ISSUE-G12-002：`else if` 的简单标识符条件会把后续空块误解析为对象字面量

### 归属

- 发现组：G12；
- 关联组：无；
- 发现用例：PARSE09 / PARSE13，`test_g12_control_flow_and_try_syntax` 正向用例。

### 现象与结论

- 最小复现：`if ready {} else if retry {} else {}`；
- 预期结果：按流程控制主规范解析为两个条件分支和一个 `else` 分支；`retry` 是第二个条件，紧随的
  `{}` 是该分支的空 block；
- 实际结果：Parser 在第二个 `else if` 条件后面的 `else` token 处报告 `SE0005 expected '{' to start
  block`；
- 原因：`parse_if_statement()` 对首个条件使用 `parse_expression_before_block()`，会在控制流 head 中
  抑制未分组对象字面量 suffix；但后续 `else if` 条件直接调用 `parse_expression()`。当条件末尾是可接
  对象字面量的标识符且 block 为空时，`retry {}` 被整体吞成对象字面量，之后才尝试解析分支 block；
- 规范依据：`docs/specifications/feng-flow.md` 第 1、2 节已经明确支持 `if / else if / else`，并要求
  `if` 与 `else if` 使用相同的 bool 条件规则；本问题不需要修改语言规范。

### 决策与实施

- 状态：已关闭；
- 分类：产品缺陷（既有编译 Bug）；
- 建议方案：后续 `else if` 条件与首个 `if` 条件统一调用现有
  `parse_expression_before_block()`，不增加新的语法特判；
- 是否涉及既有测试修改：否；新增独立 G12 正向用例固定简单标识符条件、空 block 和三分支 AST；
- 是否涉及运行时性能：否；只调整编译期 Parser 的既有入口复用，不改变生成代码和 runtime；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 人工决策与批准范围：用户已批准补齐 G12，并要求增补用例发现的编译 Bug 在记录、分析后解决；该
  修复遵循既有明确规范且不引入运行时开销，不存在待选择语义；
- 实际变更：把 `parse_if_statement()` 的后续 `else if` 条件从 `parse_expression()` 切换为与首个条件
  相同的 `parse_expression_before_block()`；新增正向用例核对两个 clause、最终 `else` block 和简单
  标识符条件。

### 验收与关闭

- 本组专项复验结果：`make build/bin/test_parser && build/bin/test_parser` 通过，新增最小复现已解析为
  两个 `FengIfClause` 和一个最终 `else` block；
- 本组沙箱外 `make test` 结果：通过，退出码 0；UBSan 与 normal 两个干净阶段均完成，FCTS
  1072/1072、smoke 90/90、std 601/601；
- 关闭依据：规范行为、正向 AST、既有 Parser 测试及完整全量回归全部通过；变更只影响编译期解析，
  不增加生成程序运行时开销。

## ISSUE-G12-003：直接书写的 `if` 表达式 `else if` 链被 Parser 拒绝

### 归属

- 发现组：G12；
- 关联组：无；
- 发现用例：PARSE09 / PARSE13，`test_g12_expression_and_postfix_syntax` 正向用例。

### 现象与结论

- 最小复现：`let result = if first { 1 } else if second { 2 } else { 3 };`；
- 预期结果：合法 `if` 表达式；条件按顺序判断，AST 可归一化为根 `if` 的 `else` block 中嵌套第二个
  `if` 表达式；
- 实际结果：`parse_if_expression()` 消耗 `else` 后只接受 `{...}`，在 `if` token 处报告 `SE0005
  expected '{' to start block`；
- 原因：statement form 已用 clause 数组支持 `else if`，且结果分支末尾的 statement-form `if` 链已
  能转换为嵌套 `FENG_EXPR_IF`；但直接 expression form 没有把 `else if` 归一化到同一既有 AST；
- 规范依据：`docs/specifications/feng-flow.md` 第 1、2 节定义 `if / else if / else`，第 4.2 节定义
  `if` 可作为表达式并支持前述 `if` 形式。

### 决策与实施

- 状态：已关闭；
- 分类：产品缺陷（既有编译 Bug）；
- 建议方案：`parse_if_expression()` 在 `else` 后遇到 `if` 时递归解析嵌套 `FENG_EXPR_IF`，再用单一
  expression statement 的 block 承载它；普通 `else {...}` 保持现有路径；
- 是否涉及既有测试修改：否；新增独立 G12 正向用例核对根/嵌套 `FENG_EXPR_IF` AST；
- 是否涉及运行时性能：否；该 AST 与用户显式写成 `else { if ... }` 的既有形式相同，不新增语义、
  codegen 分支或生成代码开销；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 人工决策与批准范围：用户已批准按规范补齐 G12，并要求增补用例发现的编译 Bug 在记录、分析后
  解决；主规范和既有 AST 对预期行为均已有明确依据，不存在待选择语义；
- 实际变更：`parse_if_expression()` 在 `else` 后识别直接 `if`，递归构造嵌套 `FENG_EXPR_IF`，并以
  单一 expression statement block 承载；新增正向用例核对根与嵌套节点。普通 `else {...}` 路径未改。

### 验收与关闭

- 本组专项复验结果：`make build/bin/test_parser && build/bin/test_parser` 通过，直接 `else if`
  expression 已归一化为预期嵌套 AST；
- 本组沙箱外 `make test` 结果：通过，退出码 0；UBSan 与 normal 两个干净阶段均完成，FCTS
  1072/1072、smoke 90/90、std 601/601；
- 关闭依据：主规范、正向 AST、既有 Parser/Semantic/Codegen 路径及完整全量回归全部通过；生成 AST
  与显式 `else { if ... }` 相同，不增加生成程序运行时开销。
