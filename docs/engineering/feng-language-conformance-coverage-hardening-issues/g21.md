## ISSUE-G21-001：数组层数在 `.ft v1` 与 Semantic subject key 中分别受 32 / 64 位固定容量限制

### 归属

- 发现组：G21 实施前审计；
- 关联组：G23 的 array fit / witness，但一般 fit 语义仍归 G23；
- 发现用例：ARRAY-D04～ARRAY-D06。

### 现象与结论

- `src/symbol/ft_write.c` 当前把数组 rank 写入一个 record，并用 32 位字段保存逐层可写位；rank 大于
  32 时直接报告内部错误。若只删除该 guard，第 33 层以后的 `!` 会丢失，不能视为修复；
- `src/semantic/semantic.h` 的 array subject key 使用单个 `uint64_t writable_mask`，
  `feng_semantic_subject_key_init_array_from_type_ref` 在 rank 达到 64 时返回失败。因此普通类型路径虽然
  使用递归 / 动态结构，超过 64 层的 array fit / witness 身份仍不能建立；
- 两个限制来自内部表示宽度，不是语言语义。它们会使同一个公开数组类型在源码内、导出时和作为
  spec subject 时得到不同结果，属于产品缺陷和测试缺口；
- 语言结论：Feng 不设置固定的数组嵌套层数上限，所有实际出现的有限层数及每层 `!` 都必须精确保留。
  33 / 65 层仅作为越过现有固定容量的回归样本，不形成新的上限。

### 决策与实施

- 状态：已关闭；
- 分类：产品缺陷、跨包一致性缺口和测试缺口；
- 批准方案：`.ft` 与 Semantic subject key 均改用可随实际类型结构扩展的表示，禁止把 32 / 64 换成
  更大的固定常量，也禁止截断可写位。`.ft v1` 优先复用已有可组合类型 record，以递归或分段方式保持
  旧 reader 可理解的表示；如果完整修复确实需要改变 `.ft` wire 格式或版本，必须先暂停并取得人工
  决策；
- 是否涉及既有测试修改：默认否，新增 33 / 65 层的 Parser、Semantic、Symbol、Codegen 和 FCTS
  回归；若必须修改既有断言，先列出精确名单并再次取得批准；
- 是否涉及运行时性能：否。类型层数和 subject key 仅在编译期处理，生成程序不得新增运行时字段、
  判断、分支、调用、分配或 ARC；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：不得修改 runtime 私有 ABI 或公开 ABI；`.ft`
  内容表示属于本问题范围，但格式 / 版本变更尚未概括授权，触发时须再次决策。

### 验收与关闭

- `.ft v1` writer 已把任意有限层数组拆成既有 32 层 ARRAY record 链，reader 再无损合并；没有改变
  wire 版本。Semantic 对 64 层以内保留紧凑 mask，超过 64 层改以完整 type-ref 树作为结构身份，并
  把跨阶段使用的树复制到 analysis 生命周期；
- Parser、Semantic、Symbol、Codegen 与 FCTS 已覆盖 33 / 65 层、交替 `!`、不同结构不碰撞，以及
  短名、alias、完整路径的真实 `.ft` consumer；专项与 G21 全量回归通过。

## ISSUE-G21-002：`Type[:n]` 在范围检查前直接窄化为 `size_t`

### 归属

- 发现组：G21 实施前审计；
- 关联组：G04 的整数语义、G18 的元素默认零值；
- 发现用例：ARRAY-D21～ARRAY-D25。

### 现象与结论

- Semantic 当前只检查 `n` 的静态类型是否为整数，没有检查可确定值的非负范围；
- `cg_emit_array_new` 当前先把 `n` 直接转换为 `size_t`，再调用数组分配函数。负数会变成大无符号值，
  比 `size_t` 更宽的整数在窄目标上还可能截断；runtime 现有乘法、对象总大小和 OOM 防御只能观察
  转换后的值，不能恢复原值是否合法；
- `length()` 的语言结果为目标平台 `int`。若允许数组长度超过 `int` 最大值，后续读取长度才 panic，
  会使“已成功创建的数组”不满足语言长度契约；
- 结论：当前路径没有完整实现合法长度值域，属于产品缺陷、规范缺口和测试缺口，不能把偶然的分配
  溢出 / OOM panic 当作负数或超 `int` 上界的正确诊断。

### 决策与实施

- 状态：已关闭；
- 分类：产品缺陷、诊断契约缺口和运行时边界缺口；
- 批准方案：`n` 的合法范围统一为目标平台 `int` 的非负值域。编译期可确定的非法值在长度表达式产生
  新数组段诊断 `AE0204`；动态值先以其原整数类型求值一次并完成范围检查，通过后才转换为分配大小。
  动态非法值在分配及元素默认初始化前 panic，不允许截断、回绕或 UB。合法长度导致的字节数溢出或
  OOM 继续由分配路径 panic；
- 是否涉及既有测试修改：默认否，新增 32 / 64 位 Semantic、Codegen、runtime、隔离 CLI 和 FCTS
  用例；
- 是否涉及运行时性能：静态值必须在编译期消除检查；动态值只在 `Type[:n]` 创建点增加一次已批准的
  值域验证，并尽量与现有分配溢出检查收敛。普通数组读取、写入、`length()`、遍历和 ARC 不得增加
  开销；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：默认均不修改。若正确实现需要新增或改变
  runtime 私有接口，必须先提交接口、调用面、运行时开销和无 ABI 方案比较，由人工再次决策。

### 验收与关闭

- 32 / 64 位 Semantic 矩阵已锁定静态合法范围及 `AE0204`；生成代码对动态长度先保留原值、求值一次，
  在窄化和分配前完成一次范围判断，静态合法长度不生成该判断；
- 隔离 CLI 已覆盖动态负数与超过目标 `int` 最大值，runtime 专项已覆盖确定性乘法 / 对象总大小溢出；
  性能约束与 G21 全量回归通过。

## ISSUE-G21-003：限定类型路径不能作为 `Type[:n]` 的元素类型入口

### 归属

- 发现组：G21 实施前审计；
- 关联组：G02 的三种公开顶层名称访问形式；
- 发现用例：ARRAY-D20。

### 现象与结论

- 模块主规范已规定公开具名类型可通过导入短名、`import ... as` 别名和完整模块路径用于类型引用与
  构造语境；
- Parser 的 array-new 分支当前只接受标识符或“标识符 + 泛型实参”，`alias.Type[:n]` 和
  `full.module.Type[:n]` 的 target 是成员链，因而被 `SE0201` 误拒绝；
- 结论：这是 G02 已确定通用名称规则在 array-new 语法入口的实现遗漏，不需要新增模块语义。

### 决策与实施

- 状态：已关闭；既有规范已唯一确定结果，无新增人工语义决策；
- 分类：Parser 产品缺陷、跨包行为缺口和测试缺口；
- 方案：让 array-new 从合法的类型目标表达式统一构造完整 type reference，支持短名、alias、完整模块
  路径及其闭合泛型形式；保持局部值优先与现有名称歧义规则，不按模块名或类型名加特判；
- 是否涉及既有测试修改：默认否；G12 的真正非类型 target `factory()[:1]` 继续产生 `SE0201`；
- 是否涉及运行时性能、runtime、ABI 或 `.ft`：否，只修复 Parser AST 与后续已有类型解析路径。

### 验收与关闭

- array-new 已统一从完整类型引用构造元素类型，Parser、Semantic、Codegen 与真实 package-public
  FCTS 均覆盖导入短名、alias 和完整模块路径，以及对应闭合泛型形式；`factory()[:1]` 等非类型目标
  仍由 Parser 拒绝。专项与 G21 全量回归通过。

## ISSUE-G21-004：无目标的嵌套空数组字面量可能越过 Semantic

### 归属

- 发现组：G21 实施前审计；
- 关联组：G12 的数组字面量语法；
- 发现用例：ARRAY-D10。

### 现象与结论

- `validate_untyped_array_literal_expr` 当前只检查被直接用作绑定 / 参数等入口表达式的空字面量；
  `let value = [[]];` 的外层数组非空，内层 `[]` 又没有收到元素目标，因而可能通过 Semantic；
- Codegen 遇到没有元素类型的内层空数组后仍保留 `CE0182` 防御。该错误是用户源码可修复的目标类型
  缺失，按既定编译阶段边界必须由 Semantic 报 `AE0203`，不能泄漏为 Codegen `CE`；
- 有明确 `T[][]` 目标的 `[[], []]` 合法，修复不能把所有嵌套空数组一律拒绝，也不能改变既有数值
  字面量贴合算法。

### 决策与实施

- 状态：已关闭；既有空数组目标规则已唯一确定结果；
- 分类：Semantic 产品缺陷、阶段错误和测试缺口；
- 方案：递归传递并检查数组元素目标；只在实际没有目标的空字面量左方括号产生唯一 `AE0203`。
  合法输入不得到达 `CE0182`；如果本次触及相应 Codegen 防御，应改为 `IE` 内部不变量错误，不开展
  与新增用例无关的 CE 全面迁移；
- 是否涉及既有测试修改：默认否，新增直接和嵌套正反向矩阵；
- 是否涉及运行时性能、runtime、ABI 或 `.ft`：否，全部发生在编译期。

### 验收与关闭

- Semantic 已递归检查无目标字面量树；直接、嵌套和多层嵌套空字面量均在实际缺少目标的 `[` 产生
  唯一 `AE0203`，具有绑定、参数、返回或字段目标的嵌套空数组保持合法；
- 对应非法输入不再进入 Codegen，专项与 G21 全量回归通过。

## ISSUE-G21-005：用户手册把无目标 `Type[:length]` 误写为始终可写

### 归属

- 发现组：G21 实施前规范审计；
- 关联组：ARRAY-D13、ARRAY-D26；
- 发现用例：无，属于文档一致性问题。

### 现象与结论

- 中英文类型手册原文均称 `Type[:length]` “创建可写数组”；
- 内建类型与表达式主规范规定：array-new 自身不携带 `!`，无目标时推导为当前层只读的 `T[]`，只有
  明确 `T[!]` 目标才使该层可写；
- 结论：实现和主规范方向一致，用户手册描述错误；内建类型规范示例中无显式 `T[!]` 目标却写入
  `writable_nums` 的写法也必须一并纠正。

### 决策与实施

- 状态：已关闭；
- 分类：文档错误；
- 实际变更：中英文类型与表达式手册已明确无目标结果为 `T[]`、显式 `T[!]` 目标才可写，并补入长度
  值域与索引 panic 摘要；内建类型示例为可写字面量增加显式 `int[!]` 目标；
- 是否涉及既有测试修改、运行时性能、runtime、ABI 或 `.ft`：均否。

### 验收与关闭

- 中英文用户手册与主规范已经对齐；ARRAY-D13、ARRAY-D26 的 Semantic 与 FCTS 行为用例已证明无
  目标结果为只读 `T[]`，显式 `T[!]` 目标才赋予当前层写权限。专项与 G21 全量回归通过。

## ISSUE-G21-006：array-new 缺少元素默认零值资格检查

### 归属

- 发现组：G21 实施前完整性审计；
- 关联组：G18 的 `AE0332` 默认零值有限性；
- 发现用例：ARRAY-D27。

### 现象与结论

- `Type[:n]` 是按 `Type` 的默认零值创建元素的实例化入口。G18 已规定没有有限默认零值的普通对象在
  默认实例化点必须由 Semantic 报 `AE0332`；
- 当前 array-new Semantic 分支只解析元素类型和长度，不调用默认零值有限性检查。Codegen 对没有
  可用默认零值工厂的普通对象元素可能退回零指针槽，无法满足 Feng 普通对象的默认零值语义；
- 普通对象的直接构造，以及包含该对象类型无初始化器字段的父对象构造，已经在构造实例点执行同一
  有限性检查。array-new 没有本质不同：其语法本身表示按默认零值实例化元素，元素类型资格应作为
  静态类型条件统一检查，而不是由运行时长度决定；
- 结论：`RecursiveType[:0]`、`RecursiveType[:1]` 和 `RecursiveType[:dynamic]` 均必须在 Semantic
  拒绝。数组自身的空数组默认零值及由显式已有元素构成的数组字面量不实例化元素默认零值，继续合法。

### 人工决策

- 已确认采用统一静态资格规则：任何 `Type[:n]` 都要求 `Type` 具备有限默认零值，包括常量零长度、
  常量正长度和动态长度；
- 不采用常量零长度例外，也不依赖常量求值证明 `n == 0`；不增加按动态长度判断资格的运行时分支；
- 诊断沿用 G18 的 `AE0332` 并定位到 array-new 的元素类型引用。Semantic 通过后，Codegen 只能把同类
  缺失视为 `IE` 内部不变量破坏，不得生成 NULL 元素或报告用户可修复的 `CE`。

### 决策与实施

- 状态：已关闭；
- 是否涉及既有测试修改：默认否；新增常量 `0`、常量正数和动态长度的同包 / 跨包反向用例，以及
  有限元素默认值和不请求元素默认值的正向用例；
- 是否涉及运行时性能：否；资格检查只发生在 Semantic，不新增运行时检查、分支、元数据或调用；
- 是否涉及 runtime 私有 ABI 或公开 ABI：否；若跨包实现发现必须改变 `.ft` 格式或版本，仍须暂停并
  另行取得人工批准。

### 验收与关闭

- 同包直接自引用、互相引用及首成员递归 union-form 已按常量 `0`、常量正数和动态长度完整覆盖，均在
  元素类型引用产生唯一 `AE0332`；有限默认零值元素与不请求元素默认值的邻界均保持合法；
- 真实 package-public `.ft` 往返已覆盖短名、alias、完整路径的有限 / 递归类型，Codegen 绕过
  Semantic 的夹具产生唯一 `IE` 且不生成 NULL 元素。专项与 G21 全量回归通过。

## ISSUE-G21-007：宽整数索引在边界检查前直接窄化为 `size_t`

### 归属

- 发现组：G21 实施前完整性审计；
- 关联组：G14 的索引类型诊断；
- 发现用例：ARRAY-D28、ARRAY-D31～ARRAY-D32。

### 现象与结论

- `cg_emit_index` 当前把所有合法整数索引先转换为 `size_t`，再把转换结果传给一次运行时边界检查；
- 在当前 64 位目标上，有符号负数转换为大无符号值后仍会被 `index >= length` 拒绝，全部 Feng 整数
  位宽也不超过 `size_t`，因此既有目标上没有观察到错误；在较窄目标上，合法静态类型为 `i64` / `u64`
  的索引可能先截断成一个较小的 `size_t`，从而错误命中数组内位置；
- 语言允许所有整数类型作为索引，同时要求原索引位于 `[0, length)`。因此边界检查必须基于窄化前的
  数学值，不能把当前 64 位平台的偶然正确当作跨目标语义。

### 决策与实施

- 状态：已关闭；索引有效范围已由数组主规范确定，无新增语言决策；
- 分类：目标可移植性缺口和测试缺口；
- 方案：生成代码在保持接收者、索引各求值一次的前提下，以原整数的符号与宽度完成同一次边界判定，
  只有判定通过后才转换为元素地址所需的目标大小类型。不得为具体整数类型添加散落特判；
- 是否涉及既有测试修改：默认否；G14 的 `AE1021` / `AE1022` 诊断契约保持不变，新增 32 / 64 位
  Codegen 结构和可运行目标范围内的隔离进程用例；
- 是否涉及运行时性能：索引仍只能有既有的一次边界判断，不得增加第二个动态分支、辅助分配或 ARC；
  若无法在同一次判断中完成且会增加现有目标运行时开销，必须暂停并提交人工决策；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：默认均不涉及。若方案要求改变 runtime 私有
  helper 签名，必须先取得人工批准。

### 验收与关闭

- Codegen 已按索引原类型的符号与宽度形成既有单次边界判断，通过后才窄化为地址索引；接收者、索引
  及写入右值仍各求值一次；
- Semantic / FCTS 覆盖全部整数类型，隔离 CLI 覆盖负数、边界、越界、空数组和 `u64` 最大值；普通
  索引没有新增第二次判断，性能约束与 G21 全量回归通过。

## ISSUE-G21-008：array-new 的元素类型入口不能表示数组类型

### 归属

- 发现组：G21 实施期补齐 ARRAY-D23 FCTS 时；
- 关联组：G18 的数组默认零值与 ARRAY-D20 的 array-new 类型入口；
- 发现用例：ARRAY-D20-A、ARRAY-D23。

### 现象与结论

- 最小复现为 `let rows: int[][] = int[][:2];`。其中前一个 `[]` 属于元素类型 `int[]`，后一个
  `[:2]` 才是 array-new 后缀；
- 当前 Parser 的 array-new 入口只能把标识符 / 限定成员路径及其闭合泛型形式转换成 named type-ref。
  `int[]` 会先按普通索引表达式解析，并因索引缺失而产生 `SE0006`，因此 AST 无法表达“数组元素为
  数组”的指定长度创建；
- 数组主规范已规定数组自身具有有限的空数组默认零值，ARRAY-D23 也明确要求验证嵌套数组元素的默认
  零值。因此该写法应合法，并让每个元素初始化为相应内层数组类型的空数组；这不是新增语言语义。

### 决策与实施

- 状态：已关闭；既有规范已唯一确定结果，无新增人工语义决策；
- 分类：Parser / AST 产品缺陷和测试缺口；

## ISSUE-G21-013：共享泛型默认零值无法表达非零 trivial 默认值

### 归属

- 发现组：G21 实施期复核 ARRAY-D20、ARRAY-D23 的类型参数元素完整性时；
- 关联组：G18 的泛型默认零值与 G19 的 enum 首成员默认值；
- 发现用例：ARRAY-D20、ARRAY-D23、ARRAY-D23-A。

### 现象与结论

- 最小非数组复现为显式 enum `enum Status { Ready = 7, Done = 9 }` 与
  `func default_value<T>(): T { let value: T; return value; }`；真实运行
  `default_value<Status>()` 得到整数位模式 `0`，而语言规定的默认值是首成员
  `Status.Ready`（`7`）。同样，无初始化器的泛型字段也可复现该错误，证明根因早于数组语义；
- 对应的数组复现为 `func defaults<T>(n: int): T[] { return T[:n]; }`；
  `defaults<Status>(1)[0]` 同样错误地得到 `0`。`T[:n]` 本质上应对 `n` 个元素重复同一个
  `T` 默认零值操作，不应自行识别 enum、string、数组或对象；
- shared generic Codegen 当前按 `FengGenericParamDescriptor.kind` 分流：managed pointer 通过
  `FengTypeDescriptor.default_zero_init` 创建有效受管默认值，aggregate 通过
  `FengAggregateDescriptor.default_zero_init` 在零字节策略与自定义初始化函数之间选择，trivial 却只有
  尺寸与相等性元数据并固定执行 `memset(0)`；
- 动态 capture cell 把一个被捕获的 reified `T` 存入长度为 `1` 的 kinded 数组。无显式初始值时，
  现有路径也没有对 managed pointer 调用 `default_zero_init`，可能把 Feng 有效的空字符串 / 空数组等
  语言默认值错误地保留为 `NULL`。这与非零 trivial 一样，是泛型默认初始化入口未统一，不是
  capture 或数组特例；
- 结论：这是产品缺陷。把所有 enum 强制视为零默认、在泛型函数内枚举具体 enum 名，或只为该 FCTS
  改写写法都会违反既有语义或通用实现原则。

### 决策与实施

- 状态：已关闭；方案已获人工批准；
- 分类：泛型默认值元数据缺口、Codegen / runtime 产品缺陷和测试缺口；
- 批准方案：抽取通用的 `FengDefaultZeroInitDescriptor`，由 kind 区分零字节快路径和自定义初始化
  函数。`FengTrivialDescriptor` 与 `FengAggregateDescriptor` 都以名为 `default_zero_init` 的策略字段表达
  该能力；`FengTypeDescriptor.default_zero_init` 保持直接、可接收闭合类型描述符的回调，以创建有效受管
  默认值。三类字段表达同一语言语义，但保留各自的高性能表示；
- 命名收敛：既有 `FengAggregateDefaultInit*`、`FengAggregateDescriptor.default_init` 和
  `feng_aggregate_default_init` 分别收敛为通用策略命名、`default_zero_init` 字段和
  `feng_aggregate_default_zero_init`。这是 runtime 私有源码接口的机械收敛，不改变 aggregate 布局或运行行为；
- 入口收敛：shared generic 无初始值局部绑定、实例 / static 字段、捕获绑定和 `T[:n]`
  都必须复用 descriptor 提供的默认零值能力。消费端只按通用 value kind 和 descriptor 策略分流，
  禁止感知 std、enum 名、数组名或其他具体类型；
- 注释约束：每个 descriptor 的 `default_zero_init` 字段、通用策略类型、初始化回调和关键消费入口
  都要注释其语言默认零值契约、零字节快路径、所有权及禁止执行构造函数的边界；
- 是否涉及既有测试修改：否，新增显式非零 enum 在泛型局部绑定、字段、捕获、static 字段和
  `T[:n]` 的 Codegen / FCTS；同时以既有零默认 trivial、managed pointer 和 aggregate 作为邻界；
- 是否涉及运行时性能：具体类型路径不变；shared generic 的 trivial 默认值入口在既有 kind switch
  内增加一次策略判断，零默认类型仍直接 `memset` / `calloc`。`T[:n]` 每次创建只判断一次，只有
  自定义默认值才执行逐元素回调；普通数组读写、索引、遍历和 ARC 不增加分支或调用；
- 是否涉及 runtime、ABI 或 `.ft`：已人工批准扩展 runtime 私有 trivial descriptor 并收敛 aggregate
  默认初始化命名；不改变公开 ABI、Feng + C ABI 或 `.ft` 格式。

### 验收与关闭

- runtime 已增加共享 `FengDefaultZeroInitDescriptor`，trivial 与 aggregate descriptor 均以
  `default_zero_init` 策略区分零字节和自定义初始化；managed descriptor 保留接收闭合描述符并产出
  owned 值的直接回调。相关声明、回调和关键消费入口均已注释语言默认零值、所有权、快路径及“不执行
  构造函数”边界；
- shared-generic 局部、实例字段、static 字段、捕获和 `T[:n]` 已统一消费该能力；FCTS 以非零首成员

## ISSUE-G21-015：合法 `u64` 纯整数表达式在数组长度检查前被误判为 `i64` 溢出

### 归属

- 发现组：G21 实施期补齐 32 / 64 位常量长度矩阵时；
- 关联组：G04 的无符号整数运算与编译期常量求值；
- 发现用例：ARRAY-D22。

### 现象与结论

- 32 位目标下，`i32[:((u64)2147483647 + (u64)1)]` 可完成纯整数表达式求值，并按数组长度值域在
  `+` token 产生唯一 `AE0204`；
- 64 位目标下，对应的 `i32[:((u64)9223372036854775807 + (u64)1)]` 两个操作数和运算结果均在
  `u64` 值域内，但当前常量求值器先产生 `AE0100 integer overflow in compile-time '+' expression`，
  因而没有进入 ARRAY-D22 要求的数组长度 `AE0204`；
- 根因是 `FengConstValue` 用单个 `int64_t` 保存整数位模式，`evaluate_constant_binary` 又不依据表达式
  的已解析有符号性选择溢出规则，而是统一执行有符号 `i64` 的加减乘溢出检查；
- 结论：这是通用无符号常量求值缺口，不是数组长度语义例外。值 `2^63` 对 `u64` 合法，只是超过
  64 位目标 `int` 最大值，最终应由数组长度表达式产生唯一 `AE0204`。

### 决策与实施

- 状态：已关闭；既有无符号整数和 ARRAY-D22 规范已唯一确定结果，无新增语言决策；
- 分类：Semantic 产品缺陷、稳定诊断阶段缺口和测试缺口；
- 方案约束：常量整数运算须依据已解析的整数类型保留有符号性及完整位模式，不能只为数组长度或
  `2^63` 增加特判；修复后 32 / 64 位折叠超界样本均在整个长度表达式的 owning token 产生唯一
  `AE0204`，而真正超过相应无符号类型值域的常量运算仍使用既有算术溢出诊断；
- 实际实现：`FengConstValue` 增加编译期有符号性状态，整数 literal、显式 / 推导类型的不可变绑定、
  cast、位运算、移位、比较和算术统一保留该状态并按有符号 / 无符号值域执行运算；数组长度检查继续
  消费通用折叠结果，没有新增数组特判；
- 是否涉及既有测试修改：否，新增 32 / 64 位 ARRAY-D22 精确 Semantic 用例；
- 是否涉及运行时性能、runtime、ABI 或 `.ft`：均否，只修正编译期常量求值和诊断收口。

### 验收与关闭

- 32 / 64 位直接折叠以及经显式 `u64` 不可变绑定传播的超界样本，均已在 `+` token 产生唯一
  `AE0204`；Semantic 专项与 G21 全量回归通过。
