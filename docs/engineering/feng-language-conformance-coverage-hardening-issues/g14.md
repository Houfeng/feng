## ISSUE-G14-001：表达式规范把平台相关的 `int` 误写为固定 `i32`

### 归属

- 发现组：G14；
- 关联组：G18；
- 发现用例：EXPR01、EXPR06 与 EXPR07 实施前的数值类型规范核对。

### 现象与结论

- 最小复现：对照表达式规范的数值字面量规则与语言核心规范、内建类型规范中的 `int` 定义；
- 实际结果：表达式规范写为“整数字面量的默认类型为 `int`（即 `i32`）”，而语言核心规范和内建类型
  规范均定义 `int` 为平台相关别名：32 位平台映射为 `i32`，64 位平台映射为 `i64`；
- 规范依据与预期结果：`int` 的平台相关定义由语言核心规范与内建类型主规范确定，表达式规范不得把
  它收窄为固定 `i32`；需要跨平台固定结果的 G14 用例应直接使用 `i32`、`u32` 等固定宽度类型；
- 结论及根因：表达式规范中的括注与既有主定义不一致，属于规范文本缺陷，不代表实现语义变更。

### 决策与实施

- 状态：已关闭；
- 分类：规范歧义；
- 建议方案：仅把表达式规范中的括注改为平台相关映射，并在 G14 新增用例中使用固定宽度类型；
- 是否涉及既有测试修改：否；
- 是否涉及运行时性能：否；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 人工决策与批准范围：G14 实施前评估已向人工明确报告该不一致；人工批准开始实施 G14；
- 实际变更：`feng-expression.md` 已按主规范改为“`int` 在 32 位平台映射为 `i32`、在 64 位平台
  映射为 `i64`”；G14 新增数值边界均显式使用固定宽度类型。

### 验收与关闭

- 本组专项复验结果：Semantic、Parser、Codegen tests 通过；std 601/601、FCTS 1097/1097；
- 本组沙箱外 `make test` 结果：通过；UBSan 与 normal 两阶段均完成，FCTS 均为 1097/1097、
  smoke 均为 90/90、std 测试均为 601/601，性能约束及其余回归项全部通过；
- 关闭依据：表达式规范与 `int` 的既有主定义重新一致，固定宽度 G14 用例在专项和全量回归中通过。

## ISSUE-G14-002：核心表达式诊断仍使用未收敛到当前分段规范的旧错误码

### 归属

- 发现组：G14；
- 关联组：G18、G21；
- 发现用例：EXPR01、EXPR04 与 EXPR06 实施前的 Semantic 诊断映射审计。

### 现象与结论

- 最小复现：分别分析 `-true`、`1 + true`、`var n: i32 = 1; n += true;`、`1[0]` 与
  `let a: i32[] = [1]; a[false]`；
- 实际结果：Semantic 分别产生 `AE0234`～`AE0236`、`AE0030`、`AE0023`、`AE0052` 与
  `AE0053`；这些错误码未列入当前 `feng-error-codes-ae.md` 分段规范，其中 `AE0234`～`AE0236`
  还落在数组段编号范围，无法作为 G14 的稳定诊断契约；
- 规范依据与预期结果：表达式语法结构产生的运算、复合赋值与索引类型诊断应先在 AE 表达式段中
  收敛定义，再由实现和 Semantic tests 使用同一稳定错误码；
- 结论及根因：早期错误码结构化与后续分段迁移未覆盖这些表达式路径，属于诊断契约和实现未完成
  收敛，不改变语言接受或拒绝规则。

### 决策与实施

- 状态：已关闭；
- 分类：产品缺陷；
- 建议方案：在 AE 表达式段按根因分别定义一元操作数、二元操作数、复合赋值操作数、索引目标和
  索引操作数稳定码；直接替换上述 Semantic 产生点，并新增最小反向矩阵精确断言码、token、行列、
  数量与 Semantic 阶段；不开展其他分组错误码的全局迁移；
- 是否涉及既有测试修改：否，新增 G14 专项 Semantic 用例；
- 是否涉及运行时性能：否，仅修改编译期诊断码；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 人工决策与批准范围：实施前已向人工明确报告这些旧码；人工批准开始 G14，且此前已允许补充用例时
  一并修正明显重复或用错的错误码；
- 实际变更：在 AE 表达式段新增 `AE1018`～`AE1022`，分别承接一元操作数、二元操作数、复合赋值
  操作数、索引目标和索引操作数诊断；Semantic 对应产生点已切换到新码；新增 47 个最小反向程序，
  精确断言单个 Semantic 诊断的错误码、token、行列与消息片段。既有语言接受或拒绝行为、lowering、
  runtime 私有 ABI、公开 ABI 和 `.ft` 格式均未改变。

### 验收与关闭

- 本组专项复验结果：Semantic、Parser、Codegen tests 通过；std 601/601、FCTS 1097/1097；
- 本组沙箱外 `make test` 结果：通过；UBSan 与 normal 两阶段均完成，FCTS 均为 1097/1097、
  smoke 均为 90/90、std 测试均为 601/601，性能约束及其余回归项全部通过；
- 关闭依据：五类表达式诊断均已在主错误码规范、Semantic 产生点和精确反向测试之间建立一一对应，
  G14 范围内的旧码不再由编译器产生。
