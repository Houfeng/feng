## ISSUE-G17-001：主规范和用户手册仍描述可省略 `catch`

### 归属

- 发现组：G17；
- 关联组：G12；
- 发现用例：EXC01～EXC03 的实施前语法、规范与历史核对。

### 现象与分析

- 当前 Parser 在 `try` 后没有任何 `catch` 时产生 `SE1401`，G12 已有诊断码、token、行列、唯一
  诊断和空 AST 的直接证据；
- 实施前 `feng-exception.md` 和中英文用户手册仍写明 `catch` 可以省略并自动传播，和实际语法矛盾；
- Git 历史显示，后续提交 `2ac095fd` 的 commit message 为
  `feat(parser): forbid try without catch clause`，因此实际 Parser 行为代表较晚的语法决策；
- 未被当前函数捕获的异常本来就会沿普通调用链传播，不需要引入无 catch 的 `try` 作为传播标记。

### 决策与处理

- 状态：已关闭；
- 分类：文档问题；
- 人工确认：每个 `try` 必须至少包含一个 `catch`；
- 处理：删除“省略 catch”条款和示例，对齐主异常规范、中英文用户手册及 G17 TODO；Parser、AST、
  Semantic、Codegen 和现有测试均不改动；
- 是否涉及运行时性能：否；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否。

## ISSUE-G17-002：值形式 catch 错误地把 `return` 当作分支结果

### 归属

- 发现组：G17；
- 关联组：G15、G16；
- 发现用例：EXC12～EXC16 的实施前语义和当前实现核对。

### 现象与分析

- 当前 Semantic 的 `block_terminal_return_value()` 会把值形式 catch 的末尾 `return expr` 提取为结果，
  `validate_try_expr()` 和 `validate_try_catch_clause_result_presence()` 又明确把它作为合法结果；
- Codegen 随后按真正的 `return` 发码，因此以下程序进入 catch 时直接返回外围函数，而不是让 try
  表达式产生 `1`：

  ```feng
  func run(): int {
      let value = try fail() catch {
          return 1;
      };
      return value;
  }
  ```

- 现有 Semantic、Codegen、smoke 和 FCTS 中已有多处正向断言固定了该实现行为；
- 值形式 `if` / `match` 当前会因末句 `return` 不属于结果表达式而拒绝最简单形态，但若在 `return`
  后再写一个不可达结果表达式，仍可能通过结果提取。三种值表达式尚未真正共用“不得返回外围
  callable”的完整边界；
- `return` 是 callable 控制转移，不是块结果表达式。只移除 try 的末尾提取特例仍不能覆盖普通嵌套
  block、条件、循环或“return 后有不可达结果”的情况，也会留下三种值表达式不一致。

### 决策与实施要求

- 状态：待实施；
- 分类：Semantic 产品缺陷、既有用例语义迁移；
- 人工决策：值形式 `try` 与值形式 `if` / `match` 一致，结果分支禁止目标为外围 callable 的
  `return`；普通嵌套结构不改变目标，嵌套 Lambda 自己的 `return` 合法；语句形式的 `if`、`match`
  和 `try/catch` 均不形成该限制，其分支可返回当前 callable；
- 实施必须建立三种值表达式共用的编译期 callable-return 边界，不得只扫描 catch 末句，也不得给
  try 添加独立特判；边界只能在表达式 AST 上生效，不得改变三种语句 AST 的语义、诊断或发码；
- 值形式 catch 的非法 return 使用 `AE1405` 并定位实际 `return` token；if / match 使用共同的
  `AE1110` 分支控制转移段；catch 缺少正常结果的 `AE1401` 文案删除 `'return'`；
- 拟迁移的既有测试及每项必须保留的原测试重点已经列入实施文档 §21.3，目前仍待人工明确批准；
  批准后严格以该清单为限，发现清单外测试必须修改时，先记录并再次由人工决策；
- 是否涉及运行时性能：否；只增加编译期上下文检查，合法程序不得新增运行时判断、分支、调用、
  分配或 ARC；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否。

## ISSUE-G17-003：跨 ABI 异常效果分析延期

### 归属

- 发现组：G17；
- 关联领域：ABI、package-public `.ft`、异常传播分析；
- 发现位置：原 G17 的“异常声明 / 调用方传播要求”范围核对。

### 决策

- 状态：延期；
- Feng 普通 callable 没有 checked-exception 声明，普通调用方也没有必须满足的异常声明要求；
- 异常跨 `@abi` 边界的静态效果分析以及相关事实是否需要跨 package-public `.ft` 保留，需要另行设计
  和人工决策；
- 本次 G17 不修改 `AE1313`、异常效果分析、`.ft` 格式、公开 ABI 或 runtime 私有 ABI，也不以既有
  ABI 用例推导该领域已经完整覆盖；
- G17 只覆盖普通 Feng 调用链的传播、捕获和重抛。若全量回归暴露 ABI 相关失败，先记录，不在本组
  顺带修复。
