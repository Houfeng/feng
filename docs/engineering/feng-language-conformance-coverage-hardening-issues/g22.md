## ISSUE-G22-001：别名与非本文件声明的名称冲突仍被急切拒绝

- 状态：语义已确认，待实施。
- 规范依据：模块规范 §4。
- 当前证据：`src/semantic/analyzer.c` 的 `validate_program_alias_conflicts` 在检查 import 声明时对无别名 import 引入的同名名称、同模块其他文件同名声明直接报告 `AE0906`，不依赖实际引用。
- 分析：需要将这些来源的冲突检查移至名称使用点；本文件声明与别名之间的急切检查继续保留。需统一名称解析入口，不能依赖后续成员是否存在来选择候选。
- 人工决策：别名与无别名 import 引入名称在使用点报冲突；同模块其他文件同名声明按本轮确认的惰性冲突方向处理。
- 既有用例迁移范围（实施时仅调整与已确认规则直接相关的断言）：`test/semantic/test_semantic.c` 中 `test_import_alias_conflicts_with_imported_short_name`、`test_import_alias_conflicts_with_other_file_local_value`，将声明点急切诊断调整为使用点二义性诊断。其他既有用例如需变更，须再次人工决策。
- 待补验证：未引用通过、引用时报错、冲突来源、限定成员访问、import 与文件顺序、使用不冲突别名和完整路径消歧；正向行为在 fcts 覆盖。
- 验证结果：尚未实施，尚未运行测试。
