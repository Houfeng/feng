## ISSUE-G22-001：别名与非本文件声明的名称冲突仍被急切拒绝

- 状态：待修复；两类语义已人工确认，G22 实施清单待 Review。
- 分类：产品缺陷。

### 归属

- 发现组：G22。
- 关联组：G02 的名称访问形式与文件隔离、G13 的同模块声明检查。
- 发现用例：现有 `test_import_alias_conflicts_with_other_file_local_value`、
  `test_import_alias_conflicts_with_imported_short_name`；计划覆盖 MODULE08～MODULE11、MODULE27。

### 现象与结论

当前 `src/semantic/analyzer.c` 的 `validate_program_alias_conflicts` 在 import 声明检查阶段
查找同名可见类型和值；遇到兄弟文件声明或普通 import 引入的名称，直接报告 `AE0906`，不依赖
实际引用。调用点位于 `resolve_program_names` 之前。

第一类：同模块其他文件声明与 alias 同名。

```feng
// provider.ff
open module lib.tools;
open func run(): i32 { return 1; }

// a.ff
module app;
import lib.tools as helper;
func call(): i32 { return helper.run(); }

// b.ff
module app;
let helper = 2;
```

第二类：普通 import 引入名称与 alias 同名。

```feng
// values.ff
open module lib.values;
open let helper = 2;

// consumer.ff（同时使用上例 provider.ff）
module consumer;
import lib.values;
import lib.tools as helper;
func call(): i32 { return helper.run(); }
```

- 实际结果：现有实现都在 alias import 声明处报 `AE0906`；删除 `call` 中的引用仍会报错。
  现象由源码检查和既有断言确认，本次文档更新未另行执行复现。
- 规范依据与预期：[模块规范 §4](../../specifications/feng-module.md#4-模块导入规则)。存在碰撞但
  未引用时通过；引用时在 `helper` token 处报告二义性并指出来源，不依据 `.run` 是否存在选边。
- 根因：前置检查未区分“本文件声明产生的急切冲突”和“两类外来声明参与的惰性冲突”；只删除
  前置分支还不够，类型、表达式及赋值目标的使用点必须接入相同的来源判定。

### 决策与实施

- 人工决策：两类冲突均改为使用点惰性报错；本文件顶层声明或其他 alias 与 alias 同名仍急切
  报错。同模块真正的顶层非法重名仍急切检查，合法函数重载除外。
- 边界：“局部值优先于模块路径”按已有定义保持，不扩展成所有具体符号优先；普通 import 与
  本文件或同模块其他文件顶层声明之间的惰性冲突保持现状，不新增顶层本地优先规则。
- 建议方案：统一收集当前使用位置可见的名称来源，在使用点区分明确目标与二义性；覆盖类型位、
  函数值、构造、读写和普通调用，不按模块名、类型名或后续成员存在性添加特判。具体结构在实施时
  依据现有通用解析代码确定。
- 既有测试修改：仅上述两条的声明点 `AE0906` 调整为使用点 `AE0005`，以及必要的来源、token、
  行列与数量断言；完整迁移清单在所属实施文档 §26.3.2。清单外如需修改须再次人工决策。
- 运行时性能：方案只调整编译期查找，不增加运行时名称解析、权限检查或 ARC 操作。
- runtime 私有 ABI、公开 ABI 或 `.ft` 格式：无预期变更；跨包只使用现有公开导出与导入机制。
- 当前交付范围：本次仅更新规范、TODO 和问题记录；实施与测试迁移在 G22 Review 后进行。

### 验收与关闭

- 待补验证：六类声明的未使用／使用配对、各限定访问入口、成员存在性不能消歧、顺序无关、
  文件隔离、显式消歧、真实 `.ft` 往返，以及本文件急切检查不回归。
- 本组专项复验结果：尚未执行。
- 本组沙箱外 `make test` 结果：尚未执行。
- 关闭依据：待实现修复及本组专项、全量回归通过后填写。

## ISSUE-G22-002：AE0906 文档废弃标记与现有别名急切诊断不符

- 状态：待修复。
- 分类：规范歧义（错误码文档与实际出口不一致；名称冲突语义已确认）。

### 归属

- 发现组：G22。
- 发现用例：`test_import_alias_conflicts_with_same_file_local_value` 及本轮诊断映射检查。

### 现象与结论

- [AE 错误码规范](../../specifications/feng-error-codes-ae.md) 将 `AE0906` 描述为已废弃、由
  `AE0005` 在使用处惰性覆盖，但 `validate_program_alias_conflicts` 仍用它报告本文件 alias
  与顶层声明冲突；既有测试明确断言该码。本轮决定保留这类急切检查，因此不能按文档废弃全部出口。
- 当前只发现文档说明不准确，不据此认定编译器错误码本身需要迁移。

### 决策与实施

- 处理范围：在 G22 对齐该文档条目的现用含义和历史用途，保留本文件 alias／顶层声明冲突的
  `AE0906` 及重复 alias 的 `AE0902`；两类新增惰性冲突归入 `AE0005` 的使用点诊断说明。
- 既有测试修改：本问题不需要；不得借纠正文档改动急切冲突既有断言。
- 运行时性能、runtime 私有 ABI、公开 ABI、`.ft` 格式：无影响。
- 实际变更：本次已记录问题并列入 §26.3.1，错误码主文档尚未修改。

### 验收与关闭

- 核对错误码文档、现用出口和用例映射一致；随 G22 专项及全量验收，不开展额外的错误码重构。
- 本组专项及全量结果：尚未执行。
- 关闭依据：待文档对齐及本组验收完成后填写。
