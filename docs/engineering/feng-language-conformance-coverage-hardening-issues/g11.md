## ISSUE-G11-001：整数源码字面量溢出误用字符串未终止错误码

### 归属

- 发现组：G11；
- 关联组：无；
- 发现用例：稳定 `LE` 码到现有 Lexer 错误路径的实施前映射。

### 现象与结论

- 最小复现：对十进制源码片段 `18446744073709551616` 直接执行 Lexer；该值比 `u64` 最大值大
  `1`；
- 实际结果：Lexer 产生 `FENG_TOKEN_ERROR`，错误码为 `LE0003`，文案为
  `integer literal overflows u64`；
- 规范依据与预期结果：[LE 词法错误主规范](../../specifications/feng-error-codes-le.md) 将无效数字
  字面量归入 `LE0002`，将 `LE0003` 专用于未终止的双引号或反引号字符串；因此该输入应产生
  `LE0002`；
- 结论及根因：这是明确的产品缺陷。整数解析新增溢出检查时复用了错误的错误码，错误文案和溢出
  检查本身不需要改变。

### 决策与实施

- 状态：已关闭；
- 分类：产品缺陷；
- 建议方案：把整数源码字面量超过 Lexer 可表示范围的错误码改为 `LE0002`，并新增最大 `u64`
  合法邻界与最大值加一的回归用例；
- 是否涉及既有测试修改：否；新增 G11 独立用例，不修改已有测试用例；
- 是否涉及运行时性能：否；只更正编译期错误路径上的静态错误码，不改变合法程序的 Lexer 路径或
  生成程序；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 人工决策与批准范围：已确认明显错误码重复或误用可在补充用例时一并修正；禁止合入与增补用例
  无关的单纯重构；
- 实际变更：将 `src/lexer/lexer.c` 的整数源码字面量溢出错误码由 `LE0003` 更正为 `LE0002`；新增
  最大 `u64` 合法邻界与最大值加一的精确 Lexer 回归用例。

### 验收与关闭

- 本组专项复验结果：`make build/bin/test_lexer && build/bin/test_lexer` 通过；
- 本组沙箱外 `make test` 结果：通过；UBSan 与 normal 两个阶段均完成；
- 关闭依据：新增用例精确证明溢出值产生 `LE0002`、最大 `u64` 仍产生合法整数 token，专项和独立
  全量回归均通过。

## ISSUE-G11-002：normal 全量回归中的 `feng init` 子进程被 SIGKILL

### 归属

- 发现组：G11；
- 关联组：无；
- 发现用例：首次沙箱外 `make test` 的 normal 阶段
  `init-bundled-packages-test`。

### 现象与结论

- 最小复现：首次沙箱外全量回归运行到 `scripts/run_cli_init_bundled_packages.sh`；
- 实际结果：多个 `feng init demo` 子进程先后显示 `Killed: 9`，随后因对应项目的 `feng.fm`
  未生成而出现 `grep: ... No such file or directory`；
- 规范依据与预期结果：该测试应完成各项目初始化并由脚本验收生成的清单文件；
- 结论及根因：首次全量最终因该目标退出 `1` 而失败。失败时系统内存空闲比例约 `79%`、没有
  swap I/O，系统日志明确记录对应 `feng` 进程不受 RunningBoard jetsam 管理，未发现内存不足
  证据；同一 normal 构建产物随后独立执行 `make init-bundled-packages-test` 通过。`feng init` 只
  使用 token 关键字查询，不执行本次唯一产品变更所在的整数扫描错误路径。当前证据指向外部瞬时
  `SIGKILL`，未复现产品或测试逻辑缺陷。

### 决策与实施

- 状态：已关闭；
- 分类：测试基础设施；
- 建议方案：不修改产品或测试；保留首次失败记录，使用同一 normal 产物独立复验失败目标，再完整
  重跑沙箱外 `make test`；只有再次稳定复现时才重新打开根因分析；
- 是否涉及既有测试修改：否；
- 是否涉及运行时性能：否；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 人工决策与批准范围：若属于不确定语义、运行时性能、ABI 或格式问题，暂停并交人工决策；
- 实际变更：无；未因外部 `SIGKILL` 修改产品、测试或构建脚本。

### 验收与关闭

- 本组专项复验结果：G11 Lexer 专项通过；代码路径核对确认 `feng init` 不执行本次变更所在的整数
  扫描错误路径；
- 本组沙箱外 `make test` 结果：首次执行在 normal 阶段受该瞬时信号中断；同一 normal 产物独立执行
  `make init-bundled-packages-test` 通过，随后完整复跑 `make test` 时 UBSan 与 normal 阶段的该目标
  均通过，整套回归退出码为 `0`；
- 关闭依据：问题未能复现，独立目标和完整复跑均通过；现有证据排除 G11 产品变更的稳定因果关系，
  因而按测试环境瞬时中断关闭，不修改产品、测试或构建脚本。如后续再次出现同类 `SIGKILL`，应以
  新问题记录当时的系统事件和发送方证据。
