## ISSUE-G10-001：直接字面量解构的空位表达式求值规则未明确

### 归属

- 发现组：G10；
- 关联组：无；
- 发现用例：TUP08～TUP11 实施前规范审计。

### 现象与结论

- 已确认规则：Feng 只有具名 tuple 类型；tuple 字面量既可贴合具名 tuple 目标，也可在解构绑定中
  直接按位置展开，后一种形式不产生用户可用的匿名 tuple 类型或绑定；
- 已确认规则：具名 tuple 工厂表达式作为解构右侧时，工厂必须执行一次，再从同一个返回值建立各
  非空位置的绑定；空位不会使工厂不执行或重复执行；
- 原未明确边界：对于 `let (x, , z) = (left(), middle(), right());`，tuple 主规范原先只规定空位
  不产生绑定，没有明确空位对应的 `middle()` 是否求值；
- 当前实现：直接字面量解构按位置发码，在空位处先跳过再求值元素，因此执行 `left()`、`right()`，
  不执行 `middle()`，也不物化完整 tuple；
- 人工决策：保持当前实现。直接字面量解构只求值非空位置，空位表达式不求值；字面量贴合具名 tuple
  目标时则构造完整值，全部元素表达式从左到右各求值一次；
- 当前结论：主规范与 G10 TODO 已按上述边界收敛，不需要修改产品实现，不增加运行时开销；G10
  专项与全量回归均已通过，本问题已关闭。

### 决策与实施

- 状态：已关闭；
- 分类：规范歧义（已决策）、性能风险（已排除）；
- 处理方案：采用原方案一，保持当前位置展开模型；空位对应的直接字面量表达式不求值。原方案二
  “全部元素均求值、空位只丢弃结果”不采用；
- 是否涉及既有测试修改：否；G10 只新增直接行为与 Codegen 结构用例；
- 是否涉及运行时性能：否；保持当前生成路径，不增加表达式求值、完整 tuple 物化、运行时判断、
  分支或分配；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 人工决策与批准范围：已确认保持当前实现，并按该行为更新主规范和补齐 G10 用例；未批准产品实现、
  runtime、ABI、`.ft` 格式或新增运行时开销；
- 实际变更：tuple 主规范已明确具名 tuple 表达式只求值一次、直接字面量按位置求值、空位不求值、
  具名目标贴合求值全部元素以及 `var` 解构绑定独立性；G10 已拆分 TUP01～TUP11 完整覆盖矩阵。

### 验收与关闭

- [x] 主规范明确两类字面量路径及空位求值边界；
- [x] G10 TODO 覆盖具名工厂、单/多/全空位、零 tuple、直接字面量、具名贴合、`var` 独立性和
  Codegen 零附加运行时结构；
- [x] 本组专项复验结果：TUP01～TUP10 FCTS 1072/1072 通过，TUP11 Codegen 专项通过；
- [x] 本组沙箱外 `make test` 结果：UBSan 与 normal 两个阶段全部通过；
- 关闭依据：主规范已收敛，TUP01～TUP11、G10 专项及独立全量回归全部通过，本问题关闭。

## ISSUE-G10-002：TUP11 临时量断言误匹配模块名

### 归属

- 发现组：G10；
- 关联组：无；
- 发现用例：TUP11 首次 Codegen 专项执行。

### 现象

- `build/bin/test_codegen` 在“直接字面量解构不生成 tuple 临时量”的断言处失败；
- 失败断言搜索通用子串 `_tuple`，而生成函数体内被调用函数的完整符号包含模块名
  `tuple_destructure_evaluation`，即使没有 tuple 临时量也会命中；
- TUP01～TUP10 已通过，当前未发现语言行为或产品实现错误。

### 分析与处理

- 状态：已关闭；
- 分类：新增测试断言错误；
- 根因：`_tuple` 不是临时量的完整标识，模块限定符中的 `tuple_destructure_evaluation` 同样包含该
  子串，断言无法区分符号限定名与局部临时量；
- 处理：改用 tuple C 类型片段与 `memset(&` 完整值初始化共同判断是否物化；另按 `int32_t _l_`
  局部声明数量证明只生成两个非空位置绑定、全空位不生成绑定；
- 复验：修正后的 `build/bin/test_codegen` 通过；调用次数、空位调用消除、无完整 tuple 物化、无新增
  判断、分支和分配均已由 TUP11 直接验证；
- 是否涉及既有测试修改：否；仅修正本次新增的 TUP11；
- 是否涉及产品实现、运行时性能、runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否。

### 验收与关闭

- [x] 修正后的 TUP11 Codegen 专项通过；
- [x] G10 沙箱外 `make test` 的 UBSan 与 normal 两个阶段全部通过；
- 关闭结论：问题仅存在于本次新增测试的初版断言，未发现产品缺陷；断言修正后专项与全量回归均
  通过，本问题关闭。
