## ISSUE-G19-001：enum 固定 `i32` 表示缺少 Semantic 成员值范围检查

### 归属

- 发现组：G19；
- 关联用例：ENUM-D06、ENUM-D11～ENUM-D13；
- 发现阶段：G19 实施前规范与实现审计。

### 现象与结论

- Codegen 当前把每个 enum 固定发码为 `typedef int32_t`，`.ft` 的 enum item 值也固定按 `int32_t`
  二补码位模式保存；该实现不随平台 `int` 的宽度变化；
- Parser 将合法形式的整数字面量保存在 `int64_t` 中，Semantic 当前只检查显隐式混用、名称重复与
  数值重复，没有检查该值能否由 `i32` 表示；
- Lexer 实际先按 `uint64_t` 累积整数字面量，再把位模式复制到 token 的 `int64_t` 字段；因此幅值大于
  `INT64_MAX`、但没有超过 Lexer `u64` 上限的正数字面量会在现有 AST 中表现为负数。enum Parser 对
  带 `-` 的字面量还会直接执行有符号取负，遇到对应位模式时可能产生编译器自身的有符号溢出；
- 因此，超出 `i32` 范围的显式成员值可通过 Semantic：本包 Codegen 会以 `int32_t` cast 截断，公开
  enum 则可能延迟到 `.ft` 导出时才因超出 `int32` 范围失败；更大的 `u64` 幅值还可能被错误解释为
  合法负值，两条路径不一致；
- 人工已确认 enum 底层存储与 ABI 固定为 `i32`，不跟随平台 `int`；显式成员值合法范围相应固定为
  `-2147483648...2147483647`。

### 决策与实施

- 状态：已解决；
- 分类：Semantic 类型合法性缺口、诊断契约缺口和测试缺口；
- 人工决策：已确认 `AE0405` 定位到非法初始化值位置；正数定位整数 token，负数定位作为初始化值
  起点的一元 `-`，不定位到 enum item 名称；
- 批准方案：Parser / AST 必须为 enum 初始化字面量保留足以表达原始符号、`uint64_t` 幅值和完整源码
  范围的事实，不得在值域检查前执行可能溢出的有符号取负；Semantic 在 enum 信息归一化阶段依据这些
  原始事实检查每个成员值是否可由 `i32` 表示。合法后才生成现有 `int64_t` 归一化值；
- 诊断契约：越界时在初始化值的起始 token 产生唯一 enum 段稳定诊断 `AE0405`；正数字面量指向整数
  token，负数字面量指向一元 `-`，错误消息保留包含符号的原始字面量文本。不得静默截断，不得把
  大幅值重解释为负值，也不得把用户错误延迟到 Codegen 或 `.ft` 导出；
- 检查顺序：`AE0405` 值域检查先于底层 `i32` 归一化和 `AE0403` 重复值检查，避免非法值经截断或
  回绕后产生错误的重复值诊断；超过 Lexer `u64` 上限的字面量仍由 `LE0002` 负责；
- 合法邻界：`INT32_MIN`、`INT32_MAX` 及其跨包 `.ft` 往返必须保持原值；
- 是否涉及既有测试修改：该问题本身不修改既有测试，新增 G19 精确用例；
- 是否涉及运行时性能：否，范围检查只发生在编译期；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：不改变 runtime 私有 ABI、公开 ABI 或 `.ft`
  格式；只是使 Semantic 与当前固定 `i32` 表示及既有 `.ft` 范围保持一致；
- 实际变更：Parser / AST 为源 enum 显式值保存原始正负号、`uint64_t` 幅值、起始 token 和完整源码
  范围；解析阶段不再对无法表示的幅值执行有符号取负。Semantic 在 enum 信息归一化阶段先按原始
  事实验证固定 `i32` 值域，越界时在正数整数 token 或负数一元 `-` 产生唯一 `AE0405`，消息保留
  原始字面量；合法值再归一化并进入重复值检查。导入 enum 继续读取 `.ft` 已验证的 `int32_t` 值，
  未修改 `.ft` 格式。

### 验收与关闭

- 本组专项复验结果：Parser、Semantic、Symbol、Codegen、CLI 专项均通过；覆盖 `i32` 正负邻界、
  Lexer 可承载的全部更大幅值类别、精确 token / 行列 / 源码文本、真实 `.ft` 往返和固定 `int32_t`
  发码；新增 FCTS 行为用例通过；
- 本组沙箱外 `make test` 结果：2026-09-06 执行，退出码为 `0`；UBSan 与 normal 两阶段及性能约束
  全部通过；
- 关闭依据：非法显式值统一在 Semantic 阶段以 `AE0405` 拒绝，不再静默截断、错误改号、触发编译器
  有符号溢出或延迟到 Codegen / `.ft` 导出；合法 `INT32_MIN` / `INT32_MAX` 本包及跨包保持原值。

## ISSUE-G19-002：enum 显式转换规范窄于现有通用整数转换实现

### 归属

- 发现组：G19；
- 关联用例：ENUM-D09、ENUM-D13；
- 发现阶段：G19 实施前规范与实现审计。

### 现象与结论

- enum 主规范原来只写明允许 `enum -> int`；
- Semantic 的实际通用规则允许 enum 显式转换到任意有符号或无符号整数类型，Codegen 使用既有标量
  转换发码；整数到 enum 以及 enum 与整数之间的隐式转换仍被拒绝；
- 人工已确认保留实际通用行为：允许 enum 显式转换到任意整数类型，结果遵循目标整数类型的既有转换
  规则；不允许任何整数类型显式转换到 enum。

### 决策与实施

- 状态：已解决；
- 分类：规范描述缺口和测试缺口；
- 实施方案：已对齐 enum 主规范、用户手册、既有 enum 工程记录和 G19 ENUM-D09；G19 实施时新增
  `i8`、`i16`、`i32`、`i64`、`u8`、`u16`、`u32`、`u64`、`int`、`uint`、`byte` 全部整数目标的
  合法运行覆盖，以及整数到 enum、跨 enum 和 enum 到非整数内建类型转换的 `AE1023` 精确反向覆盖；
- 是否涉及运行时性能：文档变更不涉及；现有转换继续使用既有标量 lowering，不新增运行时分支、调用、
  分配或 ARC；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 实际变更：相关文档已统一为“enum 可显式转换到任意整数类型”；新增 Semantic 32 / 64 位平台别名
  矩阵、Codegen 结构断言和 FCTS 运行用例，覆盖全部整数目标、同 enum 无操作转换，以及所有整数到
  enum、跨 enum 和 enum 到非整数内建类型的反向边界。

### 验收与关闭

- 文档专项：`git diff --check` 通过；
- G19 测试覆盖结果：Semantic、Codegen 与 FCTS 专项均通过；完整 FCTS 为 `1146/1146`；
- 关闭依据：规范、现有通用标量 lowering 和正反向用例已经对齐；合法转换未新增运行时 helper、分支、
  调用、分配或 ARC。

## ISSUE-G19-003：`extern enum` 的 `SE0401` 专用出口被通用诊断提前拦截

### 归属

- 发现组：G19；
- 关联用例：ENUM-D02；
- 发现阶段：G19 Parser 精确诊断补齐。

### 现象与结论

- `parse_enum_declaration` 已包含 `SE0401`，但顶层声明分派在看到 `extern` 后只允许继续进入 `func`，
  其余 token 均立即产生通用 `SE0003`，因此 `extern enum` 永远无法到达 enum 专用出口；
- 既有 `test_extern_rejects_non_function_top_level_declarations` 把 `extern enum` 与其他非函数声明统一断言为
  通用消息。按 G19 已批准的 enum 专属诊断契约恢复 `SE0401` 后，该条旧断言必须同步迁移，否则会与
  主规范和新增精确用例冲突；
- 合法语法、Semantic、Codegen、ABI、`.ft` 与运行时行为均不受影响。

### 决策与实施

- 状态：已解决；
- 分类：Parser 诊断路由缺口和既有测试迁移；
- 人工决策：已批准仅迁移该条既有断言；
- 批准方案：顶层分派在现有 `enum` token 直接产生 `SE0401`，保持 Parser 阶段、非法性与源码位置不变；
  只把既有通用负向矩阵中的这一条 enum 输入迁移到 G19 的精确 `SE0401` 断言，其余既有用例不变；
- 是否涉及运行时性能：否；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 实际变更：顶层 `extern` 分派在看到 `enum` 时直接产生 `SE0401`；仅从既有通用负向矩阵移除该条输入，
  并在 G19 Parser 精确矩阵中断言稳定码、`enum` token、行列、消息、来源文件和唯一诊断。其余既有
  用例未修改。

### 验收与关闭

- 本组专项复验结果：Parser 专项通过，`extern enum` 稳定产生唯一 `SE0401`；
- 本组沙箱外 `make test` 结果：2026-09-06 执行，退出码为 `0`；UBSan 与 normal 两阶段全部通过；
- 关闭依据：专用错误码已经可达，既有断言只按人工批准范围迁移；合法语法、Semantic、Codegen、ABI、
  `.ft` 与运行时行为均未改变。
