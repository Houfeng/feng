## ISSUE-G19-001：enum 固定 `i32` 表示缺少 Semantic 成员值范围检查

### 归属

- 发现组：G19；
- 关联用例：ENUM-D02；
- 发现阶段：G19 实施前规范与实现审计。

### 现象与结论

- Codegen 当前把每个 enum 固定发码为 `typedef int32_t`，`.ft` 的 enum item 值也固定按 `int32_t`
  二补码位模式保存；该实现不随平台 `int` 的宽度变化；
- Parser 将合法形式的整数字面量保存在 `int64_t` 中，Semantic 当前只检查显隐式混用、名称重复与
  数值重复，没有检查该值能否由 `i32` 表示；
- 因此，超出 `i32` 范围的显式成员值可通过 Semantic：本包 Codegen 会以 `int32_t` cast 截断，公开
  enum 则可能延迟到 `.ft` 导出时才因超出 `int32` 范围失败；两条路径不一致；
- 人工已确认 enum 底层存储与 ABI 固定为 `i32`，不跟随平台 `int`；显式成员值合法范围相应固定为
  `-2147483648...2147483647`。

### 决策与实施

- 状态：已批准，待 G19 实施；
- 分类：Semantic 类型合法性缺口、诊断契约缺口和测试缺口；
- 批准方案：在 enum 信息归一化阶段检查每个显式成员值是否可由 `i32` 表示；越界时在该成员名称
  token 产生唯一 enum 段稳定诊断 `AE0405`。不得静默截断，也不得把用户错误延迟到 Codegen 或
  `.ft` 导出；
- 合法邻界：`INT32_MIN`、`INT32_MAX` 及其跨包 `.ft` 往返必须保持原值；
- 是否涉及既有测试修改：当前审计未发现需要修改既有测试，优先新增 G19 精确用例；若实施时必须
  修改既有用例，需再次取得人工决策；
- 是否涉及运行时性能：否，范围检查只发生在编译期；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：不改变 runtime 私有 ABI、公开 ABI 或 `.ft`
  格式；只是使 Semantic 与当前固定 `i32` 表示及既有 `.ft` 范围保持一致；
- 实际变更：enum、ABI、用户手册和 G19 计划已先行统一为固定 `i32`；产品实现与测试待 G19 实施。

### 验收与关闭

- 本组专项复验结果：—；
- 本组沙箱外 `make test` 结果：—；
- 关闭依据：—。

## ISSUE-G19-002：enum 显式转换规范窄于现有通用整数转换实现

### 归属

- 发现组：G19；
- 关联用例：ENUM-D04；
- 发现阶段：G19 实施前规范与实现审计。

### 现象与结论

- enum 主规范原来只写明允许 `enum -> int`；
- Semantic 的实际通用规则允许 enum 显式转换到任意有符号或无符号整数类型，Codegen 使用既有标量
  转换发码；整数到 enum 以及 enum 与整数之间的隐式转换仍被拒绝；
- 人工已确认保留实际通用行为：允许 enum 显式转换到任意整数类型，结果遵循目标整数类型的既有转换
  规则；不允许任何整数类型显式转换到 enum。

### 决策与实施

- 状态：文档问题已解决，测试覆盖待 G19 实施；
- 分类：规范描述缺口和测试缺口；
- 实施方案：已对齐 enum 主规范、用户手册、既有 enum 工程记录和 G19 ENUM-D04；G19 实施时新增
  全部整数目标的合法运行覆盖，以及整数到 enum、跨 enum 转换的 `AE1023` 精确反向覆盖；
- 是否涉及运行时性能：文档变更不涉及；现有转换继续使用既有标量 lowering，不新增运行时分支、调用、
  分配或 ARC；
- 是否涉及 runtime 私有 ABI、公开 ABI 或 `.ft` 格式：否；
- 实际变更：相关文档已统一为“enum 可显式转换到任意整数类型”。

### 验收与关闭

- 文档专项：`git diff --check` 通过；
- G19 测试覆盖结果：—；
- 关闭依据：规范与现有实现已对齐；G19 仍需完成对应正反向测试后关闭测试缺口。
