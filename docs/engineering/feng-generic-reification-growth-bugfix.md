# 泛型具化依赖无限增长 bugfix 记录

日期：2026-10-08。状态：待后续单独设计和修复。

按用户要求，本问题从[注解参数依赖优化](./feng-annotation-dependency-optimize-dev.md)
中移出，作为独立 bugfix 跟踪。本文记录已确认的问题，不预先确定新的源码拒绝规则、
诊断码或描述符生成策略。

## 1. 问题与复现

普通泛型字段可以触发 Codegen 不断注册新的泛型实例：

```feng
open module generic.growth;

open type Grow<T> {
    let children: Grow<Grow<T>>[];
}

open func create(): Grow<int> {
    return Grow<int>();
}
```

数组字段避免了直接递归默认初始化的干扰；问题发生在编译期类型实例注册，不需要
运行程序或创建数组元素。具化过程形成：

```text
Grow<int>
→ Grow<Grow<int>>
→ Grow<Grow<Grow<int>>>
→ …
```

注解参数接入公共依赖后，同一问题也可以由以下类型声明触发：

```feng
open type Grow<T> {
    @friend(Grow<Grow<T>>)
    seal let value: int = 0;
}
```

该例沿用前例的模块声明及 `create`。注解依赖的收集规则引用
[泛型规范 §6.1](../specifications/feng-generics-draft.md#61-开放检查条件)，本 bugfix
不另设注解依赖类别。

## 2. 验证与影响范围

2026-10-08 的对照记录：

| 用例 | 已观察结果 |
| --- | --- |
| 普通数组字段 `Grow<Grow<T>>[]` | 优化前后均在限定时间内未完成 C 生成 |
| 注解 `@friend(Grow<Grow<T>>)` | 优化前能生成 C；统一收集后进入同一增长路径 |
| 注解 `@friend(Grow<T>)` | 优化前后均能生成 C，相同实例递归可以去重 |

此前注解增长用例的 Semantic 检查能够结束，但 C 生成在 5 秒限制内未结束。
当前再次使用 `build/bin/feng tool compile --target=lib --emit-c=<输出路径> <源文件>`
复核，字段和注解增长用例均超过 3 秒，由测试驱动终止子进程；同实参递归完成。
超时是观察结果，无限增长的判断同时依据下述参数替换和注册过程。

优化前对照指实施时保留的对照编译器，不指之后已经更新的 Git index。
结论是公共 Codegen 原有缺陷，本次统一收集扩大了其触发范围；不能把新注解场景的
编译回退遗漏为“与本次无关”。本轮按用户决定仅记录，尚未修复。

## 3. 已确认原因

[codegen.c](../../src/codegen/codegen.c) 中：

- `cg_register_generic_type_instance_shell` 按声明及完整实参查找已注册实例，先登记
  shell，再沿成员和普通具化依赖继续注册。
- `cg_collect_closed_reifiable_dep_instances_inner` 代入当前实参并遍历闭合依赖。
- `cg_reifiable_pre_registration_is_active` 按依赖域和完整实参识别活动路径中的
  相同调用，能够终止相同实例的循环。

增长链每次都产生新的完整实参，现有去重条件不会命中。在当前完整静态依赖闭包的
生成方式下，该链无法由有限个实例描述符表达。friend 自身的有限检查传播不是此次
C 生成不终止的来源。

## 4. 后续修复边界

后续应先确定无法形成有限静态闭包时的处理契约，再修改实现和测试：

- 若采用编译期拒绝，需要在主规范确定适用范围及诊断，公共具化机制报告可定位的
  增长依赖链。
- 检测应区分持续增长与能够收敛的递归，包含相互依赖及多个参数的替换；不能仅因
  再次遇到同一泛型声明就拒绝，也不能以任意固定深度截断代替规则。
- 字段、注解及其他使用相同注册机制的来源应遵循同一规则，不按 friend 名称跳过。
- 若选择支持无限增长源码，需要另行设计描述符生成策略；本记录不授权新增运行时
  生成、分配或 ABI 变化。

## 5. 后续验证要求

编译器测试应覆盖已确认的字段和注解复现、相同实参递归、有限的相互递归及参数替换，
并为不终止回归设置子进程超时。具体诊断断言待修复契约确定后补齐。
如修复涉及跨包依赖恢复，应覆盖 provider／consumer 的同等行为。

有限合法程序的行为由 FCTS 验证；完成实现后按仓库要求在沙箱外执行完整 `make test`。
本次未增加拒绝规则、未修改实现或测试，不能将现有全量回归通过视为本问题已修复。
