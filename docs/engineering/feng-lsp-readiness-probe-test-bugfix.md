# Feng LSP readiness 探测测试修复

> 状态：2026-10-21，注解参数导航就绪等待及断言辅助函数修复、定向验证、现有 Linux ARM64 容器的 `make test` 全量回归均完成。2026-09-23 的修复和验证记录保留在下文。

## 1 问题

### 1.1 探测次数过早耗尽（已修复）

CLI 测试通过位置请求轮询等待 LSP 异步索引可见。原辅助函数连续发送最多 64 组
“位置请求 + barrier”，每次收到 barrier 后立即开始下一次探测，没有给后台索引保留
等待时间。全量构建后的冷启动或较慢 CI 环境中，全部探测可能在索引完成前耗尽，导致
`ready` 断言偶发失败；同一测试二进制在文件缓存变热后重跑通常通过。

### 1.2 Hover 可用不代表依赖源码跳转已就绪

`assert_lsp_lambda_fit_call_navigation(false)` 用 Hover 中的方法注释判定就绪，随后要求
Definition 返回本地依赖 `.ff` 的精确位置。包符号可以先于依赖源码映射可用，因此 Hover
已经满足条件时，Definition 仍可能返回包内 `.ft` 的 `(0,0)`，导致位置断言偶发失败。
这是过早判定就绪，不是探测超时。

2026-09-23 定向复现中，前 74 次通过，第 75 次在请求 11 的位置断言失败：预期
`extensions.ff` 的 `(3,12)`，实际返回 `lambda_extensions.ft` 的 `(0,0)`；同一批后续
请求已返回正确源码位置。以上坐标均为 LSP 从零起算的坐标。

### 1.3 注解参数导航遗漏依赖源码就绪条件

`assert_lsp_annotation_argument_navigation(false, false)` 只等待消费方局部变量的
`let readiness: string` Hover，然后要求依赖类型的 Definition 返回物理 `.ff` 位置。
消费方成功分析与依赖项目的源码映射分开发布，前者就绪不代表后者已就绪。
源码依赖且消费方存在语义错误的分支只等待语义诊断，同样不能据此确认依赖源码映射。

2026-10-21 在既有 Linux ARM64 容器中保持 LSP 实现不变，仅在临时测试依赖中增加
30 个私有函数以放大分析时间窗口，第 8 轮复现了 linux-x64-gnu CI 中相同的断言：
请求 11 返回 `annotation_provider.ft` 的 `(0,0)`，同批请求 29、39 已返回
`provider/src/types.ff` 的 `(2,10)`。断言辅助函数从请求 11 开始查找预期位置，匹配却
落在后续响应中，因此触发 `next_response == NULL || match < next_response`。
该复现证明等待条件不足；这里的请求详情来自本地复现，CI 原日志未记录实际响应。

### 1.4 断言退出引发测试辅助字符串泄漏

`assert_lsp_test_response_contains()` 用 `dup_printf()` 分配请求 ID 标记，直到所有断言
通过才释放。断言失败时 `ASSERT` 直接退出，请求 11 的 `"id":11,` 标记连同结尾零字符
共 9 字节未释放，随后被 LeakSanitizer 报告。这是测试辅助函数的失败路径问题，不是
编译器或 LSP 实现的载荷泄漏。原诊断只输出断言表达式，也无法直接识别失败请求及响应。

## 2 修复规则

- 保留协议探测与 barrier 判定，不以固定 sleep 代替 readiness 条件；
- 未就绪时等待 25ms 再发起下一次探测；
- 最多探测 200 次，将额外等待限制在约 5 秒内；
- 已就绪时立即继续，不增加成功路径的固定等待；
- 就绪探测必须覆盖后续断言所需的信息。本地源码依赖的 lambda 调用导航用例改为探测
  Definition，同时匹配预期 `.ff` URI 与起始位置；复用现有位置标记和通用探测辅助函数；
- 打包依赖不需要本地源码映射，保留原 Hover 就绪条件及 `.ft` 跳转预期；两个分支的
  测试源码、请求集合和全部 Hover / Definition 断言保持不变；
- 注解参数导航保留原消费方 Hover 或语义诊断就绪检查；两个源码依赖分支在同一 LSP
  会话中追加依赖 Definition 就绪探测，同时匹配物理 `.ff` URI 与起始位置。使用已有
  普通类型引用探测依赖映射，随后执行原有 15 个位置的全部注解及普通导航断言；
- 两阶段等待复用同一有界协议探测循环及已有 ready action 入口；不复制另一套重试规则，
  不新增固定成功延时，不改变打包依赖的等待条件；
- `assert_lsp_test_response_contains()` 在完成请求 ID 定位后立即释放 ID 标记，再执行
  原有断言。失败时先输出请求 ID、预期内容和该请求范围内的实际响应；请求不存在时
  明确说明缺少响应，不把下一帧内容混入实际响应。保留原有断言表达式及匹配要求；
- 只修改测试辅助逻辑，不改变 LSP 实现和生成后 Feng 程序的运行时行为。
