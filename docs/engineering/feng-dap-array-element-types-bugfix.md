# DAP 内联数组元素类型与步长修复

> **状态：已提交为 `3d223db2`，Linux 全量回归及性能核对通过。日期：2026-10-16。**
>
> 原始拆分 patch 已删除；实现及补齐的用例以该提交为准，无需再次应用补丁。
> 原补丁基线：第一阶段提交 `65672f13` 加纯 union 布局变更；本轮验证基线：`470d58d7`。

## 1. 发现过程与根因

新增 DAP 布局验证时，局部 union 和对象中的 union 字段显示正常，但 union 数组
元素显示为地址且不能展开。修改前编译器也已复现。

`proxy_array_element_c_type` 对无法识别的具名类型退回 `void *`，内联 union 被按
指针宽度计算元素间隔。数组元素的返回值也未完整复用既有载体展示处理。

## 2. 修复边界

编译器为具体用户类型、spec 及 enum 生成 Feng 类型到 C 表示的调试映射；开放泛型
占位载体不产生具体类型记录。DAP 根据记录使用真实 C 类型作数组下标访问，再复用
现有载体展示逻辑。普通值对象数组同样使用这一规则。

实现涉及 `codegen.c`、`mapping.c/.h`、`debug.c`、`dap/proxy.c` 和编译驱动的 Debug
类型保留选项。类型映射规则统一定义于 [DAP 主规范](feng-dap-dev.md)。`.fd` 增加
`type` 记录种类，复用现有 ENTS 记录宽度、section 和版本号；旧读取器不识别新种类，
调试器及调试制品需要同步更新。

不改变 union 布局、runtime、循环引用识别、部分初始化清理或 LTO 选项。纯布局
版本继续验证局部和对象字段中的 union；数组缺陷用例已随修复提交。

## 3. 独立回归覆盖

- 类型映射：生成、去重、非法记录拒绝、`.fd` 读写及依赖合并冲突拒绝。
- 真实 DAP：默认 Debug 和显式 ThinLTO，局部、字段、不同元素值及仅经数组使用
  的 union；嵌套、空、可写和默认值数组；普通值对象数组的正确步长和展开。
- 本轮补充显式 LTO off、对象和枚举数组、源码隐藏的库返回的 union／值对象数组，
  以及关闭调试映射时不生成类型记录。枚举记录改为随枚举发码登记；原 patch
  只遍历导入枚举缓存，新增本包枚举用例发现并修复了这一遗漏。
- 数组元素类型查询按一次展开复用，内建类型保持直接映射，避免逐元素重复扫描记录。
- 库仅返回值对象数组时，元素 C 类型可能没有其他 DWARF 引用。新增跨包用例确认
  原 patch 的类型名称映射不足以支持 LLDB 求值；Debug 编译需按主规范保留类型信息。

## 5. 性能与制品核对

Linux ARM64、同一容器、随包 Clang／LLDB 23.1.3。使用现有五项用例的 standard
输入、计时／RSS 采集器和结果校验器；每个版本每项预热 2 次、交错测量 15 次。
46 次边界与非法输入校验全部通过，150 次正式采样全部成功。

| --- | ---: | ---: | ---: | ---: |
| nbody | 656.658 | 657.499 | +0.13% | 1.844 / 1.801 |
| binary-trees | 325.535 | 329.749 | +1.29% | 17.266 / 17.266 |
| text-scan | 108.386 | 110.484 | +1.94% | 245.480 / 245.477 |

| spectral-norm | 103.632 | 103.655 | +0.02% | 1.844 / 1.801 |

五项用例的生成 C 与最终 Release 可执行文件均逐字节一致，runtime 静态库也
逐字节一致。每项新旧时间的四分位区间重叠；本次观测未发现修复引入的运行时退化，
不能把表中的采样差值解释成代码变慢。

额外使用同一路径的 Debug 程序核对：生成 C 和 `.text` 均逐字节一致；保留类型后
增加的是调试信息，所检查程序的可加载 section 大小及地址不变。`.fd` 新增类型
记录，Debug 文件体积会相应增加，不代表增加运行时对象存储。

DAP 对照包含 256 个额外类型、64 个数组元素，预热 2 次、交错测量 15 次，并逐项
检查显示值。整数数组响应中位数为 206.038 → 178.984 ms，字符串数组为
658.919 → 584.695 ms，未观察到退化；响应波动较大，不据此承诺固定提速幅度。
旧版对象数组字段读为空值，不能作为等价性能基线；该失败证据保留，修复后的对象
数组读取由新增 CLI 回归验证。
