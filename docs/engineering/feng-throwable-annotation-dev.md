## 1 目标与规范归属

允许库自行定义具有普通成员和父契约的异常根 spec，编译器通过内建注解识别其
身份，不感知具体库、模块、类型名称或 `toString` 等成员名称。

根 spec 同时作为普通值类型和普通泛型约束：前者支持统一持有、传递不同具体
异常，后者证明泛型共享体中的值具有可抛资格。无需增加内建 `throwable` 类型、
关键字或另一套泛型约束系统。

本轮方案比较区分两个目标：任意异常句柄可以解决异构异常的保存与再次抛出，
但句柄本身不提供统一可调用的日志契约；`Error<T: Display>` 等包装类型也只能覆盖
采用该包装的异常，不能成为所有合法异常的具名兜底。对于“统一持有、根 catch、
契约成员调用”这一完整目标，采用 `@throwable`；若只要求保存与重抛，
句柄方案无需迁移所有载荷的契约关系，所需语言规则改动更少。该比较仅保留方案
取舍依据，具体实施范围按第 6、8 节的 Review 结论执行。

## 2 已确认的语言边界

### 2.1 注解标记库中的契约

`@throwable` 用于 object-form `spec`。它标记一个已有的普通契约，不生成契约，
也不为其补充成员或实现。其他 spec 形态和其他声明种类不属于该注解的适用位置。

根 spec 必须同时满足：没有泛型参数、自身声明为 `open spec`、所在模块声明为
`open module`。在登记根前检查声明与模块叠加后的有效可见性；现有
`signature_decl_visibility` 已按这两个层级计算公开性，可复用该判定。
根成员继续遵循普通可见性规则，不额外要求所有成员公开。这些根声明限制不要求
`Error<T>` 等满足者无泛参或公开。

注解仅支持裸写 `@throwable`；`@throwable()` 和任何带实参的写法均拒绝。现有
Parser 的 `FengAnnotation.argument_kind` 已区分无括号与带括号形式，不能仅检查
`arg_count == 0` 而误放行空括号。

库层采用 `Throwable: Display`，通过普通父契约复用 `toString()`。以下示例位于
公开模块，并假定 `Display` 已可见；编译器不固定根的名称、模块或成员：

```feng
@throwable
open spec Throwable: Display {}

type Error<T>: Throwable {
  let detail: T;

  func toString(): string {
    return "error";
  }
}

func raise<E: Throwable>(error: E) {
  throw error;
}

func forward(error: Throwable) {
  throw error;
}
```

根可以按普通父契约规则复用其他契约。编译器只根据注解登记的声明
身份判断异常根，根契约的成员满足、可见性、调用和 witness 均沿用普通 spec 规则。

`@final` 是[独立特性](./feng-final-annotation-dev.md)，其通用规则不变。异常根的
子 spec 限制由第 2.2 节的统一载荷资格检查保证，不要求根额外标注 `@final`，
也不依赖该独立特性先实施。

### 2.2 在建立满足关系时检查载荷资格

统一规则：**声明主体建立对异常根契约的满足关系时，必须先通过完整的合法载荷
检查，再通过普通契约满足检查，该满足关系才能成立。**

检查入口覆盖 `type` 声明头、`fit` 的契约关系，以及 object-form `spec` 的父
契约列表。名称解析及原有声明合法性检查通过后，若关系目标是已登记的异常根，
则对关系左侧的声明主体执行同一载荷资格检查；普通契约关系继续使用原有规则。
根的注解登记不建立新的满足关系，不把根声明本身当作具体载荷执行此项检查。

合法载荷检查统一复用异常主规范的既有规则，并提前到声明满足契约时执行。
检查失败在建立满足关系处报告；已被既有声明规则拒绝的位置继续报告原有根因，
不增加重复诊断。通过验证的根满足关系同时保证合法载荷资格与契约能力，后续
throw 只消费该证明，不再按数据类别维护另一套准入判断。

统一规则的直接结果：

- `type Error<T>: Throwable` 允许建立关系：`Error<T>` 是具名 type，不能因为
  声明中有开放泛参而拒绝。T 不必满足异常根：例如 `Error<int[]>` 的载荷是整个
  具名对象，不要求它的数组字段单独具备可抛资格。
- `spec Child: Throwable` 拒绝建立关系：被检查的声明主体是 `Child`，它属于
  spec，不具备具体异常载荷资格。即使成员完全满足根契约也不能通过。因此根不能有
  子 object-form spec；多父列表、泛型子声明和跨包引用均适用，不依赖 `@final`。
- 数组等不具备载荷资格的目标，在声明满足关系时即被拒绝。

现有 `type_ref_is_exception_payload` 同时包含“载荷类别”和“当前类型引用仍含
开放泛参则拒绝”两类判断。实施时应提取共用的载荷资格检查，区分以下职责：

1. 声明验证按载荷类别及具名类型身份规则判定，允许 `Error<T>` 这样的泛型声明，
   不要求声明处已取得每个闭合实例的描述符；也不因此放行数组或任意开放类型。
2. 实际 throw 的发码按第 2.5 节取得闭合实例的精确描述符并构造载荷。
3. 具体 catch 保留类型引用必须闭合的既有要求，不能因复用函数的调整而放开
   `catch error: E` 或 `catch error: Error<T>` 等仍含开放泛参的写法。

这里前移的是载荷资格检查；语句及表达式相关的非载荷检查仍在 throw 处执行，
具体边界见第 2.3 节。

### 2.3 throw 只消费根契约证明

对于 `throw expr`，完成表达式解析和通常的语句检查后，类型准入统一判断：
**能否按既有契约关系证明该表达式满足已登记的异常根。**

编译单元及依赖闭包没有根、且没有依赖根能力的用法时，允许编译；需要进行 throw
类型准入而没有根时，明确诊断根缺失，不退回旧载荷白名单。

- 具体类型及 `Error<T>` 等具名泛型类型，根据已验证的满足关系证明。
- 直接泛参 E，根据普通 spec 约束证明；`E: Throwable` 无需另加内建 `throw` 约束。
- 已形成的根 spec 值可直接抛出；根的组合限制见 spec 主规范，不另造结构匹配
  或联合类型准入规则。
- 无约束泛参、无关契约约束及没有根满足关系的具体类型不能抛出。

禁止根的子 spec 不改变普通泛型约束规则：`E: Throwable` 的实际类型仍可为
`Throwable` 本身。共享体必须保留实际 spec 值，
并按第 6 节从该视角形成真实载荷，不能假定所有 E 都是具体实体类型。

合法载荷检查已在建立满足关系时完成，throw 不再重复执行，也不维护另一套数据类别
判断。根值形成、泛型转传、字段保存、函数返回和跨包消费必须维持同一证明，不能绕过
关系准入。

以下非载荷规则不变：表达式解析与非 void 要求、匿名 catch 中 `throw;` 的作用域、
defer 限制、控制流终止与可达性、try 表达式规则、异常清理和 C ABI 边界规则。
根 catch 是具名 catch，不自动取得匿名 catch 的 `throw;` 权限。

### 2.4 catch 的允许形式

- 具体类型 catch 保持具体描述符身份的精确匹配；泛型实例按完整实际类型区分。
- 允许 `catch error: <根 spec>`，将任意合法异常绑定为根契约值，供普通成员调用、
  保存和传递使用。
- 保留匿名 catch。除根以外，不开放其他 object-form spec、intersection-form、
  union-form 或 callable-form spec 的 catch。
- `catch error: E` 继续禁止；也不因本方案顺带开放仍含泛参的 catch 类型引用。

具体 catch 的可用载荷类别沿用异常规范。根 catch 与无绑定的匿名 catch 都是兜底：
同一 try 中二者合计最多一个，有则必须最后，也允许没有兜底。每个 try 至少一个
catch 的原有要求不变；只有具体 catch 时，未匹配异常继续向外传播。不增加运行时
的 spec 满足集合查询。

当前 `resolve_try_expr` 已检查匿名 catch 必须最后，没有要求每个 try 都有兜底；
新方案将根 catch 纳入同一兜底规则，保留不写兜底的既有行为。

### 2.5 泛型与实际异常身份

是否属于泛型类型不是载荷资格的否决条件。发码必须能取得实际闭合类型对应的
描述符，正确形成载荷，并使具体 catch 与之使用同一身份。

`Error<T>: Throwable` 的声明检查与运行时的实际类型信息分属两个阶段：声明处
证明具名载荷资格，实际执行 throw 时取得 `Error<int>` 等完整实例的精确描述符。
共享体源码中仍写作 `Error<T>` 不构成拒绝理由；具化通过已有描述符重化机制完成，
不要求共享体源码先静态替换成具体类型，也不要求为每个实参复制一份函数体。

当前闭合泛型实例已经支持 throw/catch；共享体内静态类型仍为 `Error<T>` 的 throw
则被旧 Semantic 提前拒绝，旧 throw 描述符发码也不能直接视为已接通全部重化路径。
本方案需要补齐该通路，不能仅删除语义检查就宣称完成。

泛型共享体分别复用方法／函数隐式描述符和类型 owner 描述符中的既有重化信息，
覆盖引用类型及值类型。不得把具体异常身份替换成 E、泛型模板或根 spec 的身份。

## 3 根信息登记与唯一性

### 3.1 每次编译持有一个根信息记录

编译期状态保存 **spec 信息**，不是 bool。建议记录：

- 根声明的规范化身份；
- 可供语义检查和发码使用的声明引用／查询句柄；
- 所属模块及用于重复诊断的来源信息。

成员、父契约和类型信息通过该声明查询，不复制另一套成员模型。记录归当前分析
上下文所有，生命周期覆盖相关阶段；不使用跨编译任务共享的进程级静态变量。
LSP 重新分析时按当前源码与依赖重建记录，避免旧标记残留。

### 3.2 登记规则

| 状态与候选 | 处理 |
| --- | --- |
| 尚无根，遇到合法标注 | 保存 spec 信息 |
| 再次得到同一规范化声明 | 幂等复用；重复引用和菱形依赖不构成重复定义 |
| 遇到另一个被标注的声明 | 编译错误，指出两个根的模块与声明来源 |

同一源声明重复书写 `@throwable` 报错；同一声明被重复导入按上表幂等处理。
短名称相同不表示同一声明，导入别名不同也不表示不同声明。跨文件符号引用可复用
既有模块身份与符号 ID 的组合，不能只比较裸 `symbol_id` 或跨进程指针。
源码、缓存及不同 profile 的来源覆盖先遵循既有规则，再归一化为当前声明身份。

登记范围为当前编译的源码及实际参与编译的依赖闭包，不扫描未参与编译的安装包。
根必须在契约资格与函数体检查前可用，结果不能依赖源码或 import 顺序。

### 3.3 复用已有加载流程

当前 `feng_symbol_provider_add_bundle` 会读取 `.fb/mod/` 下的全部公开 `.ft`；
Semantic 则只接入被引用及其签名依赖的外部模块。因此，不能仅在 Semantic 已接入
模块中发现根，否则会漏掉输入依赖中未被直接引用模块上的第二个标注。

建议在已有声明收集、符号读取与归一化流程中同步收集根候选／模块摘要，再通过
中立的导入查询接口交给编译上下文统一登记。每个候选只需与已有根比较，不额外
遍历所有包的所有类型。核心 Semantic 不依赖 `.ft` section、reader 或 zip 路径。

注册摘要是编译期索引，不是运行时反射表。根的声明与成员可按既有导入机制解析，
无需为查找一个根而合成所有依赖模块的 AST。

## 4 `.ft` 与跨包消费

### 4.1 必须保存定义标记

定义根的包必须将标注作为 spec 的声明事实写入 `.ft`。建议追加所属 spec 的
`ATRS` 属性，复用现有声明、父契约和成员记录；不序列化 AST 指针或 witness 地址。
具体属性编号在符号表主规范中分配。

链路需要完整覆盖：源码标记 → 归一化符号事实 → writer → reader → 查询视图 →
导入声明恢复 → 根登记。package-public 和 workspace-cache 均需保留相应事实，
复制、LSP 符号形状比较和跨平台公开事实比较不能丢失标记。

已有 spec 导出会调用 `apply_decl_annotations`，但导入 spec 分支当前没有调用
`synthesize_decl_annotations_from_symbol`。因此增加属性读写之外，还必须补齐
spec 注解恢复或等价的统一声明事实访问，不能产生源码与二进制包两种判断结果。

### 4.2 定义与引用分开处理

假设 A 定义异常根，B 和 C 依赖 A，应用依赖 B、C：

- A 的 `.ft` 保存根定义标记。
- B、C 按已有机制保存使用根的类型引用和契约关系，不重新定义根。
- 依赖管理层展开并去重传递依赖；编译上下文最终登记同一个 A 中的声明。
- 若另一个依赖 D 定义了不同根，必须报告冲突，不按加载先后选择其中之一。

根按第 2.1 节要求声明与所在模块均公开。现有 `feng_symbol_export_graph` 与
`feng_symbol_export_package_selection` 选取公开模块，`writer_should_export_decl`
保留公开声明，因此合法根可以沿用 package-public 导出路径，无需为私有根或
非公开模块新增元信息保留入口。根没有被其他声明引用时也应正常导出其标记。

源码与二进制包登记根时均需验证这些声明条件；从 `.ft` 读到标注在非公开声明或
非公开模块中的根，应拒绝非法事实，不能默默忽略或提升其可见性。两种 profile
都需恢复根身份及原有声明事实。根的公开性不替代第 3.3 节的完整发现流程，未被
直接引用的公开模块中的第二个根仍须检出；普通名称解析和签名一致性规则不变。

根标记恢复后，源包建立满足关系时的载荷资格与消费侧的类型事实必须一致。
跨包同样覆盖 type、fit、泛型声明以及对子 spec 声明的拒绝，不以 provider 源码
可见为前提，也不以额外的 final 标记作为拒绝子 spec 的依据。

沿用已确认的 `.ft` 2.0 加完整重编策略，实施前将兼容声明写入主规范。
重编范围包括依赖包、consumer、符号缓存及相关生成制品；不默许混用旧异常规则下
生成的库，也不为旧 `E: throw` 元信息增加隐式兼容语义。

### 6.2 三参数传递，不要求先构造根视图

按 R04 已确认的实施范围，将异常接口调整为以下形式：

```c
void feng_throw(void *value,
                const FengTypeDescriptor *desc,
                const void *witness);
```

三个参数作为一组准备并写入同一个异常展开记录：

| 参数／记录字段 | 含义 |
| --- | --- |
| `value` | 原托管对象或既有 `ValueBox<T>`，也就是根视图应使用的 subject |
| `desc` | 该原载荷的精确异常描述符；值载荷沿用箱体描述符 |
| `witness` | 与该 subject 表示一致、用于调用异常根成员的 witness |

throw 端按统一表达式发码取得结果，再共用普通 spec 转换中准备 subject 与 witness
的逻辑。可以直接将准备结果传给 `feng_throw`，**无需先构造 `{ subject, witness }`
临时值再拆开，也无需分配独立的托管根视图载体**。公共逻辑负责准备配套的 subject
与 witness：普通转换据此组成 spec 值，throw 则据此准备上述三个参数。

对于已经是根 spec 的表达式，使用值中现有的 subject 与 witness。这里读取已有视图，
不把整个 spec 存储当作异常实体，也不再为它装箱。

`desc` 始终对应原载荷的实际闭合身份，包括从已有 spec 的 subject 取得的身份。
不能使用根 spec、泛参 E 或泛型模板的描述符代替；`Box<int>` 与 `Box<MyType>`
等不同闭合实例仍应分别匹配。`.ft` 根标记负责编译期识别，随异常传递的 witness
负责根成员调用，两者都不要求增加运行时的类型满足集合或反向搜索 witness。

该方案的处理流程是：

```text
throw 表达式 → 准备原载荷、精确描述符、根 witness → feng_throw
具体 catch  → 匹配 desc → 读取原 value → 现有绑定／解箱
根 catch    → 兜底匹配 → 读取 value 与 witness → 组成普通 spec 值
```

### 6.3 catch 匹配、绑定与重抛

`feng_region_matches_exception` 继续按描述符身份或 NULL 兜底匹配。所有合法抛出值
已受根约束，因此根 catch 可以复用 NULL 匹配；这不构成对其他 spec catch 的支持。

具体 catch 继续使用 `feng_caught_value()`。由于它仍返回原 subject，无需为本方案
抽取另一套载荷来源，也无需先解出根视图。原有绑定逻辑可以保留：

| catch 类型 | 原 `value` 表示 | 现有绑定逻辑 |
| --- | --- | --- |
| 引用类型、string | 原托管对象指针 | 按已匹配的具体类型形成绑定 |
| 标量、enum | `ValueBox<T>` 指针 | 从已知箱体布局读取 value |
| tuple、`@value type` | `ValueBox<T>` 指针 | 通过既有聚合赋值／复制路径取值并处理托管字段 |

表中描述绑定机制，不额外授予任何类型根满足关系；类型准入仍按第 2 节处理。

根 catch 从当前记录取得 `value` 和 `witness`，组成普通根 spec 值。提供读取
witness 的 runtime 入口 `feng_caught_witness()`；该必要入口已纳入 R04 实施范围，
该入口已在本轮接通。runtime 只保存和返回不透明 witness 指针，不感知库名称、
根成员或 witness 表内容。

根值绑定、复制和保存到 catch 外均沿用普通 spec 的持有规则。显式 `throw error`
再次准备原 subject、精确描述符与根 witness；匿名 `throw;` 则继续复用整个异常
记录，自然保留新增 witness。具体 catch 的匹配与绑定机制无需为此改变，根值逃逸、
重抛及嵌套异常的所有权仍须按第 6.5 节验证。

### 6.4 共享体取得正确 witness：复用既有表示与静态准备

本节受上述实施边界约束。保留现有泛型参数与类型 owner 描述符布局、共享体
通用参数／返回 ABI、值复制／持有／转传及约束成员分派实现。spec 实参继续保持
完整 spec，不提前改写为底层 subject。移除旧内建 throw 约束及迁移 throw 专属
发码不构成修改这些通用机制的授权。以下依赖准备必须先核对现有能力，不能因
准备链路尚未完成就自行扩展通用描述符、增加转换回调或更改共享体通用实现。

函数／方法级泛参有隐式描述符，类型级泛参信息保存在类型 owner 描述符中。
`FengSpecCoercionDescriptor` 的现有静态槽可将箱体描述符、载荷偏移和 box-owner
witness 成组绑定；共享体通过依赖所属的 `_desc` 或 `_td` 读取。依赖归属按现有
重化规则确定，不能仅凭“类型级泛参”就假定所有转换表都从 `_td` 读取。

**情况一已确认：实际泛型实参为具体值载荷时，复用现有装箱能力，仅补齐 throw
专属接入。** 普通 spec 转换已有箱体描述符、载荷偏移及与箱体匹配的 witness，
本轮没有改变其装箱机制。throw 应登记所需的已有静态转换依赖，在类型闭合处
复用已有转换信息生成，执行时复用既有装箱、值复制和所有权操作，再将箱体、
精确描述符与对应根 witness 交给异常协议。

旧 `E: throw` 将装箱信息指针存入泛参描述符的 `witness` 字段；普通 spec 约束
使用该字段进行成员分派。这只说明旧 throw 的取信息方式需要迁移，不说明现有
装箱能力不足。新的 throw 专属路径从已有静态转换槽取信息，保留普通泛参
`witness` 的用途，不改变泛型实参表示、描述符布局或共享体通用实现。
**情况一不再作为扩展泛型描述符、`FengSpecCoercionDescriptor` 或异常根 witness
布局的理由。** 直接泛参 E 的 throw 依赖接入与发码已实现，实施记录见 §11.5，
本轮 Linux 全量验收结果见 §11.6。

**情况二按 R07 收敛为根值自身。** 根值已保留 subject 和真实根 witness。
throw 在聚合分支比较实际聚合描述符与已登记根的聚合描述符，识别后按根值的
既有布局读取；借用值的持有与拥有值的转移复用普通聚合操作。无需交叉路径、
专属 witness 字段、泛参描述符扩展或完整 spec 异常载体。此前额外布局候选撤回。

直接泛参的准备依赖仅登记在 throw 表达式的语义附属记录中，沿用既有静态转换
依赖的收集和转传；由 throw 专属发码消费，不开放普通表达式的 `E → spec` 转换。

但“已有泛参描述符和约束 witness”不等于“可直接把该 witness 随异常传递”：

| 泛型实参的实际表示 | 约束调用与异常根 witness 的差异 |
| --- | --- |
| 具体引用载荷 | 复用指向该具体 subject 的根 witness |
| 标量、enum、值类型 | 约束调用可能按原值地址解释 subject；异常传递的是 `ValueBox<T>*`，必须选择与箱体布局一致的 witness |
| 根 spec 值 | 泛型约束仍使用既有 spec-slot 适配；throw 读取实际根值中的 subject 与 witness，不把适配表搭配到原 subject |

例如标量约束调用的 `BORROW_LOCAL` witness 会解引用原值地址，而 `BOX_OWNER`
witness 会从箱体读取 value；不能将前者与箱体指针搭配。spec-slot witness 也不能
与已解出的 subject 搭配，否则 thunk 会把 subject 错当成完整 spec 存储。

实现使用以下编译期链路：

1. 语义阶段为受根约束的 throw 记录所需的 subject／witness 准备依赖，覆盖直接
   泛参 E 与开放具名类型；依赖收集、转传和跨包恢复保持完整。
2. 在类型闭合处确定实际表示、规范箱体及其根 witness；实际根值使用空准备项，运行时从原值读取 witness。
   共享体消费静态安排的信息，不在运行时搜索某个类型满足哪些 spec。
3. 发码将上述信息与表达式结果、精确异常描述符及所有权配套使用。实参为 spec
   时必须保留并读取其实际值，不能仅凭泛参描述符合成底层 subject。

已做的普通 spec 探针覆盖具体引用／值类型、共享函数中的 `Error<T>` 与
`ValueError<T>` 转视图、类型级及方法级共享体中的开放值类型转视图，以及引用／值／
spec 实参的泛型约束成员调用和已有视图返回。共十项检查编译运行成功，退出码为 0；
成员实际读取载荷的托管字段，生成代码使用静态转换槽及箱体 witness。

同一轮核查也确认：`func view<T: Root>(value: T): Root { return value; }` 当前
报 AE1003，类型级和方法级同类隐式转换亦然；显式 `(Root)value` 报 AE1023。
已有开放具名类型视图路径不能据此推广为直接泛参转换已经可用，当前闭合转换入口也
不能直接覆盖实参为 spec 时所需的投影。

**三参数方案不要求先开放通用 `T → spec` 语言转换。** 上述 throw 专属准备链路
保持现有泛型边界；普通 spec 探针是设计依据，实际异常行为由本轮测试验证，
不能以历史探针代替交付验收。

### 6.5 表达式与所有权边界

throw 继续使用统一表达式求值结果，不按 AST 表达式种类分别实现异常协议。凡是
现有规则下合法、结果可证明根能力的表达式，都应接入同一准备路径：变量、字段、
索引、构造、函数／方法／闭包调用，以及 if、match、try 结果表达式。分支结果仍按
既有类型合并与转换规则处理，不因 throw 接受根契约就增加隐式的异构类型合并。

- 表达式只求值一次；准备描述符或 witness 不得重复求值，也不改变原有副作用顺序。
  表达式自身抛出时，传播该异常，不继续执行外层 throw 的载荷准备。
- 借用结果按既有规则取得异常记录所需的持有，拥有结果正确转移；聚合值继续通过
  普通复制路径维护托管字段。值类型复用既有装箱，已有根值的 subject 不重复装箱。
- 异常记录继续拥有原 `value`；清理仍释放该载荷。witness 指向静态表，不需要 ARC。
- 根 catch 组成的 spec 值若复制或逃逸，必须维持对 subject 的有效持有；显式重抛
  必须先确保新异常取得所有权，释放旧记录不能使新载荷悬空。
- 覆盖正常离开 catch、嵌套异常、匿名重抛和保存后再抛出的清理，不遗漏或重复释放。

### 6.6 已确认的 runtime、ABI 范围与成本验证

根 spec 继续使用已有 `{ subject, witness }` 布局，无需新增根视图布局；异常传递
接口和 `FengUnwindException` 增加 witness 则明确属于 **runtime 私有 ABI 变更**。
复用原异常记录，保留 `value` 的含义、描述符匹配和载荷释放，只增加 witness
保存／读取及编译器对应发码。运行时无需理解根契约的成员面。

成本以当前实现为基线：值类型的 `ValueBox<T>` 与异常展开记录分配已经存在，
本方案不因携带根能力再分配独立根载体。仍需评估新增参数传递、witness 字段存取、
记录大小及根 catch 持有成本；记录大小受布局和对齐影响，不能直接断言恰好多一个
指针大小，也不能把“不新增根载体分配”等同于零成本。

R04 已确认三参数传递、异常记录 witness 字段及读取入口是新方案的必要改动，
其配套 runtime 私有 ABI 调整、参数／字段存取与所有权处理属于实施范围。
共享体准备／投影的设计、字段布局核对及成本和生命周期验证由实施承担，不再将
这些已确认的必要工作作为重复审批事项。若实际需要超出本方案的 ABI 调整、额外
分配、动态查询或新的转换回调，应先记录具体原因及影响，再由人工决策。

实施后至少验证：跨包 throw → 根 catch → 调用库声明的成员 → 保存到函数外
→ 再抛出 → 具体 catch，并覆盖第 6.4 节的实际表示、第 6.5 节的表达式与所有权。

## 7 `E: throw` 与现有代码的迁移

### 7.1 移除内建约束的专属部分

按新方案定向移除 `E: throw`，普通 spec 泛型约束不是该特性的新增能力，不随其
移除。既有用例及旧内部表示断言按第 7.3 节已确认的范围做等价迁移。

- 移除该专属约束语法、AST kind、语义分支、专属发码和 `.ft` 属性消费，同步
  dump、LSP、标准库 Parser 与规范；保留新方案仍需使用的通用值操作和描述符能力。
- 将有价值的泛型抛出、跨包、实际身份及所有权测试场景迁移到根 spec 方案，
  不通过删掉验证场景来完成回退。
- 原有不可抛载荷检查早于该功能存在：`359b9820` 已包含数组禁抛等规则，
  `a742bc20` 新增内建约束时复用了它们；这些载荷规则应按第 2 节保留和调整职责。
- `a742bc20` 同时包含标准库 `FengParser.nextToken` / `peekToken` 的 EOF 循环修复。
  该独立修复及相应验证必须保留，不能整笔撤销后遗漏。

历史交付文档 [throw 泛型约束方案](./feng-throw-generic-constraint-dev.md) 在实际迁移
完成后标注被本方案取代，保留历史验证事实，不提前宣称已回退。

### 7.2 标准库与调用方

当前 `std.Error` 是满足 `Display` 的具体 type；`FengCompileError` 也是具体 type。
标准库多处直接抛出 string，并有具体 string catch。已确定通过 `fit` 为原有合法
载荷建立根契约关系，保留现有 throw 表达式、具体 catch 与行为断言，不将原有
用例改写为抛出新的包装异常类型。适配必须满足根契约成员及普通可见性规则。

库层根采用 `Throwable: Display`，复用父契约的 `toString()`；声明组织沿用现有
标准库结构，编译器不固定其模块和成员。既有载荷的适配方式按第 7.3 节执行。
编译器不得为了兼容旧用例而自动给类型添加满足关系、硬编码 std，或在
缺少根时退回旧 throw 白名单。

统一根值应验证跨字段、容器和泛型返回的保存／再抛出能力。Future 可作为这种能力
的应用场景；本方案不顺带重设计 Future / Promise 的调度、状态机或公开 API。

### 7.3 用例迁移与补充覆盖（已确认）

实施时遵守以下要求：

1. **原有普通异常用例保持不变。** 对 `throw "text"`、`throw str` 及其他原有合法
   载荷，通过库代码或测试辅助源码中的 `fit` 满足被 `@throwable` 标记的根 spec。
   保留用例本身的类型定义、throw / catch、控制流、预期值和断言；适配放在独立
   声明中，不通过改变载荷或 catch 类型使测试通过。
2. **原有泛型异常行为用例仅替换约束。** 将 `E: throw`、`T: throw` 等约束中的
   `throw` 改为 `Throwable`，涵盖类型级、函数／方法级及其他已有泛参入口；原有
   调用、表达式、具体 catch、所有权和行为断言保持不变。根声明、必要导入与
   `fit` 由对应库模块或测试辅助源码提供，不对其他位置的 `throw` 做全局替换。
3. **面向新方案新增用例。** 按第 10 节逐项补齐正例、负例、边界及相关组合，覆盖
   共享体、跨包、根 catch、实际身份与生命周期；保留旧覆盖，不以迁移代替新增
   验证。实施时建立“验证项—用例—实际结果”对应记录，发现遗漏继续补齐，并在
   定向验证后执行沙箱外 `make test` 全量回归。

测试辅助源码必须通过正常编译流程建立真实的根与满足关系，不能向编译器添加
测试专用豁免。独立编译器用例未必加载标准库，需按各自编译单元提供可见的根及
所需适配，不能假定标准库的 fit 全局生效。负例只提供其前置条件所需的合法关系，
不得为无关 spec 或原本不满足约束的目标统一补 fit；根缺失、不可抛载荷等新负例
独立构造，防止其他前置错误掩盖所要验证的诊断。

实际核查发现，少数用例直接断言 `E: throw` 的专属内部表示，**仅替换约束名称
不足以迁移这些断言**。R06 已确认以下等价迁移属于新方案的必要工作，目前未
修改测试：

| 用例 | 现有断言 | 所需调整及保留的验证 |
| --- | --- | --- |
| [编译器 Parser](../../test/parser/test_throw_constraint.c) | `FENG_CONSTRAINT_THROW`、空 constraint 引用及旧 dump 文本 | 改为普通 spec 约束及实际类型引用，dump 对应 `Throwable`；保留全部声明入口。非法类型位置的 `throw` 关键字用例不机械替换；按新规范等价调整旧约束移除后的诊断断言，记录对应关系 |
| [符号表与 `.ft`](../../test/symbol/test_throw_constraint.c) | 专属 kind 的统计、`FENG_SYMBOL_ATTR_BUILTIN_CONSTRAINT` 及其损坏数据校验 | 约束事实改为普通 spec 引用，根标记另行验证；保留两种 profile 往返、源码不可见消费和非法元信息拒绝。旧属性的损坏场景需逐项映射到新事实，不直接删掉或跳过 |
| [标准库 Parser](../../std/std_test/src/test_throw_constraint_parser.ff) | `GenericConstraintKind.Throw` | 改为普通 spec 约束的等价结构断言；保留 `throw` 不是普通类型的负例，以及 EOF、空输入和尾部 trivia 验证 |

上述内部表示、展示文本及相应诊断断言的等价更新已确认，保留原验证目标与覆盖，
不再逐项重复请求批准，也不为保留旧断言继续生成废弃的内建约束事实。若发现必须
改变原有行为场景或无法等价保留验证目标，则先记录具体差异，由人工决策；不得
删除、禁用或放宽断言来取得通过结果。

## 8 Review 结论与实施责任

以下记录本轮确认结果。必要的发码、runtime 和测试迁移属于实施任务；设计补齐
及验证由实施承担，不能将尚未完成的工作反复列为已确认方向的审批前提。

| 编号 | 事项 | 已确认结论与实施责任 |
| --- | --- | --- |
| R01 | 根 spec 的可见性及泛型参数 | 根必须是无泛参的 open object-form spec，所在模块必须为 open module；复用有效可见性判定及公开导出路径，成员仍遵循普通规则 |
| R02 | 注解写法、重复标注及根缺失 | 仅支持 `@throwable`，拒绝空括号和任何实参；同一声明重复标注报错，同根重复导入幂等。无依赖根的用法时允许没有根，需要 throw 类型准入时诊断根缺失 |
| R03 | 兜底 catch | 根 catch 与无绑定 catch 二选一，有则必须最后，也允许没有；保留至少一个 catch 及未匹配异常向外传播的既有规则 |
| R04 | 异常协议与共享体 | 第 6 节的三参数 `feng_throw`、witness 保存／读取及必要 runtime 私有 ABI 改动纳入实施；补齐共享体准备／投影，验证所有权、跨包与实际成本 |
| R05 | 库层契约 | `Throwable` 继承 `Display`，复用 `toString()`；编译器不感知库名和成员名。按第 7.3 节通过 fit 适配既有载荷 |
| R06 | 约束及测试迁移 | 移除旧内建约束并完成第 7.3 节的等价断言迁移，这是新方案必要工作；保持行为用例要求及独立修复，`.ft` 保持 2.0，重编全部相关制品 |
| R07 | 根与交叉契约 | 用户确认禁止异常根参与交叉；按 spec 主规范收紧声明准入。泛型 throw 的 spec 来源只处理根自身，保留现有泛型机制、描述符布局与共享体通用实现 |
| R08 | P22 固有缺陷 | 用户确认一并修复普通泛型函数／方法值遗漏的编译期约束 witness 准备；仅复用 Semantic 现有替换及物化路径，不改泛型表示、描述符或共享体通用实现 |
