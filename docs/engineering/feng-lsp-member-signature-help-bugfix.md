# LSP 成员签名提示与重载切换修复

状态：已完成，待人工 Review。基线：`c38a4ccc`。

## 问题与范围

在 `feng-demo/src/main.ff` 第 35 行输入 `list.clone(`，其中 `list: int[]`，成员补全能够显示 `clone`，但 Signature Help 返回 `null`。2026-09-27 通过真实 `feng lsp --stdio` 连续查询三次均复现，未修改用户文件。

修复成员调用的签名提示、接收者泛型代入及重载切换。语言规则沿用 [fit 规范](../specifications/feng-fit.md)、[数组 fit 规范](../specifications/feng-fit-builtin-type.md)和[可见性规范](../specifications/feng-visibility.md)。成员解析复用[补全修复](feng-lsp-fit-completion-bugfix.md)及[链式上下文修复](feng-generic-chain-context-bugfix.md)的现有实现。

不变更语言语义、核心编译器、runtime、ABI、FT、标准库和用户项目，不增加 Python 或 `.inc` 文件。

## 根因与方案

### S01 签名查询仍按类型声明或名称查找

原 `build_signature_help_json` 要求接收者能解析到名义类型声明，另行遍历直接成员和 fit。数组没有这种类型声明，fit 目标也只接受 NAMED／BUILTIN，因而漏掉数组。该路径还直接展示声明签名，未持续应用接收者泛型绑定。

将原方法签名查询接入 Completion 已使用的完整接收者类型解析、成员枚举及签名实例化。源码和 FT 共用规则，保留作用域、可见性、静态／实例过滤。删除被替代的三段重复查询，不保留新旧算法兜底。解析恢复及开放泛参约束处理由两种请求共用；已有 AST 优先，确实缺失时才通过现有 parser 恢复接收者。

### S02 未消费客户端的重载选择

原请求入口忽略 `context.activeSignatureHelp`。根据 [LSP 官方协议类型](https://github.com/microsoft/vscode-languageserver-node/blob/main/protocol/src/common/protocol.ts)，客户端在用户切换重载后会更新其中的 `activeSignature`。

完整返回所有可见同名方法签名，由客户端提供切换界面。再次触发时读取已选签名的 label，在本次真实候选中匹配并保留选择；不直接信任旧索引，以免编辑后重载顺序改变。无有效选择时使用首个签名。每个签名及顶层活动参数按各自参数数量计算，越界收敛到最后一个参数，无参数时为 0。该选择处理也用于既有函数及局部 callable 提示，保持无上下文请求的原默认行为。

### S03 调用目标文本解析限制了合法接收者

接入共享成员查询后，独立协议验证 `v.element(` 已正常，但 `[1,2].element(`、`v.convert<string>(`、`(if ...).element(` 仍返回 `null`。定位到请求前置的 `resolve_signature_callee`：旧 `receiver_chain_parse` 只接受标识符／部分字面量及成员、调用、下标，不接受括号根或泛型参数，尚未进入成员解析便退出。

保留现有词法范围定位，目标表达式改由已有 Feng parser 解析，再从 AST 的调用目标读取方法名及完整接收者。禁止为数组、if 或泛型单独增加字符串识别规则。显式方法泛参的签名保留方法声明参数，接收者绑定仍正常代入；本次不重新实施核心编译器的调用重载推导。

同时探查的 `(v).element()` 被现有 parser 按转换表达式前缀解析并报 SE0006；该源码不能作为合法分组表达式的正例，本次不修改语法，以合法的 if／match／调用结果分组验证。

### S04 泛型实参中的逗号误计为调用实参分隔符

新增参数位置用例 `value.convert(pair<i32,string>(1,"x")|, 2)`（`|` 表示光标）发现第一个参数被标为第二个。原计数只跟踪 `()`／`[]`／`{}`，将 `<i32,string>` 内的逗号也计入外层实参。

复用当前／修复后 AST 的调用查询和表达式范围，在原词法计数中排除实参表达式内部的逗号。由 parser 决定泛型和比较运算的语法，LSP 不自行猜测尖括号，也不增加类型或表达式特判。

追加分支验证发现，既有 `find_call_hit_expr` 仅搜索 if 条件、match 目标和 try 主表达式，没有进入其分支／catch 块，导致上述位置仍然误计。按现有表达式访问规则补齐通用调用遍历，增加 if／match／try-catch 内部调用用例；不为参数计数再造一套遍历。

### S05 无源码依赖的泛型 fit 作用域

新增 `fit Box<T> { func probe() { self.take(...); } }` 验证中，本地和源码依赖通过；删除依赖源码、只保留 FB 后返回 `null`。`member_fit_scope` 原先只从 AST 类型声明读取 owner 泛参，未适配 FT 的类型声明，导致当前 fit 中的开放 `T` 无法解析。

在同一作用域适配函数中接入已有 symbol 类型声明及其参数身份，之后仍使用共同的结构匹配和签名实例化。原成员补全也复用这一作用域修复；不增加描述符、FT 字段或新的匹配算法。
