# 值对象字面量部分初始化清理修复（已废弃）

> **状态：旧方案已废弃，归档保留；未应用到主工作区。日期：2026-10-16。**
>
> 后续修复以[按异常信息登记构造期清理的新方案](feng-value-literal-conditional-cleanup-bugfix.md)为准。
> 原 patch 已删除，可从 Git 历史恢复；不再按本文方案应用。
> 原补丁基线：第一阶段提交 `65672f13` 加纯 union 布局变更。

## 1. 发现过程与根因

补充 union 异常生命周期覆盖时，构造 `@value Pair`：第一个字段取得托管资源，
第二个字段求值抛异常。第一个字段的终结器没有执行。在 `65672f13` 的旧 union
布局下也已复现，因此不是移除 `_fwd` 引入的问题。

`cg_emit_object_literal` 的值对象路径在逐个初始化显式字段时，没有把正在构造的
完整值登记到 cleanup 链。后续字段求值失败，已经写入的资源没有清理责任方。

## 2. 旧方案与废弃原因

旧方案在显式字段初始化期间，复用 tuple 构造已使用的拥有存储保护机制，登记完整的
aggregate 或具化存储。异常时清理部分构造的值；成功时仅撤销临时保护并转移
原有拥有权，不额外增加 retain／release 对。

原补丁只修改 `src/codegen/codegen.c` 的值对象字面量构造路径。不改变 union 布局、
循环类型识别、异常协议、runtime API 或 DAP。清理保护有必要的登记成本，不能
将“不新增 retain／release 对”解释为没有任何运行时成本。

该方案未利用异常信息，对后续求值可证明无异常的构造也登记保护。现以新方案替代，
在修复资源遗漏的同时，尽可能避免正常路径的不必要开销；新方案尚未实现和验证。

## 3. 原补丁的独立回归覆盖

原补丁包含独立 FCTS 文件及入口注册，保留拆分前的三个失败场景和断言：

- 普通值对象后续字段抛异常：检查已写入资源和已完成 union 的清理次数、顺序。
- 值对象字段包含 union，活动成员又是多资源 aggregate：检查嵌套清理顺序。
- 源码隐藏的泛型 provider 构造部分值：检查参数拥有权和调用方临时值各自清理。

正常 union 构造、完整 union 异常清理留在布局优化用例中。上述缺陷用例当时随补丁
迁移；新方案仍需保留这些场景，不能通过跳过断言或改变预期掩盖问题。
