# Feng 跨 FT 闭合泛型 type/spec 实例去重修复

> 状态：已完成

## 1 问题

同一个跨包闭合泛型 type 或 spec 可能分别由多个已导入 FT 声明路径引用。例如不同模块都引用
`KeyEvent<Widget>` 时，导入后的泛型源声明或类型参数 AST 不保证具有相同指针身份。
当前代码生成仅按 AST 指针和结构相等查找实例，因此可能把同一个逻辑类型注册两次，
最终生成两个同名 C 结构及描述符定义。

callable-form spec 也遵守同一规则。例如同一个闭合
`Func<Box<Value>, Box<Value>>` 同时从跨包方法签名和本包显式类型引用进入时，必须复用
同一个 `UserSpec`，不能生成重复 closure/witness 定义。

## 2 修复规则

闭合泛型 type/spec 实例除现有的快速身份比较外，还必须按其规范化 C 类型标识去重：

- 泛型源使用声明所属 module 与声明名；
- 每个类型参数复用现有的规范化完整类型标识；
- 仅在无开放类型参数上下文的闭合实例间采用该标识去重；
- 开放泛型实例继续保留现有上下文比较，不与闭合实例合并。

规范化标识就是该闭合实例唯一的代码生成符号来源，因此相同标识必须复用同一个
`UserType` 或 `UserSpec`；不同 module 中的同名类型仍保持不同。修复仅影响编译期实例注册与查找，
不改变生成后 Feng 程序的数据布局、ABI 或运行时开销。
