# text-scan 性能优化方案

> **状态：两阶段实现进入逐文件 Review；toolchain 制品变更已临时撤回，审核通过后再生成并全量回归。日期：2026-10-12。**
>
> 人工已批准开始实施，包括 File.readBytes 和 runtime 头文件可见性调整。
> 容量极限策略与极小文件固定成本亦已单独批准；正式实现的验证结果见第 9 节。

## 1. 目标、范围与规范归属

目标是在保持 Feng 原有语义和行为的前提下，使正式 `text-scan` 的整程序耗时
不慢于同机、同轮 Swift，并降低当前读取路径的峰值内存。优化必须服务于实际的
文件读取与通用数组访问，不能依赖评测名称、输入内容、固定文件大小或元素类型特判。

方案分为两个可独立验证的阶段，按以下顺序实施：

1. **std.fs 批量读取：** 消除逐字节 `List.add` 及最后的逐项复制，取得主要收益。
   依赖现有 runtime 能力，不要求修改 runtime 的 API、实现或头文件。
2. **runtime 数组辅助函数可见：** 把少量原有函数体提供给编译生成 C 的 Clang，
   进一步优化扫描循环。runtime 保留静态库分发方式，不新增 `@runtime` API。

本方案不修改 `List<T>`、正式评测程序和扫描算法，不依赖尚未实施的
[`@inline` 方案](feng-inline-dev.md)，不恢复 `@memory`，不新增 LLVM 插件，
不启用 LTO、全局 O3、fast-math，不关闭向量化或安全检查，不更换分配器。

本文记录已批准的开发方案及实施验证。新增行为先写入对应主规范，再实现和测试：

| File 私有成员访问 | [可见性规范](../specifications/feng-visibility.md) |
| 数组复制与只读转换 | [数组扩展规范](../specifications/feng-std-array.md)、[内建类型规范](../specifications/feng-builtin-type.md) |
| 固定容量与内部存储占用长度 | [数组存储设计 §4.2](feng-array-storage-dev.md#42-核心不变量) |

## 2. 已确认的问题与实验依据

### 2.1 主要成本在 std.fs 组织输入数组

优化前的路径见 [File.ff](../../std/std/src/fs/File.ff) 和
[List.ff](../../std/std/src/collections/List.ff)：

```text
std.fs.readBytes(path)
  -> readAllBytes(file)
     -> File.read(chunk[4096])
     -> 对每个已读字节调用 List<byte>.add
     -> List.entries() 创建数组并逐项复制
  -> 原始扫描循环
```

2026-10-12 阶段探针三次正式采样的中位数为：读取并形成数组 **8.843016 秒**，
扫描 **0.282425 秒**，读取约占两阶段耗时之和的 **96.9%**。
生成 C 和 std 发布汇编确认，逐字节路径仍经过下标检查、取址、泛型 List 调用、
后备数组保活及清理登记。`List.entries()` 还执行逐项复制。

这不是磁盘读取本身耗时约九秒，也不是已经证明 List 扩容存在二次复杂度；
当前扩容采用容量翻倍。详细历史归因见
[text-scan 性能调查](feng-text-scan-performance-investigation.md)，本文不重复其堆分析。

### 2.2 std.fs 与 runtime 可见性分别贡献多少

正式 [2026-10-12 基线](../../benchmarks/results/2026-10-12T02-25-58-255Z/report.md)
中，Feng 为 **9.000848 秒／746.52 MiB**，Swift 为 **0.113794 秒／494.19 MiB**。
以下是之后另行执行的同轮诊断对照，不能把两批数字拼成严格配对结果：

| 同轮诊断方案 | 耗时中位数 ms | 最小～最大 ms | 峰值 RSS 中位数 MiB |
| --- | ---: | ---: | ---: |
| 批量读取＋原扫描发码，runtime 函数体仍不可见 | 314.648 | 311.803～317.500 | 245.922 |
| 批量读取＋数组辅助函数体可见 | 108.543 | 104.522～113.625 | 245.922 |
| Swift | 126.021 | 119.446～127.449 | 494.188 |
| C++ | 118.221 | 117.381～122.180 | 245.813 |

这组实验保持 O2、原扫描代码和输出校验，预热两次、正式七次，串行交替执行；
四个版本共通过 36 项既有 text-scan 输入检查。批量 reader 使用 Feng 数组及原
runtime 静态库，以 libc 直接填充数组，不再经过 List。

另一次验证保留 runtime 原函数名，以 GNU `extern inline` 提供原函数体，
同时链接原 runtime 静态库，并将单次读取上限设为 1 MiB：

| 同轮诊断方案 | 耗时中位数 ms | 最小～最大 ms | 峰值 RSS 中位数 MiB |
| --- | ---: | ---: | ---: |
| 批量读取＋原符号的可内联定义 | 105.959 | 102.307～107.720 | 245.906 |
| Swift | 119.332 | 117.240～120.585 | 494.188 |

后一组同样预热两次、正式七次；Feng 通过九项既有输入检查，各完整输入执行均
校验输出。它证明静态库分发与选定函数体可见可以并存，不要求 LTO。

**证据边界：** reader 是临时 C 原型，错误分支使用 `feng_panic`，没有实现正式
Feng 异常传播，也没有覆盖本方案的全部边界。因此数据只证明优化方向有达标空间，
不能保证正式 std 实现恰好得到 0.106 秒。实验尚未完成 Linux 对照。

## 3. 第一阶段：仅修改 std.fs 的读取实现

### 3.1 现有 runtime 已能提供所需能力

| 能力 | 拟使用方式 | 是否修改 runtime |
| --- | --- | --- |
| 分配及管理缓冲区 | 普通 `byte[!]` 数组语法，复用现有数组分配、默认零值及 ARC | 否 |
| 获取长度与首元素地址 | `buffer.length()` 和 `&buffer`，沿用现有发码 | 否 |
| 计算当前写入地址 | 现有 `feng_pointer_move`，在 std.fs 补充 `byte*` 重载声明 | 否；契约与 C 符号已有 |
| 批量读取 | 当前 `c_read` 对应的 libc `read` | 否 |
| 查询剩余大小提示 | 现有 File.stat 能力，加 libc `lseek(fd, 0, SEEK_CUR)` 声明 | 否 |
| 扩容时复制已读前缀 | 在 std.fs 声明 libc `memcpy`，仅复制字节缓冲区 | 否 |
| 收尾时生成准确长度的数组 | 现有 `clone(0, used)`，底层为 `feng_array_slice` | 否 |

`feng_pointer_move(byte*, int)` 的使用已有
[std.process 实例](../../std/std/src/process/Process.ff)。它按字节移动地址；
Feng 指针不直接执行 `ptr + offset`。`memcpy`、`lseek` 属于 C ABI 声明，
不是新增 runtime 能力。指针只用于同步调用，缓冲数组必须在调用期间保持存活。

### 3.2 File 与顶层入口的拟调整

| 位置 | 拟调整 |
| --- | --- |
| `File.readBytes(): byte[]` | 新增公开方法；读取当前位置到 EOF 的剩余字节，不关闭 File |
| File 私有 `readInto(buffer, offset, count)` | 新增内部方法，检查范围，向数组指定区间调用 libc read，并保持现有读失败异常 |
| File 私有剩余长度提示方法 | 查询普通文件的大小与当前偏移；查询失败或不可用时回退到未知长度路径 |
| 顶层 `readBytes(path)` | 保持签名及打开／异常关闭／正常关闭结构，改为调用 `file.readBytes()` |
| `File.readText()` | 改用 `self.readBytes()`，保持原 UTF-8 解码流程 |
| 私有顶层 `readAllBytes(file)` | 由 File 内部实现取代，消除 List 构建路径 |
| `File.read(buffer)`、写入相关方法 | 保持现有接口与行为，不要求改为新 helper 的包装 |
| `File.readLines()`、`List<T>`、数组扩展 API | 不修改实现；readLines 的读取部分随 readText 获益 |

将实现放入 File，是为了访问私有 fd 并保持封装。现行可见性规则不允许同模块
顶层函数访问 File 的 `seal` 成员；不能让顶层 readAllBytes 直接调用私有
readInto。新增公开 readBytes 已随两阶段方案获得实施批准。

### 3.3 批量读取算法

1. 先检查 File 是否打开。尝试取得普通文件的剩余字节数，仅作为预分配提示：
   当前偏移查询使用 `SEEK_CUR` 和零偏移，不跳到文件尾，不重置读取位置。
   查询失败、非普通文件、数值不能安全表示时回退，不因提示不可用而拒绝读取。
2. 创建正常初始化的可写字节数组，以独立的 `used: int` 记录实际已读字节数。
   `used` 不写入 runtime 数组头，不改变普通数组长度或固定容量。
3. 有空余空间时，计算 `feng_pointer_move(&buffer, used)`，向该位置读取。
   `request` 不超过剩余空间及单次读取上限；正数短读继续循环，零返回表示 EOF，
   负返回按现有读取失败行为处理，不自动增加 EINTR 重试语义。
4. 缓冲已满时，先通过一个小缓冲确认是否还有数据，避免恰好填满的文件为了
   判断 EOF 再分配更大的数组。有额外数据才创建更大数组，批量复制原前缀，
   接入已读探测字节，然后替换旧数组。容量变化始终通过新数组迁移完成。
5. 若最终 `used == buffer.length()`，将完全填充且未对外共享的数组转换为
   只读数组返回；该转换不需要复制。若未填满，使用 `clone(0, used)` 返回
   准确长度的独立结果。空输入返回可正常使用的空数组。
6. 任何异常路径都由正常 Feng 生命周期清理缓冲数组。File 方法保持 File 打开；
   顶层路径方法继续保证成功或异常时关闭其创建的 File。

建议的初始策略是：可靠长度提示可用于预分配；无提示时，在确认有数据后从
64 KiB 起步；扩容采用倍增；每次 read 最多 1 MiB。这些是通用文件读取策略，
不是依照本基准大小选择分支。人工已批准此实现方向，实际出现的额外成本仍须
按验收矩阵测量并交人工决策。

容量使用平台 int，文件大小提示仅接受其可表示的剩余长度；倍增前检查范围，
必要时限制到 int 最大值。若缓冲已达此上限且探测仍有数据，抛出现有的
`fs/read-failed`，不新增异常字符串。这一边界处理已单独获得人工批准。

实现时必须在加法、容量增长、类型转换和指针计算之前验证范围，不先计算
可能溢出的表达式。不得在空数组的空 C 地址上做偏移运算或调用 memcpy。
Feng `clone(start, end)` 的第二个参数是终点，runtime slice 的第二个范围参数
是长度，不能混用二者。

该阶段不要求任何辅助函数被内联：原来每字节一次的集合操作变成每块数据少量
函数调用。重建 std 包即可交付本阶段，runtime 静态库可以保持原样。

## 4. 第二阶段：让通用数组辅助函数对 Clang 可见

### 4.1 需要提供的函数体

实施前 [feng_array.c](../../src/runtime/feng_array.c) 中这些实现仅存在于 runtime
静态库，而生成 C 在 [feng_runtime.h](../../src/runtime/feng_runtime.h) 中只能
看到声明。没有 LTO 时，调用方不能利用静态库里的机器码进行跨函数内联。

| 函数或依赖 | 拟处理 |
| --- | --- |
| `feng_array_length` | 在头文件提供原长度访问实现 |
| `feng_array_data` | 在头文件提供原数据地址访问实现 |
| `feng_array_check_index` | 在头文件提供原检查及失败分支 |
| `feng_array_payload_inline` | 提供前三项所需的原 payload 计算实现 |
| 对齐／偏移计算 helper、`FengArray` 布局 | 作为上述实现的依赖集中维护，避免复制布局和偏移常量 |

这使 Clang 能在原生成 C 中展开小函数，优化重复地址计算、长度读取，以及可证明
冗余的检查；不能手动去除必要检查或假设所有调用都能展开。
`feng_array_get_length` 是 std 的契约入口，与 `feng_array_length` 不同，本阶段
不要求把前者及所有 runtime API 都移入头文件。

### 4.2 静态库与头文件共同分发

建议保留现有 `feng_runtime.h` 安装路径，向生成 C 提供
`extern inline __attribute__((gnu_inline))` 定义；runtime 静态库继续提供同名
普通外部定义，用于未内联调用及函数地址。诊断已验证这一组合可以链接和运行，
正式实现仍需验证 O0、多翻译单元及函数地址一致性。

采用 runtime 通用命名，供后续其他小函数复用，不按数组、字符串等模块分别
建立内联机制：

| 名称 | 职责 |
| --- | --- |
| `FENG_RUNTIME_INLINE` | 修饰头文件中的候选函数定义；默认展开为 `extern inline __attribute__((gnu_inline))`，实现模式下展开为空，形成普通外部定义 |
| `FENG_RUNTIME_INLINE_IMPLEMENTATION` | 选择实现模式，仅由下面指定的唯一实现文件在首次包含头文件前定义 |

候选函数的完整函数体只写在头文件中，并统一使用 `FENG_RUNTIME_INLINE`。
新增 `src/runtime/feng_runtime_inline.c`，由它定义实现宏、包含
`runtime/feng_runtime.h`，再取消实现宏。该文件统一生成这些函数的普通版本，
每个目标的 runtime 静态库仅编入一份对应对象文件；原 `.c` 中的重复函数体移除。

其他 runtime `.c` 和生成的 C 使用默认模式：函数体供 Clang 判断是否内联，
未内联调用和函数地址引用静态库中的同名普通函数。实现宏不得作为全局编译选项，
也不得由其他 `.c` 定义，否则会产生重复外部定义。

后续选入其他小函数时，复用同一标记和唯一实现入口，函数体仍只有一个维护来源。
不在 `.c` 与 `.h` 中手工维护两份相同逻辑，不新增 `.inc` 文件，不强制
always_inline，不改变现有调用符号、参数、数组布局或失败分支。

头文件定义需要完整的 `FengArray` 布局。建议将这一结构定义从
`feng_runtime_internal.h` 移到编译器使用的 runtime 头文件，其他内部结构仍留在
原处。生成 C 继续调用 helper，不直接生成字段访问或复制偏移计算。

**这不改变二进制布局，但扩大了布局的编译期可见范围，属于必须 Review 的
runtime 实现边界调整。** 当前 internal 头文件明确禁止生成 C 直接依赖其布局，
不能把诊断中直接 include internal 头文件的做法照搬为生产实现。

编译器、runtime 头文件、runtime 静态库和 std 包必须匹配并重编译。旧 std `.a`
内的调用不会因为消费者换了头文件自动得到优化。数组分配、释放和其他较大函数
仍由静态库提供，本阶段无需让整个 runtime 源码对消费端可见。

## 5. 行为保持与需 Review 的风险

| 边界 | 约束或待验证事项 |
| --- | --- |
| 固定数组与默认零值 | 使用普通初始化数组，扩容分配新数组；不新增 set_length、未初始化数组或 malloc 替换方案 |
| 短读、非 seekable 输入 | 不把短读当 EOF；不能取得长度时仍能完成读取 |
| 文件增长、截断和当前偏移 | 大小只作提示，以实际 read 结果为准；保持从当前偏移读取，不新增并发修改的快照保证 |
| 失败与生命周期 | 保持现有异常及关闭规则；迁移和收尾复制失败时不得丢失拥有者或泄漏资源 |
| 元数据查询成本 | fstat／lseek 增加固定成本，必须测小文件、空文件和大量重复调用；发现开销增加交人工决策 |
| 预分配及内存峰值 | 大小提示过大或随后截断可能导致过度分配；倍增及收尾复制可能同时保留两份数组，不能承诺所有输入都只占一份内存 |
| 容量极限 | 按已批准的 §3.3 检查 int、C ABI 长度与分配尺寸边界，不新增错误码或截断数据 |
| 通用数组访问 | 保留内部空表示、空数组、有效长度与容量的区别，以及越界 panic 行为；不增加元素类型特判 |
| 后端优化影响 | 小函数可见可能改变寄存器、向量化和访存指令选择；须验证 nbody、多种尺寸与地址布局，不能只看 text-scan |

已修正 std.fs 规范中读取失败返回负值的旧描述，使其与原有异常行为一致。
异常契约统一见主规范，本文不另行定义。

## 6. 用例与验收矩阵

新增独立用例，不修改已有断言或夹具；确需修改时先取得针对该处的人工批准。
编译器测试检查发码与链接，FCTS 检查语言行为，std 用例检查文件接口行为。

| 范围 | 必须覆盖 |
| --- | --- |
| 内容与长度 | 空文件、1 字节、包含 NUL 的任意二进制内容、小文件、大文件、返回长度与每个字节正确 |
| 读取边界 | 初始缓冲、单次读取上限及扩容边界的前一字节／恰好／后一字节；多次扩容及最后未填满 |
| 流与大小提示 | FIFO 等无可靠长度输入、连续短读、大小查询失败、提示大于或小于实际读取量、增长与截断；使用可控同步保证测试稳定 |
| File 状态 | 已关闭 File、已读取部分内容后的 readBytes、重复读取到 EOF、File 方法不关闭与顶层方法负责关闭 |
| 错误与清理 | 打开失败、首次及中途读失败、异常继续传播、缓冲及文件描述符清理；分配失败沿用现有可控测试能力，不新增生产故障开关 |
| 文本入口 | readText 的 UTF-8 行为及 readLines 原有行为保持不变 |
| runtime 函数语义 | 内部空表示、零长度、内部存储占用长度与容量不同、正常和越界索引、长度及数据地址与原实现一致 |
| 元素与生命周期 | 平凡值、普通托管引用、含托管槽的聚合值、嵌套数组；默认值、保活、释放次数与顺序不变 |
