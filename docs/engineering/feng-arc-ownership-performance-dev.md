# Feng ARC 所有权传递性能优化方案

## 1. 状态与目标

状态：2026-09-25，已批准范围的实现及验证完成，等待人工 Review 与提交。包含
A-R01／A-R02 的 ARC 优化，以及经指定基线确认并追加授权的 A05／A09 固有 Bug
修复。A11 参数副本释放时机与 A13 条件清理节点寿命回归已修正；最终代码通过
沙箱外 `make test`、五目标 release 和 A09 编译器 ASan 复验，详见 §12。
A10 接收者边界尚未修复，语义及范围待人工决定。批准范围不包含 runtime、ABI、
FT 或循环回收策略变更。

目标：保持可观察生命周期、求值顺序与异常安全，通过准确传递已有所有权和保活
事实，减少不必要的 retain／release、临时拥有者及其清理登记。优化适用于普通
对象、字符串、数组、聚合体、spec／callable 和泛型表示，不按类型名或用例特判。

[空清理边界优化](./feng-cleanup-boundary-performance-dev.md)已在 `03cdb4a4` 独立
交付。本项实施基线冻结为 `10e2403d`（包含该优化）；现状审计最初依据 `a0e0956a`，
实施时重新核对当前代码。测量分别记录 ARC 增益与此前清理边界增益，避免重复归因。

规范归属：

- [对象生命周期](../specifications/feng-lifetime.md)：强引用、释放时机、终结器和循环回收。
- [异常](../specifications/feng-exception.md)、[defer](../specifications/feng-defer.md)：异常退出和清理顺序。
- [ABI 互操作](../specifications/feng-interop.md)：外部调用的借用与生命周期责任。
- [泛型](../specifications/feng-generics-draft.md)：共享体、实化及跨包能力。

这些语言规则不在本文重新定义。候选优化需要改变任何可观察规则时，另提方案由
人工决定，不能把规则变化当成普通性能实现细节。

## 2. 现状与证据边界

| 已确认事实 | 代码依据 | 对后续优化的意义 |
| --- | --- | --- |
| 表达式记录是否持有新获得的 +1 引用 | `src/codegen/codegen.c` 的 `ExprResult.owns_ref` | 已有所有权转移基础，不需要从零建立另一套契约 |
| 部分借用表达式记录身份及拥有路径稳定性 | `ExprResult.managed_identity_is_stable`、`cg_callable_callee_guard_begin` | 已有稳定借用免保活逻辑，不能将它重复计作本次新增优化 |
| 局部初始化可接收已有所有权，借用结果才额外 retain | `cg_emit_initialized_local_binding` | 应检查后续转换／合流是否丢失事实，而非统一删掉绑定的 retain |
| 多个返回路径在借用结果上先 retain，再清理作用域 | `cg_emit_return`、`cg_emit_return_expr_result` 及共享体返回发码 | 存在研究局部所有权向返回值转移的具体入口；是否冗余需要逐路径证明 |
| retain 使用原子加；release 使用原子减并可能进入循环检测锁及候选处理 | `src/runtime/feng_object.c` 的 `feng_retain`、`feng_release` | 少一次有效消除可能减少计数以外的工作，但收益必须实测 |
| 清理登记与局部所有权相连 | `Local`、`Scope`、`cg_register_local_for_cleanup`、`cg_release_scope` | 删除拥有者时必须同步处理所有出口，不能留下错位的 LIFO 节点 |

当前没有足够的对象密集业务基准，不能断言 ARC 是 Feng 的最大性能瓶颈，也不能
承诺百分比。此前无 ARC 正常路径的异常性能差距不由本方案解释或验收。

## 3. 范围与分层

优先在 Feng Codegen 的现有所有权与作用域抽象中实现；如需补充局部数据流事实，
保持为编译期内部信息，统一覆盖求值、调用、转换、合流及退出，避免每种语法分别
加一套规则。暂不引入新公共 IR、语义层 API 或跨包所有权协议。

通用 `llvm-c-eh` 插件不识别 `feng_retain`／`feng_release`，不承担 Feng 对象生命
周期优化。公开插件协议保持不变；本项也不新增专门的 LLVM ARC 插件。

不修改 runtime 的引用计数算法、原子性、内存序、循环检测触发策略、对象布局、
函数签名或调用 ABI；不新增语言层 move／borrow 语法，不改变已有参数和返回约定。
不通过提前析构、延迟释放、改变捕获方式或允许悬空借用换取性能。

空边界的分析与删除统一由[清理边界方案](./feng-cleanup-boundary-performance-dev.md)
定义。本项只确保最终所有权及实际资源登记能够被该分析正确消费，不复制一套
marker 优化规则。

## 4. 统一证明条件

### 4.1 所有权与借用事实

复用现有表达式及局部信息，区分：

- 当前表达式自身拥有的一份 +1 引用。
- 已由某个局部／结果存储拥有、表达式当前只是借用的值。
- 由其他拥有者保活的借用，以及该拥有者在使用区间内是否稳定。
- 已转移或已释放的所有权，以及尚未弹出的清理节点。
- 开放泛型／聚合体中尚不能静态确定的生命周期操作。

局部存储拥有一份引用，并不要求整个对象的引用计数为 1。需要证明的是这份所有权
能否合法转移，而不是读取运行时 refcount 再决定。对象身份相同也不代表两个表达式
携带同一份所有权，不能只比较生成的 C 表达式字符串。

### 4.2 每次消除必须保持的性质

1. 原拥有者或替代拥有者覆盖所有使用，包括后续实参求值、隐式转换、回调和异常退出。
2. 正常路径和异常路径的每份所有权都准确转移或释放一次，没有泄漏、重复释放或悬空引用。
3. 不跨越可改变对象／存储身份的赋值、别名写入、闭包捕获、外部调用或未知回调进行无证明合并。
4. 最后一个强引用的消失时机、终结器／defer 顺序、复活以及循环回收行为满足主规范。
5. 源存储被清空或清理动作被移除时，没有后续源码、defer、别名或捕获依赖它的原值。
6. 调试位置及用户局部的可观察值保持正确，O0 不能通过隐藏局部或缩短源码生命周期获得收益。

缺少事实时保留当前操作，不增加运行时所有权猜测，也不把保守保活标为冗余。
Feng 的 release 可触发用户终结器及循环回收，不能照搬“任意 retain／release 对
等价于空操作”的假设；循环候选和回收相关行为若无法证明等价，同样保留。

## 5. 优化路线

### 5.1 保持已有 +1 的传递，避免中途重新建立拥有者

审计初始化、转换、字段／spec 投影、表达式合流、临时物化和返回之间的所有权
传递。优先修正可证明的事实丢失，使后续消费者直接接收已有所有权。

if／match／try 各分支须分别说明结果的所有者及存储归属；不能只把合流结果的
`owns_ref` 设为 true。如果值已登记在某个局部的清理表中，转移时必须同时转移
对应责任。聚合体及开放存储须沿用现有描述符和复制／转移规则。

### 5.2 在作用域结束处转移局部所有权

以下是待验证的候选形态，不是按字符串类型设置优化分支：

```feng
func makeText(input: string): string {
    let result = input + "!";
    return result;
}
```

局部 `result` 已拥有结果，返回当前按借用结果处理时，会先为返回值 retain，再
在作用域退出时 release 局部。若满足 §4，可以将局部已有的那份所有权转交给
返回结果，免除这对计数操作；调用者仍按既有约定取得 +1。

转移不能机械地变成“return 前清空源变量”。例如 defer 读取／修改该变量、它已
被闭包引用捕获，或退出清理还可能产生异常时，需要同时证明源值的可见性和返回
结果的异常清理责任。不能证明则保留原路径，不改变求值与释放顺序。

借用参数、对象字段或调用者存储不能仅因出现在 return 中而被夺走所有权；若要
返回一个独立强引用，仍须建立现有契约要求的所有权。聚合返回亦不得在未证明时
省略字段级 retain 或复制。

### 5.3 扩展有证明的短期借用

对于只需要在有限求值区间存活的中间值，若已有拥有者覆盖整个区间，且对象身份
与保活路径不会被后续求值／回调破坏，可复用该借用，减少额外的临时 retain、
release 及清理登记。

复用 `managed_identity_is_stable` 的真实含义，不把 `let`、只读访问语法或参数
形式直接当成不逃逸／稳定证明。被调者仍按既有契约存储、捕获或保留引用；不为
跨包调用发明隐含的“不保留参数”承诺。

### 5.4 同步精简临时清理

一份编译器临时所有权被完全消除后，它独占的清理节点也可消除；如果只是提前
转移所有权，节点仍留在 LIFO 链中，则须与既有 pop-only 等状态协同处理。
正常落出、早退和异常退出共用同一所有权事实，不留下多 pop／少 pop。

第一轮不改变仍然必要的清理链表示。不得为了减少某次 release 而新增堆分配、
原子操作、锁或运行时分支；存在性能取舍时交人工决定。

## 6. 泛型、跨包和边界调用

函数、类型和方法泛参共享体的所有权证明须覆盖全部允许实参；托管指针、聚合体
和 trivial 值按照现有描述符处理。只在某个闭合实例成立的事实不得标到共享定义。

跨包生产者／消费者保持已有参数与返回约定，包括间接 callable、spec witness
及地址形式桥接。只优化调用方自身有证据的重复操作；未导出的事实不能猜测，也
不要求用户暴露包源文件才能保持正确性。

C 互操作遵循既有借用、回调与生命周期约束。外部函数、副作用不明的目标及可
重入回调均不得被默认视为稳定借用区间。若优化必须新增 FT 信息或改变边界约定，
单列需求、替代方案和兼容性影响，由人工决定。

## 8. 性能基准与验收

先建立对象密集且结果可校验的基准，分别覆盖局部构造并返回、连续结果传递、
短期借用、表达式合流、泛型／跨包、数组／聚合体及无法优化的保守路径。使用动态
输入，避免基准被常量折叠；前后使用相同的业务对象规模，源码要求的构造、存活与
最终销毁事件保持一致。被消除的是冗余计数操作，不能通过少做业务工作制造收益。

测量组织复用[现有性能基准方法](../../test/exception_perf/README.md)，但使用
适合 ARC 的独立用例，不用纯标量数据代替 ARC 收益。每项记录：

- 减少的 retain／release、临时拥有者与清理登记，以及仍必须保留的原因。
- O0／release、同翻译单元／跨包的耗时、栈／代码大小与峰值存活资源。
- 正常路径和异常退出的结果、终结器／defer 事件顺序及完整资源回收情况。
- 单项与组合结果；如前序清理优化已交付，区分本项增益，避免重复计算。

诊断插桩可用于核对执行次数，但正式性能测量使用未插桩产物，不给产品 runtime
增加统计 API。普通 C++ 的手动生命周期或 `shared_ptr` 不自动等价于 Feng 的 ARC
与循环回收，未经语义对齐不据此宣布接近／超过 C++。

每项收益必须有可复现证据，无法证明的场景保持正确且不新增成本。不得把减少
计数操作等同于必然整体加速。完整验收包括沙箱外 `make test`、显式完整 std／FCTS
release 回归，以及五目标的编译／执行记录；性能结论只使用对应平台的原生测量。

### A02：统一所有者来源与出口转移（2026-09-25，实施设计）

现有 `owns_ref` 只能说明表达式自己是否拥有引用，不能说明借用来自哪个局部。
为表达式补充“所属 Scope＋局部索引”的编译期来源，避免把 C 文本相同当作同一
拥有者，也避免局部数组扩容使指针失效。用户局部、物化结果及 if／match／try
结果槽都使用同一来源记录；投影或表示变化不能证明同一份所有权时清除来源。

统一使用两种消费方式：

1. 作用域出口转移：结果来源确实属于本次退出范围，且不存在捕获、可观察的延后
   访问、条件清理或未知布局时，返回存储接收现有所有权。清理仍按原位置弹出及
   清空源槽，仅省略被转移引用的 release。此事实仅属于当前发码出口，不写成
   其他分支也已转移的全局状态；异常发生在转移前仍按原登记清理。
2. 稳定拥有者下的借用：不可变绑定或只读转换已有明确拥有者覆盖整个使用区间时，
   复用其保活。用户局部仍保留原 C 存储及调试映射，不删除或提前释放原拥有者；
   聚合体还必须证明受管槽不会被重新赋值。捕获、可变来源和未知回调能够改变的
   存储继续按原实现建立独立引用。

消除计数前，按既有描述符事实证明该非归零 release 不进入循环候选路径；聚合体

### A07：A05 调用实参固定方案（2026-09-25，已授权实施）

人工指定 `10e2403db7ea0f7a9ca6f947c5ecb0a02af3895c` 复验，并授权在确认固有
Bug 后修复及增加覆盖。该版本原始 Codegen 源码 SHA-256 与冻结基线构建输入一致
（`d349be228396010fe51b85963cd9b1e536563a3a180fbae37ba606b789e0bbad`），其余
产品源码未变；重新构建最小程序，基线和当前版本均退出 `6`，确认是固有 Bug。
表达式主规范规定实参从左到右求值，正确预期仍为 `5`。按此授权实施下面的通用
修复，正确性成本与 ARC 消除收益分开记录。

**根因与入口。** `cg_emit_registered_call` 对借用的普通受管实参、标量等直接
拼入 `ar.c_expr`；该字符串可能仍指向可变源存储，也可能包含尚未执行的 C 调用。
`cg_shared_callable_argument_expr_dup` 的非地址路径同样可能直接复制表达式文本；
部分泛型调用和变参路径先收集全部 `ExprResult`，之后才生成实参表达式。因此仅
在最终参数拼接处补临时变量已经太晚，也不能仅修复某一种调用语法。

**统一调用准备。** 增加 Codegen 私有的“已求值调用操作数”抽象，记录固定后的
值／地址、表示信息和必要的临时保活责任。调用目标先固定，每个显式实参都必须
在下一个实参开始前完成求值、必要转换和固定；最终 ABI 参数拼接只消费这些结果。
已有物化、共享体描述符复制、稳定借用事实和 callable callee guard 的清理逻辑
应复用或统一，不并列添加另一套仅用于普通对象的规则。

| 表示或角色 | 固定规则 |
| --- | --- |
| 标量、enum、裸指针 | 固定本次求值的值；不能在实际调用时重新读取可变来源或重新执行子调用 |
| 普通受管引用、string、数组、callable | 固定引用身份；已有所有权直接使用，已证明的稳定拥有者可继续借用，否则建立临时强引用 |
| tuple／value／对象形态 spec | 按既有值语义固定完整值及其受管槽；不能把复制地址当作复制值 |
| 开放泛参、描述符大小聚合体 | 复用现有描述符、存储及复制规则；未知表示不能免除必要保活 |
| 方法隐式 self | 固定目标身份或接收者地址，但值类型 self 仍指向原存储，不改成显式参数式复制 |
| C ABI 参数 | 先固定 Feng 实参及所需 ABI 值，再传递既有 ABI；裸指针的来源保活仍遵循互操作主规范 |

**生命周期。** 新增保护只覆盖后续实参求值及实际调用。调用完成并固定返回结果
后，按逆序释放本次新增的保护；求值或调用抛出时使用既有清理链释放一次。必须
先执行调用再释放保护，不能在返回的 C 调用表达式尚未执行时提前清理。既有拥有
临时值的释放规则保持不变；本轮不改变调用者／被调用者的参数和返回契约。

**接入范围。** 普通／跨包函数、实例／静态／fit 方法、构造函数、动态及计算所得
callable、object-form spec 调用、函数／类型／方法泛参共享体、普通变参及
`...array`、extern／ABI 调用都经由同一准备规则。调用本身继续使用原分派和发码
路径，不重新设计整个调用系统，不新增 runtime、ABI、FT 或插件协议。

**正确性成本。** 不稳定受管借用可能比错误基线多一次临时 retain／
release 及对应清理登记；未知聚合体／泛参可能需要已有描述符驱动的独立值复制。
未被捕获的局部引用，若后续操作数仅为无副作用的直接读取／字面量，原局部拥有者
也能覆盖调用，无需额外保活；这是按存储可变性与求值效果证明，不按函数名特判。
标量固定可能增加 O0 局部读写；release 可消除其中冗余存储，但不能预先承诺完全
无成本。已有 +1、可靠稳定拥有者及已完成固定的操作数避免重复保活。新增正确性
成本与 A06 的 ARC 消除收益分别计量，不能相互掩盖。

**验收。** 扩充本轮新建 Codegen／FCTS 测试，保留 A05 的正确预期 `5`；覆盖值和
引用、字段／下标、后续赋值／回调、泛型与仅二进制跨包、变参、接收者、实参或
调用抛出，以及终结器顺序。分别验证 O0／O2／O3、既有 sanitizer 和 DAP 行为，
然后重新测量性能、执行沙箱外 `make test` 及五目标完整 std／FCTS release。

### A13：最终 release FCTS 崩溃（2026-09-25，已修正并验证）

最终 `make test` 重跑通过后，macOS release std 为 607／607，但 release FCTS
在既有泛型约束实参用例组中 signal 11。A11 前同一完整 release 集合曾通过；先
保存 `final-regression/macos-arm64-fcts_bin-release.log` 与当前产物，核查新增
条件受管清理节点在优化后的生命周期及实际崩溃调用栈，未确定根因前不宣称交付。

生成规则审计发现本轮引入的确定错误：条件保护调用普通登记 helper，把
`FengCleanupNode` 声明在 `if (kind == managed)` 内，却在离开该 C 块后才消费、
释放该节点；C 自动变量已结束寿命，宿主优化器可复用它的栈槽。LLDB 现场清理链
节点已指向无效地址。修正复用现有条件清理的存储规则：subject 和节点声明都在
外层实际生命周期内，仅 retain／push 与配对释放受条件控制。保持原节点数、原
条件与 ARC 次数，不增加 runtime 能力或改变语言语义；补充生成 IR 的寿命验证。

修正后同一 macOS release FCTS 为 1591／1591，记录为 `a13-fcts-release.log`。
原发码的前端 IR 明确在 `cleanup_push` 后、受保护调用前执行节点的
`llvm.lifetime.end`（`a13-before-frontend.ll`）。新增 Codegen 断言检查节点的
存储寿命覆盖调用；允许前端对整函数存活的 alloca 不生成 lifetime 标记，若存在
标记则必须先开始、后结束。首次新增断言误要求所有节点都存在显式标记，已按此
IR 语义修正；不变更任何既有断言。最终代码已重新通过完整入口及五目标 release。
完整 Codegen 已通过（`a13-codegen.log`）；重新构建 ARC 基准并通过所有行为校验，
O0／O2／O3 的同单元与跨包共九份非 DWARF 汇编（含 EH 表）均与测量版本相同，
记录为 `a13-assembly-comparison.txt`，因此无需把同一发码重复计时作为新收益。
