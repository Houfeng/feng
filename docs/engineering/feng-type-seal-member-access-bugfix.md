# type seal 成员访问与同名重载修复

> 状态：已完成（completed）

## 1 问题

type 的 `seal` 成员按 `docs/specifications/feng-visibility.md` 属于类型私有，只允许
所属 type 自身访问。当前语义分析却以声明 module 是否等于使用 module 判断私有成员
可见性，导致同 module 中其他 type 或顶层函数可以非法访问 `seal` 字段、方法、静态
成员和构造函数。

成员表达式的预检查还会按名称返回第一个成员。如果第一个同名方法为不可访问的
`seal` 重载，即使另一个可见重载能够唯一匹配实参，也会提前报告 `AE0308`。例如：

```feng
open type Painter {
  seal func draw(styles: Style[]) {}
  func draw(styles: Style...) {}
}
```

`Style[]` 与 `Style...` 是合法的不同签名。外部调用 `painter.draw(Style.bold)` 应排除
第一个不可访问候选并选择第二个公开候选。

## 2 目标行为

1. `seal` 实例成员、静态成员和构造函数只允许所属 type 自身访问。
2. 是否同 module、同包或跨包不改变 type 私有成员的可见域。
3. `fit` 不是目标 type 自身，不能访问目标 type 的 `seal` 成员。
4. 方法调用先过滤不可访问候选，再按现有重载规则解析。
5. 不可访问的同名重载不能遮蔽可见重载；同名候选全部不可访问时仍报告现有访问错误。
6. 不改变数组与变长参数的既有签名及冲突规则。

## 3 实现

### 3.1 统一 type 成员可见性

语义分析的成员可见性判断改为接收成员所属 type：

- 非 `seal` 成员保持现有公开行为；
- `seal` 成员仅在 `current_type_decl` 等于所属 type，且当前不在 `fit` 方法体时可见；
- 不再以 provider module 与当前 module 相等作为 type 私有成员的放行条件。

type 字段初始化器也属于 type 自身实现。解析字段初始化器时设置所属 type 上下文，
但不改变 `self` 在普通字段初始化器中的既有约束。

### 3.2 可见重载查找

实例和静态成员表达式的预检查不再以第一个同名成员决定整个成员名的可见性：

- 存在任一可访问的同名成员时，允许后续调用或方法值解析继续处理；
- 方法调用与方法值解析继续遍历同名候选，并仅保留可访问候选；
- 存在同名成员但全部不可访问时，保留现有 `AE0305`、`AE0307` 或 `AE0308` 诊断；
- 完全不存在同名成员时，保留现有“成员不存在”诊断。

### 3.3 标准库内部访问适配

标准库中需要由协作类型读取的内部状态不再依赖同 module 的 `seal` 字段访问：

- `Promise<T>` 使用 `seal let _state` 保存状态，并通过 `state()` 提供读取；
- `Mutex` 以只读的 `open let handle` 暴露原生句柄，供 `CondVar` 等底层同步原语使用。

## 4 测试

### 4.1 编译器语义测试

新增用例覆盖：

- 同 module 的其他顶层函数访问 `seal` 实例字段、实例方法、静态成员和构造函数，均被拒绝；
- 所属 type 自身访问上述 `seal` 成员保持合法；
- 不同 module 调用公开重载时，不受先声明的同名 `seal` 重载遮蔽；
- 同名候选全部为 `seal` 时仍报告不可访问。

### 4.2 FCTS

在 `fcts_bin` 中新增独立 provider module 和消费用例，运行时验证：

- type 自身可通过公开方法读写私有状态；
- 跨 module 调用只匹配公开签名的同名重载成功；
- 数组版本与变长参数版本保持各自行为。

编译失败行为由语义测试覆盖；FCTS 只验证能够进入可执行测试套件的正向语言行为。
