# C IR 函数契约传递协议

> **状态：已终止 · 已归档。日期：2026-09-29。**
>
> 本轮函数契约表及其插件处理已撤销。下文仅保存历史协议，不是现行接口或
> 待迁移计划；不得据此向 `llvm_c_eh` 增加通用函数属性。
> 终止范围与历史验证见[归档开发方案](feng-memory-access-inference-dev.md)。

终止前状态（历史记录）：2026-09-29，原实现的模块归属已被否决，待迁移。`llvm_c_eh` 仅负责 C 与
unwind 异常转换，不承载通用函数属性协议。下述版本 1 表格式是尚未移除的实现记录，
不是后续接入方案；修正要求以[开发方案 §6.2](feng-memory-access-inference-dev.md#62-发码链路必须实际传递信息)为准。

本协议是编译期元信息，由 llvm-c-eh 的独立 FunctionContracts 模块消费；没有运行时
API，不依赖 Feng 名称、类型、FT 格式或异常类。Feng 侧规则见
[内存访问规范](../specifications/feng-memory-access.md)。

头文件 `llvm_c_eh.h` 提供版本 1 的 `__llvm_c_eh_function_contract`。生成端声明
一个 internal、constant、used 的数组 `__llvm_c_eh_function_contracts`，每项依次为：
原生函数指针、版本 u32、读区域 u32、写区域 u32、未知区域 u32、标志 u32、保留零 u32。
区域位 1 为参数可达内存，位 2 为全部其他内存。标志位 1 为无向外异常的源级候选，
其他位须为零。没有记录时不生成空表。函数指针只用于身份，不改变调用 ABI。

消费端须拒绝版本、布局、权限位、目标身份或存储属性错误，以及对表的运行时使用；
表只允许由 LLVM used 列表保留。必须先验证全部记录，再设置属性并删除表及其保留项。
消费后执行一次全局死代码清理，防止 O0 下“仅被元信息引用”的私有函数留下新链接
依赖；实际导出、地址逃逸及其他 used 保留的目标不受影响。
旧插件因不认识保留名而拒绝新表，旧头文件因缺少版本宏而无法编译新生成代码。

同一原生函数的多项访问权限按区域取并集。unknown 对应区域允许读写；其他区域
包括 LLVM 的 inaccessible、errno 和目标状态。新事实与 LLVM 已有事实取交集。
内存属性不得附加 nounwind、willreturn、speculatable、noalias 或 nocapture。

异常候选仅将有函数体的函数送入现有原生不展开证明。无函数体、可替换定义、未知
调用、尚未闭合的递归都不能仅由候选获得 nounwind；源级捕获也不能替内部调用担保。
协议不描述“必定返回”。无内存访问的无限循环仍须保留。

验证包括 O0/O2/O3 的四种权限及区域组合、unknown、函数别名、多记录、表清除、
非法输入、读写别名、无源码声明、不会返回的函数、局部捕获与未知原生异常；
正式 Feng 路径另覆盖 FT 导入、隐式 ARC／defer／浮点余数与源码行为。
