# Feng 官方网站规范

> **禁止在此文档中描述站点外观，这个文档是用来说明官网包含的内容和逻辑的。**

> 本文档定义 Feng 官方网站的目标、内容范围、信息架构、用户路径与交互逻辑。语言规则、CLI 规则与包格式规则仍分别以对应规范文档为准；官网只做面向访客的介绍性表达，不承载仓库导览职责。

## 1 目标与边界

- 官网实现位置固定为 `website/` 目录。
- 官网面向首次了解 Feng 的开发者，核心任务是让访客认识 Feng、看到语言形态、完成安装，并进入文档、插件页面或开源仓库。
- 官网采用静态站点实现。首页文件可直接预览；用户手册网页由构建工具从 Markdown 内容生成。
- 官网首页支持的语言及文档回退规则见 §3.1，英文为默认语言；用户手册仍只提供英文与简体中文。
- 官网首页不得承担仓库结构说明、目录导览、编辑器实现说明等仓库级内容。
- 官网首页只包含完成上述核心任务所必需的内容；非必要的功能清单、数据指标与工作流展开不得进入首版。
- `website/` 作为网站根目录，页面内不得直接链接到 `website/` 之外的父级或同级其他目录；若后续需要扩展内容，应将页面或资源落到 `website/` 内部。
- 面向用户的手册内容以 `docs/manual/` 为唯一来源，生成后的网页位于 `website/docs/`，不得直接修改生成结果。

## 2 内容权威来源

- 语言定位、特性总览、关键词与文件扩展名说明以 `docs/specifications/feng-language.md` 为准。
- CLI 命令与项目工作流以 `docs/specifications/feng-cli.md` 为准。
- 编译器与构建工具职责分离以 `docs/specifications/feng-build.md` 为准。
- 包格式、`feng.fm` 与 `.fb` 分发语义以 `docs/specifications/feng-package.md` 为准。
- 在线安装脚本的入口、唯一源文件与发布规则以
  `docs/engineering/feng-release-and-install.md` §7.2 为准。
- 官网中使用的示例代码、命令与清单片段必须能在现有规范或示例文件中找到依据。
- 用户手册网页的内容与章节关系以 `docs/manual/en/` 和 `docs/manual/zh-CN/` 为准；网站构建逻辑不得复制或重新定义手册正文。

官网可以对上述内容做压缩表达，但不得重新定义规则，也不得把“去仓库哪里看”作为首页主叙事。

## 3 首页信息架构

首页采用单页结构，按以下顺序组织：

1. 顶部导航：包含 Feng 品牌入口、`安装`、`文档`、`插件`、`开源`、`语言` 与主题切换。`安装` 指向首页唯一的安装内容；`文档` 按 §3.1 进入用户手册；`插件` 指向 `https://marketplace.visualstudio.com/items?itemName=houfeng.feng-language`；`开源` 指向 Feng 官方 GitHub 仓库；`语言` 展开语言选择菜单，并在对应语言首页之间切换；主题切换位于语言选择之后，在浅色与深色主题之间切换。小窗环境允许收起导航入口，展开后必须提供同一组菜单项、语言选择与主题切换能力。
2. Hero：传达 Feng 的核心定位，包含主标题以及 `AI 友好`、`显式契约`、`静态类型`、`自动内存管理`、`编译型`、`跨平台`这一组定位关键词。Hero 同时承担开始使用 Feng 的入口，安装内容使用 `快速安装` 作为标题，只出现一处在线安装命令，并提供复制命令、支持平台说明与手动下载入口。开源入口由顶部导航提供，不在安装内容中重复；首页不得在后续区块重复安装命令或另设安装区。
3. 代码示例：通过标签切换展示多个简短、可读且具有 Feng 语法辨识度的示例，使访客无需阅读文档即可了解语言表层形态。首版包含 `你好世界`、`定义类型`、`声明契约`、`定义泛型`、`循环控制`、`条件分支`、`模式匹配`、`异常处理` 八个示例。`声明契约` 分别展示对象契约、函数契约、联合契约与交叉契约，并展示具体类型通过 `fit` 满足对象契约；`循环控制` 同时展示三段式 `for`、`for/in` 与 `while`；`条件分支` 和 `模式匹配` 分别展示对应的语句用法与表达式用法；`异常处理` 展示 `throw`、作为语句的 `try/catch` 与作为表达式的 `try/catch`。每个标签对应一段只围绕该主题编写的代码，并使用必要注释说明关键语法意图；示例区不附加解释性标题或说明段落。
4. 页脚：仅保留项目名称、必要的版权信息及 `开源` 入口，不扩展仓库导览或重复页面主体内容。首页不另设文档与开源介绍区块，避免与顶部导航、Hero 和页脚重复。

用户手册网页包含以下内容与逻辑：

1. 手册入口：`/docs/` 进入默认英文手册；英文与简体中文手册分别位于 `/docs/en/` 与 `/docs/zh-CN/`。
2. 章节导航：章节顺序与分组由网站构建配置统一维护，章节名称读取对应语言文档的一级标题；当前页面需要在章节导航中标识。
3. 正文：完整呈现对应 Markdown 文件的标题、段落、列表、表格、引用、链接与代码块，不在模板中复制正文。
4. 页内导航：根据当前文档的二级与三级标题生成页内锚点；没有相应标题时不生成空导航。
5. 前后章节：按当前语言的章节顺序提供上一篇与下一篇入口，不跨语言跳转。
6. 语言切换：切换到另一语言中相同相对路径的页面；对应翻译不存在时构建失败，不回退到其他语言。
7. 主题切换：与官网首页共用主题状态，用户在首页或手册中作出的选择对另一部分同样生效。

首页不得包含关键词数量、保留字数量、注解数量等数据指标，不得包含扩展特性清单、完整 CLI 工作流、语言主题目录或 Manifest 示例。语言能力如需在首页辅助表达，只允许使用少量短语，不展开为完整功能说明；详细内容由后续文档承载。

### 3.1 首页语言与文档回退

首页提供以下语言版本：

| 语言 | `lang` | 首页文件 | 语言菜单名称 | Hero 标语 | 文档地址 |
| --- | --- | --- | --- | --- | --- |
| 英文 | `en` | `index.html` | `English` | `Clarity by design` | `/docs/en/` |
| 简体中文 | `zh-CN` | `index-zh.html` | `简体中文` | `自有章法` | `/docs/zh-CN/` |
| 西班牙语 | `es` | `index-es.html` | `Español` | `Claridad por diseño` | `/docs/en/` |
| 巴西葡萄牙语 | `pt-BR` | `index-pt-br.html` | `Português` | `Clareza por design` | `/docs/en/` |
| 日语 | `ja` | `index-ja.html` | `日本語` | `明快さを設計する` | `/docs/en/` |
| 俄语 | `ru` | `index-ru.html` | `Русский` | `Ясность в основе` | `/docs/en/` |
| 德语 | `de` | `index-de.html` | `Deutsch` | `Klarheit mit System` | `/docs/en/` |
| 法语 | `fr` | `index-fr.html` | `Français` | `Clarté intégrée` | `/docs/en/` |

- 每个首页必须完整使用对应语言，包括页面元信息、导航、正文、无障碍文本与交互反馈。
- 首页语言通过语言菜单手动切换，不增加自动跳转逻辑。
- 没有对应用户手册的首页语言直接链接英文文档，链接文本仍使用当前首页语言，不额外标注英文。
- 首页语言与用户手册语言分别维护。不得仅为增加首页语言而修改用户手册构建配置中的支持语言。
- `website/app.js` 在文件顶部维护按 `lang` 分组的界面文案字典，复制反馈、主题名称及主题操作提示均从该字典读取；未识别的语言回退到英文，不再使用“英文与非英文”二分逻辑。

## 4 用户路径与交互逻辑

- 首次访问者应能依次完成三个认知步骤：理解 Feng 的定位、看到语言代码形态、选择安装或继续进入文档、插件页面与开源仓库。
- 顶部“安装”入口定位到首页唯一的安装内容；“文档”按 §3.1 进入对应用户手册；“插件”进入 Feng 的 VS Code Marketplace 页面；“开源”进入官方 GitHub 仓库。
- 语言菜单使用 JavaScript 处理菜单间互斥、点击外部关闭、`Escape` 键关闭与焦点返回；JavaScript 不可用时仍可通过原生语义展开。
- 主题首次访问时跟随系统浅色或深色偏好；用户手动切换后在当前设备保存选择，后续访问优先使用已保存的主题。桌面窗口与小窗菜单中的主题切换操作保持同步。
- 小窗导航默认收起，用户可以通过“菜单”操作展开或再次收起；选择菜单项后允许自动收起。导航展开能力不得依赖 JavaScript。
- 复制安装命令成功或失败都应使用当前首页语言给出反馈，反馈结束后恢复原操作文本。
- 复制操作优先使用浏览器 Clipboard API，在不可用或被拒绝时使用兼容性回退；回退失败时不得伪造成功状态。
- 代码示例标签支持点击切换；使用键盘操作时，方向键用于切换相邻标签，`Home` 与 `End` 分别切换到首个与末个标签。
- 手动下载入口始终指向官方 GitHub Releases，不在官网复制或维护发布文件。
- JavaScript 不可用时，语言定位、安装命令、支持平台、全部代码示例、文档入口、语言菜单和所有链接仍应完整可读；主题跟随系统偏好。
- 桌面端与移动端提供相同的内容、操作和访问顺序，不因设备类型隐藏核心信息。
- 手册中的站内 Markdown 链接在构建时转换为对应网页 URL；生成页面不得保留指向源码 `.md` 文件的访问链接。
- 手册页面的语言切换、章节导航、页内锚点与前后章节入口均由生成结果确定，不要求作者在正文中维护网站专用链接。

## 5 实现约束

- 页面需兼顾桌面与移动端访问，所有核心内容和操作在两类设备上保持一致。
- 页面文案必须以“语言介绍”为中心，不出现仓库目录导览、仓库模块清单或实现组件罗列。
- 页面文案必须面向最终用户，优先回答“用 Feng 能做什么、为什么值得用、如何开始”，避免“网站该回答什么”“先看实现再看语言面”这类自指或面向实现者的表达。
- 每个首页使用与其 `lang` 一致的界面文案；Feng、GitHub、macOS、Linux、Xcode、Command Line Tools 与代码等品牌名或技术名词保留原文。
- 网站内导航与资源引用必须留在 `website/` 根目录范围内。
- 在线安装命令必须使用 `https://feng-lang.com/install.sh`；页面不得维护安装脚本副本，也不得重新定义脚本行为。
- VS Code Marketplace、GitHub、GitHub Releases 与 GitHub Issues 使用各自的官方外部链接；除这些明确的外部入口外，首页不增加社交媒体、社区或第三方平台链接。
- 首版脚本只用于复制安装命令、代码示例标签切换、小窗菜单选择后的自动收起、语言菜单的交互增强与主题切换。导航、语言菜单、全部代码示例与安装说明在 JavaScript 不可用时仍须完整可读、可访问。
- 页面必须使用语义化 HTML，具备清晰的标题层级，支持键盘操作并满足无障碍要求。
- `website/` 不维护专用自动校验脚本，页面内容、链接、跨设备可用性与交互质量由人工 Review 验收。
- 官网静态资源命名应清晰稳定，便于后续继续扩展多页结构。
- 网站构建工具及其依赖配置统一放在 `website/`；`website/package.json` 与锁文件需要提交，`website/node_modules/` 不得提交。
- 用户手册使用 Eleventy 生成。生成内容写入 `website/docs/`，该目录不得提交；每次正式构建前必须清理旧的生成内容，避免已删除页面残留。
- 本地预览以 `website/` 为站点根目录，同时提供首页与已生成的用户手册；手册内容或模板变化后需要重新生成并刷新预览。
- GitHub Pages 部署物必须通过临时 staging 生成。CI 在复制 `website/` 到 staging 前生成 `website/docs/`；除生成的用户手册外，staging 仅按 `docs/engineering/feng-release-and-install.md` §7.2 注入在线安装脚本。
- 自定义域名由仓库 GitHub Pages 设置管理，Actions 部署物不维护 `CNAME` 文件。

## 6 人工 Review 要求

官网变更由人工 Review 验收，不要求通过 `website/` 专用脚本执行自动验证。Review 至少覆盖以下内容：

- 首页 HTML 正确引用自身 CSS、JavaScript 与资源文件，页面内不存在失效引用。
- 首页包含顶部导航、Hero、多个代码示例和页脚；文档、插件、开源、语言选择与主题切换由顶部导航提供，不另设重复介绍区块。
- 在线安装命令只出现一次并使用 `https://feng-lang.com/install.sh`；手动安装入口指向官方 GitHub Releases。
- 首页不包含关键词、保留字、注解等数据指标，不包含完整 CLI 工作流区块。
- 每个首页及其交互反馈使用对应语言；除品牌名、技术名词与代码外，不混入其他语言的界面文案。
- 语言菜单包含 §3.1 定义的全部首页语言，并正确标识当前语言。
- 巴西葡萄牙语、日语和西班牙语首页的文档入口直接指向英文用户手册，链接文本不额外标注英文。
- 首页不存在跳出 `website/` 根目录的本地链接。
- 关闭 JavaScript 后，导航、全部代码示例、安装说明、文档、插件、开源与语言菜单仍然可读，主题跟随系统偏好。
- 键盘操作、交互反馈与跨设备内容一致性符合本规范。
- `website/docs/` 的页面均来自 `docs/manual/` 中对应 Markdown 文件，生成结果不存在未转换的本地 `.md` 链接。
- 英文与简体中文手册的对应页面可以相互切换，页面语言属性与当前内容一致。
- 手册章节导航、页内锚点及前后章节入口指向有效页面，不跨语言串联。
- 从首页和手册切换主题时使用同一份持久化状态。
