# Feng object-form `spec` 成员访问优化备忘

> 状态：暂停，仅作未来方向备忘。
>
> 正确性优先。当前不实施，不修改现有 witness、生成 C ABI、runtime ABI 或语言语义。

## 1. 背景

object-form `spec` 成员访问当前通过既有 `subject + witness` 机制完成。重复访问同一
`spec` 值的成员时，可能重复读取 subject/witness，并重复执行相同的字段 getter 或方法
分派。

此前曾考虑把字段 witness 改为 offset。该方案会扩大 witness ABI、默认 subject、父
`spec`、intersection、泛型 slot adapter、跨包发码和生命周期验证的影响面。现阶段不推进
该方向，也不改变现有 witness。

## 2. 候选方向

未来可优先评估局部、保守的重复表达式提升：

1. 在生成代码前识别同一作用域或基本块内、结构相同且重复出现的 `spec` 成员表达式；
2. 只有在能够证明 receiver 稳定、表达式无副作用、两次访问之间不存在可能改变结果的
   写入或调用时，才把第一次结果保存为局部绑定供后续访问复用；
3. 无法完成证明时保持现有发码，不做优化；
4. 继续通过现有 witness 执行第一次访问，不修改 witness 表示和成员分派规则。

例如，对重复的 `widget.rtStyle`，只有在编译器能证明 `widget` 未改绑、`rtStyle` 未被直接
或间接修改，并且提升不改变求值顺序、借用和所有权时，才可以复用局部结果。`var` 字段、
可能经 alias 修改的字段，以及跨越未知方法调用的访问，默认不得提升。

也可独立评估只缓存稳定 receiver 的 `subject` / `witness`；该优化不缓存成员值，正确性条件
相对简单，但实际收益需要通过生成代码与基准验证。

## 3. 评估结论

相较全局迁移字段 witness ABI，按安全证明提升重复表达式的方向影响面更小，也更直接针对
实际重复访问，因此更适合作为下一步候选。不过它不是无条件有效：保守的 alias 与副作用
判断可能使可优化场景较少，实施前仍需先设计通用的数据流与失效规则。
