# 内建 throw 约束与异常根的 Linux 性能对照

2026-10-21。测试已完成，复用 `feng-throwable-20261020`，未修改实现或正式测试用例。

实施方案见 [异常根开发方案](feng-throwable-annotation-dev.md)。

## 结论

在本次 Linux ARM64、Release/O2、ThinLTO、system 分配器的等价微基准中，异常根
存在可测量的完整抛出路径增量：具体类型约 **+2.42%～+5.21%**，函数泛型约
**+4.56%～+5.96%**，即每次完整 throw/catch 约增加 **49～126 ns**。
六个主场景配对增量的 95% bootstrap 区间均大于零。

这些百分比是当前构建配置下的总路径测量值，不是 witness 本身的固定成本。
关闭应用 LTO 并禁内联的诊断中，多数路径的正向差异消失或反向，只有 u64 函数
泛型仍显示明确的正增量（约 +88 ns、+4.22%）。因此必须把直接新增操作、寄存器/
栈/展开信息变化，以及编译布局对整个异常路径的影响区分开来。

没有发现新增独立根载体分配、额外装箱或动态契约查询；既有泛型描述符布局和
共享体通用协议没有变化。正常路径并非可以一概宣称零成本：新增用途使既有元数据
参数无法再被优化器删除，本次也测到部分正常调用有极小差异。

## 默认 Release 主结果

单位为 ns/次完整 throw → 具体类型 catch。两版各 20 个样本；增量和增幅取同轮
配对差的中位数，所以不等于两列独立中位数直接相减。

| 载荷/路径 | 旧版中位数 | 新版中位数 | 配对增量 | 配对增幅 | 增量 95% 区间 |
| --- | ---: | ---: | ---: | ---: | ---: |
| u64 / 具体 | 1805.586 | 1898.282 | +94.012 | +5.21% | [80.167, 118.965] |
| 引用对象 / 具体 | 2006.360 | 2044.595 | +49.073 | +2.42% | [16.520, 84.952] |
| 含托管字段的值 / 具体 | 1921.438 | 1983.083 | +60.728 | +3.16% | [29.014, 80.076] |
| u64 / 函数泛型 | 2125.374 | 2251.777 | +125.714 | +5.96% | [106.485, 150.959] |
| 引用对象 / 函数泛型 | 2221.692 | 2349.177 | +118.145 | +5.28% | [86.648, 155.473] |
| 含托管字段的值 / 函数泛型 | 2231.082 | 2324.612 | +100.792 | +4.56% | [74.280, 131.903] |
| u64 / 类型级泛参 | 2058.388 | 2146.169 | +81.274 | +3.96% | [68.147, 92.057] |
| u64 / 一层泛型转发 | 2334.353 | 2440.844 | +97.119 | +4.15% | [67.196, 144.197] |

不抛出时，六个主场景的配对差为 -0.0042～+0.0080 ns/迭代，多数区间包含零。
引用泛型的 +0.0069 ns（+0.69%）和补充转发场景的 +0.0215 ns（+1.35%）区间
大于零，幅度远小于真实抛出路径。它们来自极短循环，不宜外推成普遍固定开销。

每 1000 轮抛出一次时，六个主场景平均增加 **0.0585～0.1232 ns/迭代**
（+1.96%～+3.80%）。这里的单位是整个循环的平均耗时，不能读成单次 throw
耗时。低频和不抛出对照支持主要增量集中在真实抛出路径。

## 禁内联机制诊断

保持源码、分配器和配套 runtime 不变，应用使用 `--release --lto=off`、
`FENG_CC_FLAGS=-fno-inline`；runtime 仍使用与主测相同的各版本 ThinLTO 归档。
最终符号确认具体函数、泛型共享函数和转发函数均保留。只补测八条路径的密集抛出，
每版各 20 个样本，不与默认 Release 数据合并。

| 载荷/路径 | 配对增量 ns | 配对增幅 | 增量 95% 区间 |
| --- | ---: | ---: | ---: |
| u64 / 具体 | -26.164 | -1.21% | [-57.687, -9.732] |
| 引用对象 / 具体 | -7.021 | -0.33% | [-37.699, 8.311] |
| 含托管字段的值 / 具体 | -28.486 | -0.92% | [-67.754, 23.362] |
| u64 / 函数泛型 | +88.335 | +4.22% | [38.472, 104.867] |
| 引用对象 / 函数泛型 | -26.019 | -1.21% | [-42.448, -8.940] |
| 含托管字段的值 / 函数泛型 | +13.936 | +0.64% | [-1.663, 38.528] |
| u64 / 类型级泛参 | -25.350 | -0.97% | [-55.713, 7.045] |
| u64 / 一层泛型转发 | -39.997 | -1.10% | [-55.622, 30.805] |

这项对照证实总差值对优化配置敏感。它同时改变了应用 LTO 和内联，不能据此单独
判定是哪一项主导，也不能把主测差值全部归给 witness 的一条保存指令。
诊断中的负值同样保留，不据此推导异常根在一般场景中会加速。

## 实际新增操作与原因

| 位置 | 实际发码变化 | 核查结论 |
| --- | --- | --- |
| 具体 throw | 传递静态根 witness；从 subject 头部读取精确描述符 | 三种载荷的优化后 IR 均保留该描述符读取。根视图临时 pair 已被优化消去，不另分配对象。 |
| 泛型 throw | 从既有 callable 描述符读取转换槽及 witness；聚合分支比较实际描述符是否为根值 | 本轮实体实参仍走原有装箱/引用持有路径；聚合实参额外经过根值判别。 |
| 泛型调用点 | 保留既有 `_desc` 参数 | 旧版该参数无用途，被 LLVM 删除；新版 throw 需要读取它，机器码调用点多准备该参数。源级共享体协议没有新增参数。 |
| 异常记录 | `feng_throw` 接收并保存 witness | witness 静态存储，无 witness ARC。记录仍为 64 B；matched_clause 从 48 后移至 56，尾部 padding 减少。 |
| 寄存器和栈 | 主测共享函数栈帧 64→80 B，feng_throw 栈帧 32→48 B | 真实抛出分支保存额外寄存器；正常返回不建立共享函数的该帧。整体峰值不能直接相加，调用者帧也受优化影响。 |
| 展开信息 | feng_throw 增加 x21、共享函数增加 x23 的恢复规则 | 两个对应 DWARF FDE 各增加 4 B。展开路径须处理对应规则；本次没有逐项拆分其纳秒贡献。 |
| 静态产物 | 根 witness、适配代码、转换表项及被保留下来的 callable 描述符 | 泛参描述符和转换描述符均仍为 24 B；增加的是静态实例及生成代码，而非这些结构体的布局。 |

三种具体/泛型载荷的原有复制、持有、具体 catch 与释放继续存在。尤其具体托管值
的临时聚合持有、清理链和装箱复制在旧版已存在，不计为此次新增。
本轮具体 catch 未调用 feng_caught_witness，也没有根 catch 的额外 subject 持有。

因此有两层结论：**代码确实新增了准备、传参、存取与判别操作；这组默认优化产物
的完整路径也确实变慢。** 但新增操作引起的寄存器分配、栈帧、展开信息和代码布局
会共同影响测量，诊断结果不支持把 2%～6% 当成该语言方案恒定不变的运行成本。

详细证据见 [发码核查记录](../../temp/throwable-perf/codegen-findings.md)、各 builds 目录的 post-lto.ll、
final-annotated-assembly.txt、generic-throw.asm、runtime-throw.asm、eh-frame.txt。

## 静态大小

该八场景合并基准可执行文件从 **63,832 B → 66,080 B（+2,248 B）**。
`.text` +380 B，`.rodata` +80 B，`.data.rel.ro` +920 B；其余涉及重定位、展开表
和布局对齐。共享泛型函数机器码 268→328 B，feng_throw 172→184 B。
这是该测试产物的大小差，不是任意项目的固定增量，也不是每次抛出的堆分配增量。

## 方法与范围

- 旧版：`9c8b1b4448aef35c81a657a03160db130adb4ed8`；新版：
  `a06897d76fa9267665ea40c9dcd0f20aa7b174fe`。
- 同一现有 Linux ARM64 容器，Linux 6.18.15，固定 vCPU 0；容器 CPU 限额为 4。
- 两版应用后端均为 Ubuntu Clang 23.1.3；runtime 均按相同 O2 参数由各自配套
  bundled Clang 23.1.3 构建。bundled LLVM、EH 插件和 unwinder 的两版哈希相同。
- Release/O2、ThinLTO、system 分配器，无 sanitizer。每版使用自己的编译器、
  runtime、头文件，不混用私有 ABI。
- 单成员自定义异常根，不引入标准库或字符串格式化。两版业务代码完全一致，只有
  根声明、三条 fit 和三处约束不同，已自动验证并保留 benchmark-source.diff。
- 引用实例在计时前创建；值的原有装箱、异常记录分配、展开、catch、释放计入时间。
  不测根 catch、根 spec 实参、冷启动单次异常、标准库完整静态大小或编译耗时。
- CLOCK_MONOTONIC 进程内计时，输入、初始化、输出与独立 C oracle 在计时外。
  预热后为每个新旧场景校准相同循环次数，每轮交替新旧顺序，全部串行执行。
- 主测每样本 0.512～0.857 秒，诊断 0.641～0.804 秒；不剔除慢样本。
- 95% 区间使用固定种子、10,000 次配对 bootstrap，描述本次样本，不能覆盖所有
  机器、优化配置和系统性布局影响。Q1/Q3、每轮差值及原始计时全部保留。
