## 2. 已确认的优化前基线

本节记录实施前行为，优化后的通道与实测结果见第 6 节。

### 2.1 最小示例

```feng
func identity<U>(value: U): U {
    return value;
}

func relay<T>(values: T[]): T[] {
    return identity<T[]>(values);
}
```

`relay` 接收 T 的泛参描述符；调用 `identity<T[]>` 时，内层 U 的实际类型是 T[]，因此需要
描述 T[] 的泛参描述符，而不是直接复用描述 T 的记录。

优化前 [Codegen](../../src/codegen/codegen.c) 的 `cg_closed_array_descriptor_expr` 分成两条路径：

- 当前发码点的数组类型已经完整闭合，例如 `i32[]`：生成并复用静态 `FengTypeDescriptor`。
- 当前发码点仍含开放泛参，例如共享体中的 `T[]`：用传入的 `_T` 生成函数内的
  `&(const FengTypeDescriptor){...}`，其中元素泛参数组也在局部组装。
  `cg_generic_descriptor_expr` 再为这个数组类型生成相应的临时 `FengGenericParamDescriptor`。

第二条路径确实存在运行时临时描述符初始化，不是纯粹传递静态地址；这里不是创建或复制数组，
也不是运行时检查约束是否满足。宿主编译器可能优化个别调用，但不能把依赖内联或消除临时对象
作为共享体及跨包调用的实现保证。

### 2.2 描述信息不依赖实例

这组记录只依赖具化后的元素类型及数组类型属性，不依赖 `values` 的实例指针、数组长度或
元素内容。T 的描述符通过运行时参数传进共享体，并不意味着 T[] 的描述信息只能在运行时生成。

例如 `relay<i32>` 与 `relay<string>` 可分别在具化点生成 `i32[]` 与 `string[]` 的静态
描述符，再让同一个共享体通过各自的具化上下文取得正确记录。不应在共享体内缓存第一次传入的
T，也不能把含 `_T` 的局部初始化表达式机械改成一个共用的 `static` 变量。

### 2.3 为什么优化前会临时构造

优化前 [依赖收集](../../src/semantic/reifiable_deps.c) 的 `try_collect_type_ref` 会把
`List<T>` 这类具名泛型实例作为完整类型依赖收集；对数组节点则只递归检查元素类型，
未把本场景所需的数组节点本身作为完整类型描述符依赖接入静态读取链路。
Codegen 在这里取得的是 T 的描述符，没有直接取得具化后的 T[] 描述符，因而采用局部组装。

完整静态化还需要解决外层泛参描述符的读取与转传。实施前实测确认：普通泛型容器作为整个
泛型实参时也存在这层局部构造，不能把“具名容器已收集类型依赖”视为“整个泛型实参已能
静态转传”；复现及现有字段的具体承载范围见 [5.1](#51-普通容器也存在外层泛参描述符临时构造)。
这是编译期依赖与描述符传递路径的缺口，不是数组描述符必须依赖实例的语言要求。
历史字段增大造成的初始化与栈布局实测结果保留在 ISSUE-G24-015；那些数字不是本专项优化后
或补齐 `_count` 后的测量结果。

## 3. 优化目标与方案方向

### 3.1 目标：与普通泛型容器一致

2026-09-09 人工明确：T[] 是语言内建泛型容器类型，应与 `List<T>` 等普通泛型容器一样，
将只依赖具化类型的描述信息在具化点静态生成。共享体内仍写作开放 T[]，不构成运行时动态
构造描述符的理由。数组与普通容器的实例布局可以不同，但依赖收集、具化、静态描述符生成、
槽位读取和泛参描述符传递必须复用同一套通用机制。

`List<T>` 仅作为普通泛型容器对照，编译器不能感知 std 或按 `List` 名称增加处理分支。
共享体方法中使用的 T[]，以及泛型类型中类型为 T[] 的成员绑定及其初始化，必须分别按相同
位置的 `List<T>` 依赖处理；不得因数组是内建类型而改走专用的运行时描述符构造或转发路径。

将本场景需要的数组类型描述符、元素泛参数组及相应泛参描述符在具化点静态生成，消除共享调用
中的这一组临时描述符构造。完整闭合数组现有静态路径保持有效，实际类型与生命周期语义不变。

### 3.2 复用既有具化依赖机制

必须沿用 [泛型具化设计](./feng-generic-optimize-dev.md) 的既有机制：

1. Semantic 像记录 `List<T>` 等具名泛型容器一样，记录共享体实际需要的完整开放数组类型依赖，
   保留嵌套层次、元素可写性及泛参归属；数组只增加自身结构身份，不增加专用依赖类别。
2. 使用现有依赖归属和稳定槽位规则；类型初始化域与 callable 域分别处理，不因引用了类型级 T
   就把方法自身的依赖并入类型初始化域。
3. `.ft` 保存恢复这些依赖所需的信息，使 consumer 在没有 provider 源码时仍能完成具化；
   格式契约仅在 [符号表规范](../specifications/feng-symbol-table.md) 中定义。
4. 在最终具化点按普通泛型容器的规则生成 T[] 的静态 `FengTypeDescriptor`、元素泛参记录和表示
   整个 T[] 的静态 `FengGenericParamDescriptor`。相同闭合记录可以复用，但不得破坏开放槽位对应。
5. 各层共享体方法和泛型成员绑定初始化使用同一通用泛参转传协议。派生实参记录通过隐藏入参
   传递，声明泛参仍沿用其现有入参；闭包沿既有捕获机制保存静态记录指针。

`List<T>`／自定义 `Container<T>` 的真实发码已完成前置核验；数组与普通容器共同补齐派生泛参
静态转传，不再假定普通容器的外层记录已完成优化。不得新增数组专用 runtime 字段、
依赖类别或 `.ft` 节，也不得借用无关投影表的槽位。

### 3.3 成本和不变边界

- 禁止变更任何现有描述符结构，包括但不限于 `FengTypeDescriptor`、
  `FengAggregateDescriptor`、`FengFunctionDescriptor` 和 `FengGenericParamDescriptor`；不得新增、
  删除、改型或重排字段。本次生成新的静态描述符实例，并允许以通用隐藏入参传递派生泛参记录；
  编译器生成的静态隐藏实参包不加入 runtime，不扩展或强转任何既有描述符的布局。
- 既有测试仅允许迁移 [test_codegen.c](../../test/codegen/test_codegen.c) 中的
  `test_open_generic_param_descriptor_remains_runtime_scoped`：其局部描述符存在断言与优化目标
  直接冲突，改为验证开放 provider 不引用局部泛参生成文件级静态记录、闭合 consumer 生成静态
  描述符、共享体读取并转传静态地址。禁止修改其他既有测试的源码、断言或预期结果；其余覆盖
  新增独立测试。不得删除、弱化或绕过检查，也不得生成无效或不可达代码来迎合文本断言。
- 共享体方法及泛型成员绑定中的 T[]，必须与相同位置的 `List<T>` 使用同一依赖归属、具化、
  静态生成、槽位读取和泛参描述符入参转传规则；禁止按数组名称、内建身份或固定层数增加特判。
- 不增加运行时描述符工厂、堆分配、首次调用缓存、动态类型搜索或约束满足检查。
- 不通过读取数组实例的运行时对象信息替代编译期类型依赖，不增加实例相关分支。
- 不新增方法转接层，不改变数组默认零值、元素布局、复制及 ARC 协议。
- 不为某种 T、某个包、std 或固定数组层数增加非通用特判。
- 静态记录和依赖表可能增加制品体积；固定槽位读取也须与现有临时初始化作完整比较，
  不能将“无运行时构造”直接表述为“没有任何运行时读取或总耗时必然下降”。
- 没有派生泛参依赖（包括下游和类型初始化域）的共享体和普通闭合实参保持原路径；三张现有
  `reified_*` 依赖表保持其既有含义，数组按 managed 类型依赖接入。
  若方案依赖变更描述符结构或上述唯一例外之外的既有测试，直接判定为不符合本专项边界；
  其他额外执行成本或范围扩大须先记录原因并交人工决策。

### 5.1 普通容器也存在外层泛参描述符临时构造

2026-09-09 实施前核验，使用以下对照探针，并分别增加调用 `relayArray<i32>` 与
`relayContainer<i32>` 的闭合入口：

```feng
open module feng.probe.generic_array_descriptor;
func identity<U>(value: U): U { return value; }
open type Container<T> { var value: T; }
open func relayArray<T>(values: T[]): T[] {
    return identity<T[]>(values);
}
open func relayContainer<T>(value: Container<T>): Container<T> {
    return identity<Container<T>>(value);
}
```

首次探针使用工程 `build/generic-array-descriptor-baseline.ff`。以下命令均退出 0，当时生成 C
与汇编位于同目录；该目录随后由全量回归清理，最终保存的可复核基线见 6.2。
首次核验本身不作为正式测试用例或优化完成的验收结果：

```sh
build/bin/feng tool compile --target=lib --emit-c=build/generic-array-descriptor-baseline.c build/generic-array-descriptor-baseline.ff
clang -std=gnu11 -O2 -fno-inline -fexceptions -Werror -Isrc/runtime -S build/generic-array-descriptor-baseline.c -o build/generic-array-descriptor-baseline.s
```

实际结果：`relayArray` 向 `identity` 传入局部数组类型描述符、局部元素泛参数组和局部外层
泛参记录；`relayContainer` 同样传入 `&(const FengGenericParamDescriptor){...}`，其
`.descriptor` 引用开放 `Container<T>` 的 `__T__CTX__T` 描述符符号，未在此调用位置读取
已有的闭合类型依赖槽。两者在禁用内联的汇编中均保留外层记录的栈写入；不能据此宣称普通
容器的整个泛型实参已有静态转传实现，也未据此断言新的语言行为错误。

预期结果仍为 [3.1](#31-目标与普通泛型容器一致) 的整组静态化。代码依据是
[Codegen](../../src/codegen/codegen.c) 的 `cg_generic_descriptor_expr`：开放托管实际类型
进入局部泛参复合字面量分支，具名类型通过 `cg_managed_pointer_descriptor_expr` 取得符号；
`cg_emit_generic_function` 仅为声明中的泛参生成独立描述符入参。

现有字段的承载范围也已核实：`reified_type_deps[i]` 指向 `FengTypeDescriptor`；
`T[]` 或 `Container<T>` 的 `reified_generic_params[0]` 描述 T，不描述整个 `T[]` 或
`Container<T>`。独立泛型函数当前收到的 `_T` 也仅描述 T。无约束的 `identity<U>` 在探针中
只生成空依赖的 `FengFunctionDescriptor`，没有可读取的 U 泛参表。约束投影表的既有目标必须是
spec，见 [符号表规范 6.3.8](../specifications/feng-symbol-table.md#638-constraint_projections-开放泛参约束投影依赖)，
不能将无约束的派生类型记录塞入该表绕过本专项边界。

因此，仅补齐数组的类型依赖槽不能完成外层泛参记录的静态转传。唯一旧用例的迁移权限已经
解决测试边界冲突，但当时尚未补齐这条通用通道。该前置核验不代表本专项的最终实现状态。

### 5.2 通用隐藏实参协议的实施范围

2026-09-10 已批准一起优化。为共享体实际使用的派生泛型实参增加通用描述符入参，适用于数组和普通容器，
继续使用现有 `FengGenericParamDescriptor`。例如 `relayArray<T>` 额外接收静态实参包
`_generic_args`，将其中描述整个 T[] 的 `params[0]` 传给 `identity` 的现有 `_U`。
数组类型描述符和元素记录继续沿现有具化机制静态生成；不修改任何现有描述符结构。

这会改变共享体隐藏入参协议，且须统一处理跨包恢复、多层转传、成员初始化和闭包捕获。
新增传参及捕获的成本必须与消除临时构造的收益一并验证。隐藏实参可按当前依赖域组成一个
编译期静态实参包，统一传递直接使用的派生泛参记录及下游调用所需的实参包指针；共享体只读取
固定槽位，不动态创建、搜索或缓存。静态图按完整开放身份分配槽位、按闭合身份生成记录，
先声明节点再连接依赖，以支持循环调用；闭包只捕获该静态包的指针。

派生实参的源类型与目标约束来自已解析调用及其 `.ft` callable 依赖中的类型实参和签名。
类型初始化域与方法域独立，不因共用类型级泛参而混合槽位。精确相同的闭合记录可以复用，
开放槽位不可因某次具化结果相同而合并。本节记录已批准的协议，最终验证结果见第 6 节。

### 5.3 迭代协议的合成共享调用

收尾核验使用 `local/generic-arguments-iterator.ff`：泛型 `Sequence<T>.iter()` 转传
`identity<Cursor<T>>`，泛型 `Cursor<T>.next()` 转传 `identity<T[]>`，泛型函数通过
`for/in` 调用两者。生成 C 的两个共享入口已有隐藏实参包，但循环降级生成的调用仍只有原有
四个参数，clang 明确报告 `expected 5, have 4`。这是本次隐藏 ABI 接入中的遗漏，不是既有
`identity<Container<T>>` 的语言正确性问题。

处理沿用合成调用已有的 callable 依赖槽，同时转传该槽对应的静态实参包；普通方法和 fit 方法、
固定返回槽和描述符大小返回槽使用相同规则，不增加迭代器专用描述符。新增跨包行为用例及
两个 `.ft` profile 的 C 编译覆盖后，再重新执行完整回归。

同一探针再增加 `direct<T>(values: Sequence<T>): Cursor<T> { return values.iter(); }`，
确认通过另一开放实例调用非泛型成员的独立发码分支也遗漏了隐藏实参。该入口同样读取已有
callable 槽对应的静态包，与 self 调用和方法泛型调用保持一致；新增直接调用覆盖。

## 6. 实现与验证记录

### 6.1 统一静态通道

`src/semantic/reifiable_deps.c` 将完整开放数组加入现有 managed 类型依赖，同时递归收集元素
树；数组层次和各层可写性参与已有排序身份。普通具名容器保留原有类型依赖规则。

`src/codegen/detail/generic_arguments.c` 实现编译器内部的开放实参槽与闭合静态图：从现有 callable
依赖中的实际类型及被调声明的约束恢复槽位，不增加 `.ft` 节。需要该上下文的共享 C 入口在
最后追加 `const FengGenericArguments *_generic_args`，声明泛参的原有描述符入参不变。

这个新增的编译器私有 C 实参包独立于所有 runtime 描述符：`params` 指向完整静态泛参记录，
三个子表与现有 callable／managed／aggregate 依赖槽一一对应，`owner` 连接方法或 fit 的类型
初始化域。无所需子上下文时省略整张子表，不压缩有用表中的槽号；静态节点先登记再连接，支持
有限的循环调用图。已有约束投影能直接提供完整静态记录时保留其原有路径，不重复添加隐藏实参。

`src/codegen/codegen.c` 接通顶层函数、共享成员／fit、闭合薄包装层、隐式及显式构造、静态成员
初始化、析构、默认零值入口、`for/in` 合成调用、函数值／方法值适配和 lambda 捕获。
普通闭合包装层在内部绑定静态包；
需要逃逸的泛型 lambda 只额外捕获静态包指针。数组描述符函数不再保留局部复合字面量回退。

全部现有 runtime 描述符结构、数组实例布局和复制／ARC 协议保持不变。隐藏共享 C ABI 已变化，
provider 与 consumer 必须用本次编译器一起重建；本专项不提供新旧隐藏 ABI 混用的兼容层。
