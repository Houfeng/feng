## 1 文档定位

本文是总计划 D1A 的唯一实施清单，负责记录表达式求值顺序 FCTS 的现状证据、用例边界、实施 Todo、

## 2 目标与规范依据

### 2.1 目标

为以下已经生效的规则增加带副作用、可直接观察的 FCTS 证据：

- 二元运算先左后右；
- 函数的多个实参从左到右求值；
- `&&`、`||` 按规则短路；
- `if` 表达式只求值被选中的分支；
- 成员、下标和调用组成的后缀链从左到右展开。

每个用例同时断言表达式结果、副作用顺序和副作用次数，避免仅凭最终值间接推断求值顺序。

### 2.2 权威规范

- [表达式与运算规范 §4](../specifications/feng-expression.md)：二元运算、调用与后缀链求值顺序，
  以及逻辑短路和 `if` 分支选择；
- [流程控制规范 §4](../specifications/feng-flow.md)：`if` 表达式的分支结果规则；
- [函数规范](../specifications/feng-function.md)：普通函数调用与参数规则。

若实施结果与上述规范不一致，应记录最小复现并停止实施，不得在本文中解释或改写规范。

### 2.3 非目标

本交付不覆盖：

- 函数返回类型推导；该能力属于后续 D1B；
- 赋值左侧定位和复合赋值左侧只求值一次；总计划未将其纳入 D1A；
- 运算符优先级、结合性、类型适配或负向诊断；已有 Parser、Semantic 与 FCTS 负责；
- callable 结果立即调用的合法形状、callee 固定和生命周期；已有专项直接覆盖；
- 泛型、跨包、descriptor-sized 值、异常或生命周期的组合排列；
- Parser AST、Semantic 事实或生成 C 结构测试；本组行为可全部由 FCTS 直接观察；
- 任何产品实现、runtime 私有 ABI、公开 ABI、`.ft` 或标准库 API 变更。

## 3 现有覆盖与直接缺口

| 规范规则 | 现有直接证据 | 当前不足 | D1A 处理 |
| --- | --- | --- | --- |
| 二元运算先左后右 | `test_expression.ff` 的 `left-to-right evaluation order` | 只读取预先写好的数组元素；即使交换求值顺序，结果仍相同 | 新增 EVAL01 |
| callee 只求值一次且先于参数固定 | `test_callable_result_immediate_invocation.ff` 的 `callee is fixed once before arguments` 与数组元素替换用例 | 已有副作用、次数和固定目标的直接证据 | 复用，不新增等价 case |
| 多个实参从左到右 | 当前 FCTS 未发现以不同副作用标记多个实参的直接证据 | 参数顺序不可由纯值调用证明 | 新增 EVAL02 |
| `&&`、`||` 短路 | `test_expression.ff` 使用无副作用的 `returns_true()` / `returns_false()` | 即使 RHS 被错误调用，当前结果断言仍可能通过 | 新增 EVAL03、EVAL04 |
| `if` 只求值选中分支 | `test_flow.ff` 断言 `if` 表达式结果 | 未观察未选分支是否执行 | 新增 EVAL05 |
| 后缀链从左到右 | callable 立即调用专项覆盖 computed callee、索引 callee 和参数前固定 | 尚无一个用例同时记录 base、index、argument 和 invoke 的完整顺序 | 新增 EVAL06 |

以上缺口以“独立可观察语义”为单位，不按运算符种类、参数数量、返回类型或后缀链深度做笛卡尔积。

## 4 测试模型

### 4.1 文件与入口

- 新增 `fcts/fcts_bin/src/test_evaluation_order.ff`；
- 新增公开入口 `test_evaluation_order()`；
- 经人工 Review 批准后，仅在 `fcts/fcts_bin/src/main.ff` 增加一次入口调用；
- 不修改 `test_expression.ff`、`test_flow.ff`、`test_callable_result_immediate_invocation.ff` 或其他既有
  测试的内容与断言；
- 本组不需要修改 `fcts_lib` 或 `test/`。

### 4.2 副作用探针

新增文件内部定义一个职责单一的引用类型探针，至少保存：

- `trace: int`：每次观察执行 `trace = trace * 10 + marker`；
- `calls: int`：记录实际发生的观察次数。

探针提供分别返回 `int`、`bool` 和后缀链夹具的最小方法。marker 只使用单个十进制数字，使
`12`、`123`、`1234` 能直接表达执行顺序。每个 `test(...)` 创建独立探针，不使用模块级可变绑定，
避免把模块初始化或跨用例状态带入本专项。

所有新增类型和函数按工程规则编写注释。夹具只服务于顺序观察，不引入泛型、继承、spec 适配或
其他与目标无关的路径。

### 4.3 断言原则

每个 case 必须同时检查：

1. 主表达式结果正确；
2. `trace` 精确等于预期顺序；
3. `calls` 精确等于预期次数。

不得只断言 `trace` 最终包含某个 marker，也不得使用不会因错误求值而改变结果的纯函数代替副作用探针。

## 5 用例设计

### EVAL01：二元操作数从左到右

使用非交换二元运算连接两个 `markInt` 调用：

- 左操作数追加 marker `1` 并返回左值；
- 右操作数追加 marker `2` 并返回右值；
- 断言运算结果、`trace == 12`、`calls == 2`。

只选择一个能代表通用二元发射路径的普通算术运算，不为 `+ - * / %`、比较和位运算分别复制用例。
逻辑运算的非等价短路路径由 EVAL03、EVAL04 独立覆盖。

### EVAL02：多个实参从左到右

调用一个接收三个 `int` 参数的纯 helper，每个实参分别通过同一探针追加 marker `1`、`2`、`3`：

- helper 的返回值保留参数位置差异，证明实参与形参映射正确；
- 断言返回值、`trace == 123`、`calls == 3`；
- 不再新增 computed callee 的单次求值 case，callee-before-arguments 直接复用现有专项证据。

三个实参足以证明多个相邻参数的顺序，不继续扩展零参数、一个参数、变参或泛型参数排列。

### EVAL03：短路时抑制 RHS

在同一独立 case 中执行：

- `false && rhs`；
- `true || rhs`。

两个 RHS 都使用会修改探针的 `markBool`。断言两个逻辑结果正确，并且 `trace == 0`、`calls == 0`。

### EVAL04：不短路时执行 RHS 一次

在同一独立 case 中执行：

- `true && rhs`，RHS 追加 marker `1`；
- `false || rhs`，RHS 追加 marker `2`。

断言两个逻辑结果正确，并且 `trace == 12`、`calls == 2`，证明 RHS 没有遗漏或重复求值。

### EVAL05：`if` 只执行选中分支

在同一独立 case 中分别执行 true 和 false 条件：

- true 条件的选中分支追加 marker `1`，未选分支使用显著不同的 marker；
- false 条件的选中分支追加 marker `2`，未选分支使用显著不同的 marker；
- 两侧分支返回相同静态类型但不同值；
- 断言两个结果、`trace == 12`、`calls == 2`。

该用例只验证分支求值，不重复验证 `else if`、聚合结果、`throw` 分支或分支类型推导。

### EVAL06：成员、下标与调用后缀链

构造一个最小 holder，其中一个字段保存 callable 数组；通过一条连续后缀链完成访问和调用：

1. base 产生 holder 并追加 marker `1`；
2. index 表达式追加 marker `2`；
3. 外层 argument 表达式追加 marker `3`；
4. 最终 callable body 追加 marker `4` 并返回可断言结果。

断言结果、`trace == 1234`、`calls == 4`。该 case 证明完整链条的运行顺序，但不重复现有“参数替换数组
元素后仍调用已固定 callee”的强断言。
