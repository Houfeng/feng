剥离掉那些晦涩的学术名词，内核就只有这一个判断标准：**是否存在一个合法的语法调用空间，却被物理锁死成了“任凭调用侧怎么写，也无论如何都无法访问到”的绝对死角（Dead Zone）。**

如果用户能通过**显式类型转换（Cast）**或者**显式声明**把流量导过去，那这个重载就是具有“可消歧性”的，编译器应该放行；但如果两个函数的定义，直接在语法层面上制造出了一个吞噬掉某段控制流的黑洞，那这就属于**恶性冲突**，必须在编译期直接枪毙。

---

## 一、 允许的情况：存在消歧路径（无调用死角）

当参数出现“部分重叠”时，只要调用侧有办法自证清白，编译器就给通过。

### 场景：具体类型 vs 接口/Trait

```feng
fn inspect(x: int) { ... }       // 重载 A (具体类型)
fn inspect(x: AnyTrait) { ... }  // 重载 B (接口)

```

* **交集点**：如果传入一个 `int`，两个都满足。
* **是否存在死角**：**不存在。**
* 用户想调用 A：直接传 `inspect(42)`，因为具体类型比接口更特化（标量优先），去 A。
* 用户想调用 B：只需要在调用侧显式把类型向上转型（Upcast）为接口：`inspect(42 as AnyTrait)`。


* **编译期判定**：**合法。** 因为调用侧拥有绝对的自主控制权，没有任何一方被永久锁死。

---

## 二、 拒绝的情况：绝对调用死角（Dead Zone）

引入了变长参数（`...`）之后，如果不加上那两套“拉平对齐规则”，就会制造出真正的、无法通过任何显式声明自救的**纯物理死角**。

### 致命死角案例 1：无法自救的空调用

```feng
fn test(x: int...)    // 重载 A
fn test(y: string...) // 重载 B

```

* **调用死角**：用户发起空调用 `test()`。
* **为什么是死角**：在调用侧，因为根本没有传任何参数，用户**在语法上没有任何地方可以写 `as int` 或 `as string**` 来向编译器暗示意图。这段调用空间在物理上被彻底锁死了。
* **编译期判定**：**冲突！直接枪毙。**

### 致命死角案例 2：无法自救的单参数变参碰撞

```feng
fn test(x: string)    // 重载 A
fn test(x: string...) // 重载 B

```

* **调用死角**：重载 A 里的 `test(x: string)`。
* **为什么是死角**：当用户调用 `test("hello")` 时，如果编译器默认让它去了精确匹配的重载 A。那么**重载 B 接收 1 个参数的那个物理状态，就被重载 A 彻底蒸发掉了**。用户在调用侧无论怎么写（哪怕写成 `test("hello" as string)`），流量也永远只会去 A。
* **编译期判定**：“根据规则（用变参类型填充到相同个数后参与判定）”，重载 B 填充后变成 `[string]`，与 A 的 `[string]` 撞车，**冲突！直接枪毙。**

---

## 🎯 总结

把重载设计的视角从“编译器怎么做比较省力”提升到了“调用侧有没有绝对自由”。基于这个思想，`feng` 的静态重载检查代码在逻辑上迎来了最终的纯净闭环：

1. **类型树上具有上下级关系的拓扑（如 `int` 和 `Trait`）**：允许并存。调用侧可以通过 `as` 显式声明来消歧。
2. **结构和数量对齐后完全同构的水平拓扑（截断与填充规则）**：由于调用侧在语法上失去了“通过声明来消歧”的媒介（即没有参数位置可写，或写了类型也无法分流），直接判定为调用死角，定义期直接报错。
