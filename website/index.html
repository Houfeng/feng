为什么开发者会喜欢 Feng

如果你希望语言既有紧凑语法，也能把类型、抽象、异常处理和 C 互操作讲清楚，Feng 试图提供一条更直接的路径。

写代码时
类型在编译期确定，重构和排错更直接，不必一路追到运行时。
做抽象时
用 `spec` 和 `fit` 把契约写清楚，协作和长期演进都更稳。
接入现有库时
可以通过 `extern fn` 和 `@fixed` 调用 C 侧能力，而不用放弃语言本身的清晰性。

Language features

从日常业务代码到可复用库，Feng 把常用能力放进了一套统一语法里。

强类型 / 静态类型

很多错误能在编译期就暴露出来，写代码和重构时更有把握。

type 统一类型系统

对象类型和 ABI 固定布局类型都能放在同一套语言里表达，概念切换更少。

spec / fit 显式契约

接口契约和适配关系都写在源码里，代码意图更容易读懂，也更适合团队协作。

函数、Lambda 与闭包

既能写直接的业务逻辑，也能把行为提炼成可复用的函数、Lambda 和闭包。

结构化异常与自动内存管理

异常处理路径明确，普通对象由运行时自动管理，日常开发更容易保持代码整洁。

C 互操作与包分发

需要接入 C 库或分发二进制包时，语言本身就提供了一条清楚的路径。

Workflow

从新建项目到看到运行结果，只需要一条很短的路径。

01

初始化项目

先用 `feng init` 建好项目骨架，拿到清单和入口模板，马上就能开始写代码。

feng init demo
02

边写边检查

写完先跑 `feng check`，尽早发现问题，比等到最后构建失败更省时间。

feng check
03

构建目标

`feng build` 会按项目清单生成目标产物，日常构建路径保持简单直接。

feng build
04

运行或打包

写应用就 `feng run` 直接看结果；写库时再用 `feng pack` 产出 `.fb` 包。

feng run
# lib 项目
feng pack

What to learn next

如果你准备继续学 Feng，下面这些主题就是最主要的学习路径。

从语法到项目组织，按这几块理解最快。

模块与导入 `mod` 和 `use` 用来组织代码、拆分模块，并把依赖关系写清楚。
类型与绑定 `type`、`let`、`var`、构造函数和成员方法决定了你怎么组织数据和行为。
函数与抽象 `fn`、重载、Lambda 和闭包让你能从简单调用自然过渡到可复用抽象。
流程控制 `if`、条件表达式、`while`、`for`、`break` 和 `continue` 覆盖日常控制流需求。
异常与生命周期 结构化异常和自动内存管理决定了程序出错时怎么处理、对象何时被回收。
互操作与分发 当你需要接系统能力、复用现有库或发布二进制包时，这部分会特别重要。
