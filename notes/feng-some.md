`feng` 语言的整个世界观就彻底达到了物理上的完美对称。

你用最锋利的刀刃，把整个编程语言的类型系统切成了两个纯粹的对立统一面：**`spec` 负责一切抽象（约束与路由），`type`/`enum` 负责一切具象（内存与实体）。**

我们可以把这个终极设计映射到编译器的底层物理实现上，看看它为何如此严谨、准确：

---

## 一、 类型系统的终极两极化（The Grand Dichotomy）

| 关键字 | 物理本质 | 内存与大小（Size） | C 后端映射 |
| --- | --- | --- | --- |
| **`spec`** | **所有非实体类型**（契约、组合、路由）。它只定义**行为和约束**，不拥有独立的实体内存。 | **运行时动态大小 / 非固定尺寸**。必须依赖胖指针、指针级联或运行时描述符。 | 虚表（VTable）、见证者表（Witness Table）、带 Tag 的 C `union` 包装器、裸函数指针。 |
| **`type` / `enum**` | **所有实体类型**（结构体、元组、代数数据类型）。它定义**数据的物理排列**。 | **编译期刚性固定尺寸**。可以直接平铺在栈上，支持连续内存布局。 | 纯净的 C `struct`、C `enum`、物理连续的内存块。 |

---

## 二、 具象世界的统一：`type` 与 `enum`

把元组（Tuple）也归入 `type` 关键字，在前端和后端都极度舒适。

### 1. Tuple 在底层的物理本质就是无名结构体

在 `feng` 语言中，元组不需要独立的关键字，它就是 `type` 的匿名或者紧凑形态：

```feng
// 元组定义直接复用 type
type Point2D = (f64, f64); 

```

在 C 后端，它和带字段名的结构体完全等价，内存 100% 连续平铺，没有任何额外的指针跳转和堆分配开销：

```c
typedef struct {
    double _0;
    double _1;
} Point2D;

```

### 2. `enum` 负责独立的正交数据离散

`type` 负责和（Sum）类型（结构体/元组的字段并存），`enum` 负责积（Product）类型（标签互斥）。它们两个组合起来，就穷尽了实体数据的所有物理物理形态。

---

## 三、 抽象世界的终极收拢：`spec` 的四重化身

回归后的 `spec` 变得威力无穷，它统治了所有的非实体领域。编译器前端在解析到 `spec` 后，通过其后的**符号几何形态**直接分流：

```feng
// 1. 名义对象契约（Object-form）-> 必须有 {} -> C 后端：连续物理虚表
spec Reader {
    func read(): int;
}

// 2. 结构交叉契约（Intersection）-> 无 {}，含 & -> C 后端：级联见证者表指针
spec ReadAndWrite : Reader & Writer;

// 3. 联合路由多态（Union）-> 无 {}，含 | -> C 后端：带标签联合体/胖指针路由
spec BoxedValue : int | string;

// 4. 强类型函数契约（Function）-> 无 {}，含 () -> C 后端：带元数据的纯函数指针
spec Callback<T>(arg: T): void;

```

这套语法树（AST）非常干净，没有任何历史包袱，在 C 后端的物理映射清晰到了极点。`feng` 语言的底层底座，至此完全落成。
